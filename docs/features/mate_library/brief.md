# Mate → отдельная библиотека — бриф

Статус: исследование (2026-08-31). Issue не заведён.

## Цель

Выделить `modules/core/mate` (кастомный TEA-раннер: MateReducer /
Mate / effect handler'ы / ReducerChain / ReducerLogging / test-хелперы)
в ОТДЕЛЬНУЮ библиотеку — переиспользуемую вне PolyTrainer.

**Планка (требование пользователя):** библиотека обязана КОНЦЕПТУАЛЬНО
следовать идее The Elm Architecture — не «TEA-подобный раннер с
оговорками», а профессиональная концептуальная библиотека, которой
можно гордиться. Отклонения от TEA легальны только как осознанные,
задокументированные решения — не как случайные компромиссы.

## Мотивация

- Mate — самодостаточная архитектурная основа всех экранов проекта;
  конвенция (атомарные state-экстеншны, плоские Msg, мапперы границы)
  выработана и стабильна.
- Другие проекты могли бы стартовать на готовом раннере вместо
  копипасты.
- Выделение заставит зафиксировать контракт и вычистить прилипшие к
  проекту детали (logger, LogTags).

## Подзадачи

1. **Изучить принципы TEA (The Elm Architecture)** — именно принципы,
   не синтаксис Elm: Model/Update/View, managed effects (Cmd),
   subscriptions, однонаправленный цикл, чистота update. Итог —
   [elm_architecture.md](elm_architecture.md): эталон, с которым
   сверяем mate.
2. **Оценить соответствие mate этим принципам** — по фактическому коду
   модуля. Зафиксировать: что совпадает, где осознанные отклонения,
   где случайные. Предложить правки — концептуальные и мелкие. Итог —
   [mate_analysis.md](mate_analysis.md).

## Организация (решения юзера, 2026-08-31)

- **Репозиторий:** отдельный `KilgoreT/mate` (go-platform остаётся
  Go-миру).
- **Имя/пакет:** `mate`, `io.github.kilgoret.mate` (Central-валидный);
  артефакты `mate-core` / `mate-navigation` / `mate-test` /
  `mate-app-test`.
- **Публикация:** JitPack на время обкатки → Maven Central после.
- **Лицензия:** Apache 2.0.

## Вне скоупа (пока)

- Миграция words-экрана на конвенцию.
- Любые правки кода mate до старта реализации v0.
