# IS536 | Решения

История фичи. Номера сквозные, не меняются; на них ссылаются план и
ручники.

- **Д1 (юзер, 2026-10-15). Род нужен в свой компонент.** Для испанских
  существительных род из словаря должен попадать в компонент «Выбор»,
  который юзер завёл руками. Сервер род сейчас не отдаёт, хотя в базе
  слов он есть.
- **Д2 (юзер, 2026-10-15). Без привязки и каталога на сервере.**
  Предложение «каталог параметров у бэкенда, привязка компонента к
  параметру, список параметров в запросе» отвергнуто как усложнение.
- **Д3 (юзер, 2026-10-15). Стандартная грамматика в ответе.** Бэкенд
  отдаёт у лексемы-кандидата набор ключ → значение из того, что
  конвертер достаёт из выгрузок. Заменено Д8: грамматика приходит уже
  разложенной по компонентам.
- **Д4 (юзер, 2026-10-15). Встроенного компонента «Род» не будет.**
  Предложение по образцу «Части речи» с опциями-ключами отвергнуто.
- **Д5 (юзер, 2026-10-15). Соответствие по одному значению, когда
  встретилось.** Заменено Д8: соответствие делает нейронка.
- **Д6 (юзер, 2026-10-15). Цель — значение компонента.** Юзер видит
  компонент и его опции и выбирает опцию. Заменено Д8: выбирает
  нейронка, юзер видит результат и правит.
- **Д7 (юзер, 2026-10-15). Без блокировки.** Значение без соответствия
  не мешает добавлению. Заменено Д8.
- **Д8 (юзер, 2026-10-15). Нейронка на сервере с компонентами юзера в
  запросе.** Приложение шлёт дерево компонентов словаря; нейронка
  раскладывает значения записи по компонентам и отдаёт JSON «значение →
  компонент.опция» или «значение → компонент.поле». Род — частный
  случай. Таблицы соответствий, чип «род?» и лист не нужны.
- **Д9 (юзер, 2026-10-15). Первые значения — не самые частые.** Порядок
  значений в Викисловаре не по частоте, частотности в данных нет.
  Выбор и ранжирование — нейронкой. Все шестьдесят значений юзеру не
  отдаются. Уточнено Д12.
- **Д10 (юзер, 2026-10-15). Нейронка только выбирает.** Опцию из списка
  «Выбора» или готовое поле записи для текстового компонента.
  Редактировать, дописывать, сокращать запрещено. Сервер проверяет
  каждое значение ответа против записи и опций, чужое отбрасывает.
- **Д11 (юзер, 2026-10-15). Рекомендованные компоненты.** Параметр
  записи, которому в дереве юзера некуда лечь, приходит секцией «без
  компонента» с готовым описанием компонента; приложение предлагает
  создать его одним нажатием, отказ запоминается по словарю. Вместо
  каталога по языку: дерево растёт от данных, по одному параметру.
- **Д12 (юзер, 2026-10-15). Правило отбора: не больше трёх, по роли,
  без почти-синонимов.** Из текста: первое значение — употреблённое в
  этом тексте, второе и третье — если есть и достаточно отличаются от
  первого и друг от друга. По одному слову без текста: первое — самое
  распространённое и обычное, второе и третье — те, что показывают
  разнообразие употребления. Десятки значений Викисловаря часто
  описывают одно и то же разными словами — такие не дублируются.
- **Д13 (юзер, 2026-10-15). Два списка и сопоставление ключами.**
  Нейронка получает значения записи на языке изучения и на языке
  перевода, оба с ключами, и к выбранному значению подбирает значение
  на языке перевода про то же самое. Ответ — ключи, лексему собирает
  сервер. Нет значения на языке перевода — отдаётся толкование на языке
  изучения с пометкой, как сейчас; перевод от нейронки не нужен.
- **Д14 (юзер, 2026-10-15, с сомнением). Источник языка перевода —
  главный.** Для словаря es → ru нейронка получает только русские
  значения; английские — лишь когда русской статьи или нужного значения
  в ней нет. Английский Викисловарь остаётся для ведения формы к лемме
  и как запасной источник, в выдачу не подмешивается, пока русский
  отвечает. Юзер принял с оговоркой «всё равно как-то хуёво выглядит» —
  пересмотреть, когда появится контрольный набор слов.

- **Д15 (юзер, 2026-10-15). Нейронка через OpenRouter, модель по цене
  снизу вверх.** Три-пять кандидатов из OpenRouter по цене и скорости,
  в том числе китайские, если дешёвые; начать с самой дешёвой, не
  устраивает результат на контрольном наборе — подниматься выше. На
  Anthropic не останавливаться. Модель — параметр конфига сервера, без
  правки кода.

- **Д16 (юзер, 2026-10-15). Без лимитов нейронки, но с местом под
  них.** Потолков на запрос и в сутки сейчас нет; в архитектуре счётчик
  токенов нейронки по субъекту и точка, где лимит включается конфигом
  и переводит запрос на запасной путь. Скорее всего включить придётся.

- **Д17 (юзер, 2026-10-15). Нейронка раскладывает по имени и значениям
  компонента, из любого текста записи.** Задача — разложить данные
  слова по компонентам максимально полно и корректно: толкование в
  перевод не попадает, «Пример» получает примеры, «Транскрипция» —
  транскрипцию, если она в записи есть. Если имени и значений
  компонента не хватает, чтобы понять его назначение, нейронка кладёт
  в ответ пометку для показа юзеру: «назначение компонента непонятно»,
  и ничего в него не пишет. Станет таких много — у компонента появится
  поле описания для нейронки, отдельной задачей.

- **Д18 (юзер, 2026-10-15). «Куда пишем» уходит, вместо него два
  раздела.** «Как разложено» — свёрнутая справка, что из записи в какой
  компонент легло, для оценки модели; позже в dev-сборку или прочь, то
  же в лог. «От словаря» — сообщения нейронки юзеру: назначение
  компонента непонятно, перевода нет и показано английское,
  рекомендация завести компонент — с именем и, если это «Выбор», со
  списком его опций. Пока без кнопок: только текст рекомендации,
  компонент юзер заводит сам в конструкторе. Уточняет Д11.

- **Д19 (юзер, 2026-10-15). Контекст — весь распознанный текст.**
  Устройство шлёт весь текст снимка одним куском, в пределах нынешнего
  лимита в две тысячи слов; нейронка сама находит слово в тексте.
  Станет накладно — уменьшим. Выделение области снимка рамкой, чтобы
  ограничить контекст абзацем или фразой, — бэклог приложения.

- **Д20 (юзер, 2026-10-17). Второе и третье значения — самые
  употребительные из остальных.** Не «заметно другие»: после первого
  (употреблённого в контексте или самого обычного без контекста) берутся
  другие самые употребительные значения. Значений у леммы всего три —
  все три; пять — первое и два самых употребительных из остальных.
  Правило одно с контекстом и без. Уточняет Д12: почти одинаковые
  значения считаются одним.
- **Д21 (юзер, 2026-10-17). Без нейронки — первое значение по порядку,
  по одному на часть речи.** Запасной путь не отдаёт все значения леммы:
  у каждой части речи леммы берётся первое значение по порядку источника,
  сначала из источника языка перевода, нет его — из английского: «run» →
  «бегать» и «бег». Без раскладки, с пометкой «без нейронки». Правило на
  сейчас, под текущие данные. Снимает вопрос бэклога бэкенда «сервер
  отдаёт все лексемы, устройство показывает пятёрку»: сервер отдаёт
  отобранное, хвоста нет.

- **Д22 (юзер, 2026-10-17). Отдельного поля контекста нет.** Контекст —
  сами токены снимка в порядке текста, с повторами: устройство их больше
  не схлопывает, сервер склеивает в текст для нейронки и схлопывает для
  поиска. Теряются только переносы строк. Уточняет Д19. Поле вернётся,
  если контрольный набор покажет, что текста из токенов не хватает, или
  когда рамка на снимке разведёт «что искать» и «где употреблено».

- **Д23 (юзер, 2026-10-17). Данные записи — все, без экономии.**
  Нейронке уходят все короткие метки записи: грамматика, пометы, уровень,
  плюс имена непустых полей. Устройству у лексемы-кандидата — грамматика,
  уровень, синонимы, антонимы, у леммы — произношение; раскладка может
  указывать на любое из них. Таблицы форм слова в ответ не идут, пока нет
  компонента под них. Сокращатель меток не заводится: по оценке на
  фикстурах метки дают около трети токенов промпта, главный множитель —
  число значений; счётчик Д16 покажет, когда об этом думать.

- **Д24 (юзер, 2026-10-17). Пары — списком.** К выбранному значению
  нейронка даёт не одно значение другого списка, а список по убыванию
  уверенности; пустой — пары нет. Сервер берёт толкование и грамматику из
  первого, примеры со всех. Иначе под «банк» терялись бы два из трёх
  английских значений, а при отсутствии пары нейронка тянула бы чужое.
  Уточняет Д13.

- **Д25 (юзер, 2026-10-17). Нейронке всегда идут значения обоих
  источников.** Один список на слово, в нём и русские, и английские
  значения с ключами источника; русские не выключают английские. Иначе
  парам не из чего браться, и у лексемы не будет толкования и примеров.
  Уточняет Д14: русское значение главное при выборе, английские — пары
  к нему и запасной путь, когда русских нет.

- **Д26 (юзер, 2026-10-17). Ручка одна.** Карточка слова и снимок идут
  в один `lookup`, различие — один токен или много. Вторая ручка появится,
  когда у одиночного слова будут свои гарантии: скорость, лимиты, другой
  ответ. Правило регистра — без контекста написание пользователя
  считается правдой, с контекстом ищутся оба написания — в бэклоге
  бэкенда, в 536 не входит.

- **Д27 (юзер, 2026-10-17). Старые поля уходят.** `candidates` у слова
  и схемы `Candidate`, `Sense`, `Parameters` убираются из контракта в этой
  фиче: их никто не читает, приложение берёт `lemmas` с релиза 0.1.17,
  других клиентов нет. Утверждения про них становятся «заменено».

- **Д28 (юзер, 2026-10-17). Дерево компонентов — как в контракте.**
  Вложенность по зависимостям: корень — компоненты от лексемы, `children`
  компонента — зависящие от него, `children` опции — зависящие от выбора
  этой опции; у встроенных компонентов и опций ключ, у своих — имя и
  подпись. Контракт на примерах `contract.md` одобрен целиком.

- **Д29 (юзер, 2026-10-17). Для словаря с языком перевода en толкование
  и есть перевод.** У лексем английского Викисловаря переводов нет, а
  толкование уже на языке перевода: оно ложится в «Перевод»,
  `no_translation` не ставится. Для остальных языков перевода толкование в
  «Перевод» не кладётся.

- **Д30 (юзер, 2026-10-17). Рекомендация компонента — по любому непустому
  полю записи.** Не только по меткам: нет «Примера» — рекомендуется
  «Пример», нет «Синонимов» — они. Станет надоедать — сократим до меток.
- **Д31 (юзер, 2026-10-17). Лемма с пустым отбором нейронки в ответ не
  идёт.** Пустой отбор читается как «эта лемма к тексту не относится»:
  «banco» в тексте про парк — глагол «bancar» в ответе отсутствует.
  Пустую лемму не возвращать. Негодный ответ по лемме — другое, это В2.
- **Д32 (юзер, 2026-10-17). «Выбор» с признаком «несколько» получает все
  подходящие опции.** Без признака — одну, лишние строки раскладки
  отбрасывает сервер.
- **Д33 (юзер, 2026-10-17). Нейронка зовётся пачками по N слов
  параллельно.** N и потолок параллельных вызовов — конфиг сервера,
  старт с N = 1, по одному слову: любой вызов влезает в окно модели, сбой
  бьёт одно слово, цена — повтор контекста и дерева в каждом вызове.
  Пачка не ответила → без нейронки только её слова.
- **Д34 (юзер, 2026-10-17). Своего срока у нейронки нет.** Её ограничивает
  только остаток бюджета ответа 170 секунд: что не успело — по В2 с
  первым значением, ответ приходит вовремя. Бюджет 180 на устройстве и
  170 на сервере не меняется. Юзер считает это временным: долгий снимок
  как задача с ожиданием до 20 минут, вебсокет — бэклог бэкенда.
- **Д35 (юзер, 2026-10-17). Провайдер нейронки — любой по цене.** Текст
  снимка и имена компонентов могут храниться у провайдера и идти в
  обучение; фильтра по политике хранения нет.
- **Д36 (юзер, 2026-10-17). Первое значение без нейронки — по порядку
  WFT-75.** Значения с переводами раньше, пометы регистра в конец:
  «bancar» → «to pick up the tab», не разговорное «to support». Уточняет
  Д21.
- **Д37 (юзер, 2026-10-17). Поля `parent` и `parentKey` сняты из
  ответа.** При трёх значениях на лемму иерархии не видно, а ссылка на
  отсутствующего родителя — мина. Признак родителя остаётся в списке до
  отбора: порядок и нейронка его видят.

- **Д38 (юзер, 2026-10-17). Без нейронки ответа нет.** Раскладывает по
  компонентам только нейронка; значения из базы слов без отбора и
  раскладки не отдаются. Нейронка не ответила ни разу — отказ 503 и
  ошибка пользователю сразу; упала часть вызовов — их слова «ошибка»,
  остальные как обычно; лимит нейронки исчерпан — 429. Заменяет Д21 и Д36,
  уточняет Д33 и Д34: что не успело к нейронке — «ошибка», не первое
  значение.
- **Д39 (юзер, 2026-10-17). Нет перевода — английское толкование в
  «Перевод».** Данные раскладываются только по компонентам пользователя,
  компоненты за него не меняются; нейронка может лишь рекомендовать
  завести новый. Значение без перевода на язык словаря получает в
  «Перевод» английское толкование с пометкой, пользователь видит его и
  решает сам: не нравится — не добавляет. Обобщает Д29.
- **Д40 (юзер, 2026-10-17). «Как разложено» — один раздел на окно.**
  Компоненты одни на весь словарь, поэтому справка «поле записи →
  компонент» собирается по всем лексемам ответа и показывается одним
  свёрнутым разделом, не у каждой лексемы. Уточняет Д18.

- **Д41 (юзер, 2026-10-17). «Как разложено» у «Выбора» — компонент и
  опция, без метки записи.** Строка «Часть речи: существительное», «Род:
  м.р.»; у текстовых компонентов — «поле записи → компонент». Нейронку
  не просят сообщать, по какой метке выбрана опция, контракт не меняется.
- **Д42 (юзер, 2026-10-17). Пометка «есть» — только по ядрам.** Значение
  из словаря считается уже имеющимся, если совпало значение ядра
  («Перевод»), параметры вроде «Толкования» не сравниваются: «студентка»
  с тем же английским толкованием, что у «студент», добавляется.
- **Д43 (юзер, 2026-10-17). Отказ 503 токены не списывает.** Нейронка
  легла целиком, пользователь ничего не получил — его суточный лимит не
  уменьшается.
- **Д44 (юзер, 2026-10-17). Контекст снимка пишется в лог сервера
  целиком.** Пока нужна полная картина для оценки отбора и раскладки: в
  логе вызова нейронки — номер запуска, весь контекст, ключи и раскладка,
  без ключей доступа и нейронки. Юзер: «пока».

- **Д45 (юзер, 2026-10-18). Кеш отбора — в памяти процесса, без
  сохранения.** Кеш отбора без контекста (WFT-94) остаётся в фиче. Он
  живёт в памяти сервера и пропадает при рестарте и деплое. Кеш снимков
  не делается: текст почти не повторяется, попаданий не будет. Юзер:
  «пока не сохраняет».

- **Д46 (юзер, 2026-10-19). Совместимость со старыми сборками не
  нужна.** В приложении 0.1.17 поле `candidates` у слова обязательное
  (`WordResultDto` в `LookupDto.kt`), и на сервере без него по Д27 старая
  сборка не разберёт ответ. Это принято: приложение не в проде,
  `candidates` уходит без заглушки, сборку на устройстве обновить сразу
  после деплоя сервера. Подтверждает Д27.

- **Д47 (юзер, 2026-10-19). Сервис «Доступ» делится на `Auth` и
  `Quota`.** `Auth` отвечает «кто ты»: субъект по ключу, потом по
  Google и Telegram; правило живости ключа переезжает сюда из запроса
  к Postgres, хук ручки зовёт `Auth` и в хранилище не ходит. `Quota`
  отвечает «сколько можно»: лимит субъекта, потолок сервера, лимит
  нейронки, язык, списание и откат, расход токенов модели; его зовёт
  сервис запроса. Причина: способов входа станет несколько, а лимит на
  человека один, и правки входа не должны трогать лимиты. Имена выбрал
  юзер из вариантов.

- **Д48 (юзер, 2026-10-19). Три слоя: сценарий, сервис, порт; соседи
  друг в друга не ходят.** Сценарий один на операцию контракта, его
  зовёт ручка, он зовёт сервисы. Сервис — один шаг, его зовут только
  сценарии, он зовёт только порты. Сервисы между собой не общаются,
  сценарии тоже. Сервис запроса становится сценарием `LookupScenario`,
  списание токенов модели переезжает из Отбора в сценарий, хук ключа
  остаётся точкой входа с одним вызовом `Auth`. Общий код двух сервисов
  — признак неверной нарезки, не повод для общего пакета. Код и схема в
  HLD приведены к этому сразу.

- **Д49 (юзер, 2026-10-19). Ядро обязательно.** Самое важное в фиче —
  адекватное и корректное ядро, ответ без него — не результат. У каждой
  отданной лексемы-кандидата в раскладке есть строка в включённое ядро с
  непустым текстом: промпт требует её от нейронки, проверка сервера без
  неё лексему не пропускает — это негодный ответ, как чужой ключ. У
  леммы не осталось годных — слово «ошибка» (WFT-97). Пустое поле ядра в
  окне бывает только после стирания руками. Отменяет AWP-33, уточняет
  WFT-85 и WFT-87.

- **Д50 (юзер, 2026-10-19). Слова: «словарь» — только словарь
  пользователя.** Что приходит с сервера, называется тем, что оно
  есть: лексемы-кандидаты. Окно добавления — «окно лексем-кандидатов»,
  диалог в карточке — «диалог лексем-кандидатов». Раздел «От словаря»
  — «Замечания», сообщение словаря — «замечание». «Раскладка» уходит:
  то, что нейронка сопоставила значению, — «сопоставление», одна пара
  компонента с опцией или полем — «строка сопоставления», раздел «Как
  разложено» — «Сопоставление». Тексты для пользователя без «словаря»
  в смысле источника: кнопка «Добавить лексемы-кандидаты», «Сервер
  сейчас недоступен», «Лексем-кандидатов для «…» нет», «У
  лексем-кандидатов есть «Род»…». Название фичи в документах —
  «Лексемы-кандидаты через нейронку». «Соответствия» остаются за
  отменённым выбором компонентов руками из IS532, чтобы не путать.
  Переименовано во всех спеках, контракте, openapi, глоссарии и HLD.

- **Д51 (юзер, 2026-10-19). Окно лексем-кандидатов со снимка — свой
  экран со своим редьюсером.** Вкладка «Слова» открывает только диалог
  выбора источника и запускает системную камеру или галерею. Как только
  снимок получен, вкладка открывает новый экран и передаёт ему `Uri`
  файла. Экран сам распознаёт текст, шлёт запрос на бэкенд, грузит
  форму словаря, показывает карточки и пишет в словарь. Граница: до
  снимка — вкладка, после снимка — экран. Причина: один редьюсер
  вкладки крутил выбор источника, камеру, распознавание, запрос, форму,
  окно, листы и вопросы, а приставка `Photo` у всех его сообщений была
  костылём вместо своего редьюсера. Следствия: сообщения экрана без
  приставки; проверка номера запуска на пути снимка не нужна — экран
  живёт один снимок, закрыли экран — ответу некуда прийти; все ошибки
  после снимка в экране, на вкладке только «нет камеры» и отмена
  выбора; экран — отдельный маршрут навигации со своей ViewModel, не
  диалог внутри вкладки; вход — `Uri`, не токены. Снекбар «Добавлено N
  значений в M слов» — по-прежнему на вкладке после возврата. Карточка
  слова идёт своим путём: предложенные лексемы в диалоге карточки, как
  сейчас; общая логика двух окон — чистые функции `widget/candidates`,
  редьюсеры только подключают. Делается в IS536, первым шагом
  приложения: рефакторинг IS527/IS532, раздел приложения в HLD заново.

- **Д52 (юзер, 2026-10-19). Возврат после гибели процесса открывает
  экран со снимком.** Android убил приложение, пока была открыта
  системная камера или галерея; вернулись — снимок пришёл, вкладка
  открывает экран как обычно, снимок не выкидывается. Снимок камеры —
  наш файл в кеше, читается всегда. Картинке из галереи фотопикер даёт
  доступ до остановки процесса или перезагрузки; вкладка закрепляет
  доступ одним вызовом при получении `Uri`, экран отпускает его после
  распознавания. Если прочитать всё же не вышло — ошибка на экране.
  В5 WFP и WFP-22 так и говорят: снимок после перезапуска продолжает
  запуск; к WFP-22 добавлена граница про доступ к файлу галереи.

- **Д53 (юзер, 2026-10-19). «Повторить» при отказе сервера на экране
  снимка.** При сетевой ошибке и «Сервер сейчас недоступен» рядом с
  «Закрыть» есть «Повторить»: запрос уходит заново с теми же токенами,
  без нового снимка. При отказе по ключу или лимиту — только «Закрыть»,
  повтор ничего не изменит. Раньше при любом отказе было только
  «Закрыть», повтор — новый снимок.

- **Д54 (юзер, 2026-10-20). Сопоставление компонентов в контракте и
  коде — `componentMatches`.** Строка сопоставления — `ComponentMatch`,
  список у лексемы-кандидата — `componentMatches`; в приложении
  `PhotoComponentMatch`, раздел — `isComponentMatchesExpanded`. Слово
  `layout` ушло: оно было взято из поля JSON, а в Android значит
  вёрстку. Имена в коде идут от термина, не от поля; поле тоже от
  термина. Переименовано в контракте, openapi, спеке WFT и HLD.

- **Д55 (юзер, 2026-10-20). Замечание в коде и контракте — `Remark`.**
  Строка раздела «Замечания» в стейте — `Remark`, список `remarks`;
  замечание по слову в ответе — `WordRemark`, поле слова `remarks`;
  рекомендация компонента ко всему ответу — `ComponentRecommendation`,
  поле ответа `recommendations`. Поле `messages` и имя
  `PhotoDictionaryNote` ушли: «dictionary» — от старого «сообщения
  словаря», переименованного в Д50. Контракт, openapi, спека WFT, HLD.

- **Д56 (юзер, 2026-10-20). Приставка `Photo` у типов окна снята.**
  Слово в имени должно говорить о вещи; `Photo` у `PhotoCard`,
  `PhotoSheet`, `PhotoDictionaryForm` не говорило ничего — приставка
  по модулю из IS532. Имена по вещи: окно — `LemmaCard`, `CardLexeme`,
  `CandidateValue`, `EditableText`, `ValueRef`, `ComponentRef`,
  `ComponentMatch`, `ComponentMatchLine`, `CandidatesSheet`,
  `AddSummary`, `AddFailure`; форма словаря — `DictionaryForm`,
  `FormComponent`, `FormOption`, `ComponentDependency`, `FormError`,
  `FormOutcome`, шаблон — `ComponentTemplate` из домена вместо своей
  копии; ответ сервера глазами экрана — `LookupOutcome`, `LookupWord`,
  `LookupLemma`, `LookupLexeme`, `LookupDenyReason`. Остаётся
  `PhotoPicker` во вкладке: он про снимок. В HLD сейчас, в коде при
  реализации.

- **Д57 (юзер, 2026-10-20). Слои типов и маппинг в приложении.**
  Четыре слоя снизу вверх. Транспорт: Room `*Db`, Retrofit `*Net`,
  наружу из `core-*-impl` не выходят. Зеркало: `*ApiEntity` в
  `core-db-api` и `core-network-api` — чистая копия транспорта без
  правил, у обоих источников один суффикс; исход вызова сети —
  `LookupResult`. Домен: `modules/domain/*`; считается, что он есть у
  всего, где его нет — заводится, когда трогаем ту часть; исходы
  юзкейсов тоже домен: `LookupOutcome`, `FormOutcome`. Стейт: UI-типы
  экранов и общих виджетов, одиночные `*Ui`, элементы списка одного
  вида `*UiItem`, без исключений для собранных — `LemmaCardUiItem`,
  `AddSummaryUi`; доменные значения внутри UI-типов как есть:
  перечисления, id, `DependencyTarget`. Маппинг на каждой границе — в папке `mapper/` того
  модуля, где граница: транспорт ↔ зеркало в `core-*-impl`
  (`toApiEntity()`, обратно `toDb()`, `toNet()`); зеркало → домен в
  `app/mapper/` (`toDomain()`, имя зеркала = имя домена плюс суффикс);
  домен → UI в экране или общем виджете (`toUi()`). Исход юзкейса не
  мапится: хендлер ветвится по нему `when` на месте и шлёт сообщение,
  данные внутри — через `toUi()`; что собирается из нескольких частей
  стейта — сборка в атоме. Юзкейс — порт экрана, говорит доменом, один
  порт служит двум окнам. Экраны и виджеты `core-*-api` не
  импортируют; запрет — проверкой в `build-logic`, исключение для
  `components_manager` до починки. `widget/candidates` остаётся как
  есть: UI-типы, их сборка и composable — один слой; исходы из него
  уходят в домен. Гайд — `docs/handbook/guides/types-and-mapping.md`.

- **Д58 (юзер, 2026-10-20). Без ядра нет лексемы.** Ядро — не лексема,
  но без ядра лексемы нет: лексема-кандидат, у которой стёрли или
  удалили крестиком последний текст последнего включённого ядра,
  удаляется из окна целиком, как крестиком; пустое ядро с пометкой «не
  попадёт в ядро» в окне не живёт. Пока хоть одно ядро с текстом —
  лексема на месте. Пересчёт зависимых компонентов после стирания текста
  остаётся для не-ядер (стёр последнюю «Заметку» — зависимый «Пример»
  гаснет).

- **Д59 (юзер, 2026-10-20). Одновременности действий нет.** Пальцы делают
  одно дело за раз: пока окно снимка или диалог карточки открыты,
  пользователь не удалит словарь, компонент или слово и не выключит
  компонент. Такие случаи — не кейсы: ни строки спеки, ни кода.
  «Словарь удалён при записи» в диалоге снят; страховка от двойного тапа
  снята — кнопка живёт по стейту (гайд стейта, принцип 7). Слово ответа
  `error` в диалоге карточки — текст «Сервер сейчас недоступен» с
  «Повторить», как 503 (WCL-11.9).

- **Д60 (юзер, 2026-10-21). Карточка леммы всегда целиком.** Свёрнутого
  вида и переключателя у карточки нет: лемма, слова, «куда класть»,
  группа и все лексемы-кандидаты со значениями видны сразу. Краткая и
  раскрытая формы слишком разные, пользователь должен видеть всё.
  AWP-04.10 переписана, AWP-04.11 снята; `ToggleCard`, `isExpanded`,
  тексты свёрнутой карточки убраны из виджета и редьюсеров.

- **Д61 (юзер, 2026-10-22). Сервер ответ нейронки не правит.** Нейронка
  отдаёт заполненную карточку: по смыслу — значение записи, его строка
  в ядро, его часть речи, остальные компоненты словаря значениями из
  записи, которые можно показать как есть. Сервер только проверяет
  простое (ключ из списка леммы, компонент из дерева, поле непустое),
  негодное отбрасывает, своего не подставляет и собирает ответ
  приложению. Замены «по записи» (перевод ↔ толкование, часть речи),
  слоты по языкам и серверная перестановка пар сняты. Что нельзя
  положить не туда, держит схема ответа, построенная по входу вызова:
  по варианту на значение, строки по языку назначения компонента,
  только примеры в компонент примеров. Контракт бэкенда, раздел 4;
  WFT-97.15.

- **Д62 (юзер, 2026-10-22). Правка промпта и схемы проверяется на модели
  до выпуска.** Деплой — не стенд: `lexeme probe llm` гоняет сценарий
  тем же кодом на сервере с ключом из `.env`, кандидаты по сети, и
  печатает карточки; тег только после хорошего прогона. Модель
  `gpt-4o-mini` не меняется без решения юзера; теги только патчем.

- **Д63 (юзер, 2026-10-22). Только словарь языка перевода.** Значения,
  перевод и примеры кандидатов берутся только из Викисловаря на языке
  перевода словаря, без смешения изданий: для перевода на русский —
  Русский Викисловарь, на английский — Английский. Смыслы двух изданий
  нарезаны по-разному и ничем не связаны, а сводя их в пары, модель
  ошибалась: «Перевод» от одного смысла, толкование от другого (ручники
  M2: with, that, journal, have). Лемму ищем как раньше. Слово без
  статьи в нужном издании — «не найдено» (high-quality, Illinois);
  компонент толкования на другом языке не заполняется. Для языков
  перевода, которых в базе нет, пока как раньше — бэклог.

- **Д64 (юзер, 2026-10-22). Примеры по значению.** В значении кандидата
  только примеры его смысла: схема ответа строится вариантом на смысл, и
  в варианте компонент примеров принимает только примеры этого смысла.
  Общего списка примеров на всё слово нет. У смысла без своих примеров
  компонент пуст. Серверное снятие пар со строками соседних смыслов
  больше не нужно.

- **Д65 (юзер, 2026-10-22). Служебные слова в IS536 не отсеиваем.** Отсев
  служебных слов и имён, разбор текста моделью и карточка слова по тапу —
  отдельной фичей после IS536 (бэклог «Разбор текста сразу, карточка
  слова по тапу»). Промпт под служебные слова в IS536 не подгоняем.

- **Д66 (юзер, 2026-10-22). Правки окна кандидатов — в бэклог.** Пометка
  «в тексте» у первого значения и порядок компонентов в карточке в IS536
  не делаем: после разбора текста и карточки по тапу они могут стать
  неактуальны.

- **Д67 (юзер, 2026-10-22). Нейронка берёт только из предложенного.**
  Своих строк модель не пишет. Если точного смысла в записи нет, она
  берёт ближайший, и это не ошибка модели, а дыра записи: у journal в
  Русском Викисловаре нет «журнала» как издания, у likely есть только
  «правдоподобный».

Открытых вопросов нет.
