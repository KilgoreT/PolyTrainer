# IS536 | HLD LIM — лимиты, черновик

План по спеке LIM: контракт, через который операции начинают и
заканчивают работу аккаунта. В v2 лимиты — прокладка: логики лимитов
работ нет, «начать работу» всегда пускает, «закончить работу»
записывает расход нейронки (Д106). Счётчик и лимит токенов нейронки
остаются как в v1. Операции, которые зовут лимиты, — `hld-lft.md` и
`hld-lfl.md`; аккаунт им даёт доступ, `hld-acc.md`.

## 1. Рамка

- **Цель** — заложить два вызова, через которые позже ляжет политика
  лимитов, и не списывать ничего, пока политики нет.
- **Вход и выход** — от сценария: аккаунт и вид работы в начале,
  расход нейронки в конце; назад — «можно» или `ErrRateLimited`, когда
  исчерпан лимит токенов нейронки.
- **Что меняется на сервере** — `Quota` вместо `Check`, `Charge`,
  `Refund`, `ChargeModel` получает `Begin` и `Finish`; потолок сервера,
  лимит токенов запроса и язык из него уходят; порт «Расход» остаётся
  с двумя методами про токены модели.
- **Документы** — спека LIM, [решения](decisions.md) Д73, Д77, Д78,
  Д106; политика лимитов — бэклог приложения.

## 2. Схема и код

Схемы слоёв у лимитов нет: `Quota` и порт «Расход» стоят на схемах
обеих операций. Код — сервис целиком, порт сигнатурами.

```go
// QuotaService — LIM Ш1 и Ш2: начать работу, закончить
// работу. Пакет service, меняется.
type QuotaService interface {
    Begin(
        ctx context.Context,
        account domain.Account,
        work domain.Work,
    ) error
    Finish(
        ctx context.Context,
        account domain.Account,
        usage domain.ModelUsage,
    ) error
}

// Work — вид работы (LIM-111): словарные формы текста,
// значения слова. Пакет domain, новый.
type Work string

const (
    WorkTextLemmas  Work = "text_lemmas"
    WorkWordLexemes Work = "word_lexemes"
)

// Begin — Ш1: можно ли аккаунту начать работу. Лимит
// работ — прокладка, всегда «можно» (LIM-110), вид работы
// пока ни на что не влияет; лимит токенов нейронки из
// конфига — ErrRateLimited, когда за сутки записано не
// меньше предела (LIM-96). Меняется: бывший Check без
// токенов запроса, потолка сервера и языка.
func (q *quota) Begin(
    ctx context.Context,
    account domain.Account,
    work domain.Work,
) error {
    modelSpent, err := q.usage.ModelSpent(
        ctx, account,
        q.clock.Now(),
    )
    if err != nil {
        return internal(err)
    }
    if exceeded(modelSpent, q.options.ModelDaily) {
        return domain.ErrRateLimited
    }
    return nil
}

// Finish — Ш2: работа окончена, расход нейронки в счётчик
// аккаунта (LIM-79); расход 0 — нейронка не ответила или
// не звалась, счётчик не растёт; с работ пока ничего не
// списывается (LIM-112). Ошибку хранилища отдаёт
// сценарию: тот пишет её в лог, ответ уже решён.
// Меняется: бывший ChargeModel.
func (q *quota) Finish(
    ctx context.Context,
    account domain.Account,
    usage domain.ModelUsage,
) error {
    if usage.Total() == 0 {
        return nil
    }
    return q.usage.ChargeModel(
        ctx, account,
        q.clock.Now(), usage,
    )
}
```

Что зовёт Quota. Порт «Расход», `UsageRepository`:

```go
// ModelSpent — токены модели аккаунта за день (LIM-79).
// Есть.
ModelSpent(
    ctx context.Context,
    account domain.Account,
    day time.Time,
) (int, error)

// ChargeModel — прибавить токены модели к расходу дня.
// Есть.
ChargeModel(
    ctx context.Context,
    account domain.Account,
    day time.Time,
    usage domain.ModelUsage,
) error

// Spent, SpentTotal, Charge, Refund — сняты: токены
// запроса не считаются. Столбец tokens в таблице usage
// остаётся, не пишется.
```

Порт «Часы», `Clock`, и помощники пакета `quota`: `Now`, `exceeded`,
`internal` — есть; `wouldExceed` и `unsupported` сняты. В настройках
остаётся только `ModelDaily`, лимит токенов нейронки в сутки на
аккаунт; `ServerDaily` и `SupportedLanguages` сняты — языки теперь у
сервиса «Языки» (`hld-lfl.md`).

## 3. Контракт

В `api/openapi.yaml` у лимитов своих полей нет. Меняется описание 429
`rate_limited` у обеих операций: только лимит токенов нейронки, лимит
работ пока не отказывает.

## 4. Ключевые решения

- **Лимиты — прокладка** (Д106): контракт двух вызовов, ответ всегда
  «можно», с работ ничего не списывается; политика — бэклог.
- **Лимит в работах, не в токенах запроса** (Д73): единица будущей
  политики — работа, вид работы уже передаётся.
- **Два вызова из сценария** (Д78): `Begin` до нейронки, `Finish`
  после; политика списания и возврата — внутри сервиса, когда появится.
- **Лимиты — сервисная спека** (Д77): операции ссылаются одной строкой.

## 5. Сквозное

- **429** — только `Quota.Begin`, из сценария, после размера и языка.
- **Расход** — `Finish` после решения ответа: расход 0 — счётчик не
  растёт; сбой записи — лог сценария, ответ не ломается.
- **Сутки** — дата по UTC, как в v1.

## 6. Выкатка

- **База данных** — миграций нет: столбцы `usage.tokens` и
  `accounts.daily_limit` остаются, не пишутся и не читаются.
- **Конфиг** — лимит токенов нейронки как был, по умолчанию выключен;
  переменная `LLM_SUBJECT_DAILY` становится `LLM_ACCOUNT_DAILY` (Д115)
  — на проде и в `deploy.md`.

## 7. Риски

- **Лимитов работ нет** — защита от расхода только лимитом токенов
  нейронки, он выключен; включить — конфиг.
- **Гонка одновременных запросов** — при включённом лимите нейронки
  несколько запросов проходят `Begin` до записи расхода, как в v1
  (LIM-96.7).
