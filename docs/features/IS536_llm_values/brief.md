# IS536 | Бриф: лексемы-кандидаты через нейронку

Ишью #536, ветка `IS536_llm_values` от `master`. Решения —
`decisions.md`, техника — `plan.md`.

## Цель

Юзер получает из словаря не пять первых попавшихся значений, а нужные,
не больше трёх. Из текста: первое — то, в котором слово употреблено в
этом тексте, второе и третье — если есть и достаточно отличаются от
первого и друг от друга. По одному слову без текста: первое — самое
распространённое и обычное, второе и третье — те, что показывают
разнообразие употребления. Десятки значений Викисловаря — это чаще
одно и то же разными словами, такие не дублируются. Значения приходят
уже сопоставленными с компонентами словаря юзера, включая свои компоненты
вроде «Род». Ничего не настраивается
ни на сервере, ни в приложении. Когда у словаря есть параметр, которому
в словаре юзера некуда лечь, приложение предлагает завести компонент
одним нажатием.

## Сценарий

1. Юзер фотографирует текст или нажимает кнопку словаря в карточке
   слова.
2. Приложение отправляет бэкенду все слова снимка в порядке текста, с
   повторами — они же контекст — и дерево компонентов словаря.
3. Бэкенд берёт записи слов из базы, нейронка выбирает не больше трёх
   значений. Из текста: первое — употреблённое в этом тексте. Без текста:
   первое — самое обычное. Второе и третье в обоих случаях — самые
   употребительные из остальных. Почти-синонимы не повторяются. Каждое
   значение уже сопоставлено с компонентами: опция у «Выбора», готовое поле
   записи у текстового.
4. Юзер видит кандидатов с компонентами, при желании правит и нажимает
   «Добавить» → всё ложится в словарь.
5. Под кандидатами раздел «Замечания»: что нейронке было непонятно,
   где показано английское вместо русского, какой компонент стоит
   завести и с какими опциями. Юзер заводит его сам в конструкторе, в
   следующий раз значения лягут туда. Свёрнутый раздел «Сопоставление»
   показывает, что из записи куда легло.

## Границы

Входит:

- запрос с деревом компонентов словаря: id, имя, шаблон, опции с id и
  подписями, признак ядра, зависимость
- контекст: сами токены снимка в порядке текста, с повторами, отдельного
  поля нет; у карточки слова один токен, контекста нет
- на сервере: нейронке один сжатый список значений записи с ключами —
  обоих Викисловарей, языка перевода и английского — и контекст; она
  выбирает значения по правилу отбора и к каждому подбирает значения
  другого Викисловаря про то же самое, списком, или «нет такого»; ответ
  только ключами, лексему-кандидата по ключам собирает сервер
- нет значения на языке перевода — толкование на языке изучения с
  пометкой, как сейчас
- значение на языке перевода — главное при выборе; английские значения
  — пары к нему и запасной путь, когда русских нет
- нейронка только выбирает: опцию из списка «Выбора», готовое поле
  записи для текстового компонента; редактировать, дописывать,
  сокращать — запрещено; сервер проверяет каждое значение против записи
  и опций
- ответ: у лексемы-кандидата сопоставление «компонент → опция» или
  «компонент → поле записи», первое значение — основное; замечания
  по слову и рекомендация компонента по запросу с его именем,
  шаблоном и опциями
- приложение: отправка токенов и компонентов, показ кандидатов с
  сопоставленными компонентами, раздел «Замечания» текстом — компонент
  непонятен, нет перевода, рекомендация компонента, свёрнутый раздел
  «Сопоставление»; строка «Куда пишем» уходит
- без нейронки ответа нет: нейронка недоступна — отказ и ошибка
  пользователю, значения из базы слов без отбора не отдаются
- кеш ответов без контекста по слову и набору компонентов; бюджет
  нейронки внутри лимитов субъекта
- контрольный набор слов с ожидаемыми значениями для оценки качества
  выбора

Не входит:

- встроенные компоненты, привязка компонентов на сервере, каталоги
  параметров по языку
- хранение компонентов юзера на сервере: они в каждом запросе
- правка значений нейронкой
- другие источники, кроме базы слов из выгрузок

## Разрез

Бэкенд первый:

- модель и провайдер нейронки — решить
- поле запроса: дерево компонентов; контекст — сами токены
- шаг нейронки с проверкой ответа против записи и опций
- новая форма лексемы-кандидата и секция рекомендаций в ответе
- кеш, бюджет, контракт `api/openapi.yaml`
- строки продуктовых спек: WFT — выбор, сопоставление, рекомендации; WFP —
  контекст со снимка
- тег в прод

Приложение:

- токены как есть: с повторами, без схлопывания на устройстве
- дерево компонентов в запросе
- показ кандидатов с сопоставленными компонентами, основное значение
- разделы «Замечания» и «Сопоставление»
- ошибка «словарь сейчас недоступен» при отказе нейронки
- экранные строки AWP и WCL; продуктовые строки устройства в WFT и WFP
