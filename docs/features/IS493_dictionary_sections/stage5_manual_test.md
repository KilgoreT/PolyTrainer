# IS493 Э5–Э6 | Ручники фичи — полный набор

Слова попадают в группы: пикер + чипы карточки, живые окна раскрытых
групп на вкладке (Э5); импакт удаления + «удалить вместе со словами»
(Э6). Каждый кейс сверяется ГЛАЗАМИ и ЛОГАМИ; критерий провала —
blacklist (см. словарь), а не «всё неожиданное».

## Содержание

- [Словарь логов](#словарь-логов)
- M1–M5 — пикер и чипы карточки
- M6–M9 — окна групп на вкладке
- M10–M15 — гонки, каскады, живучесть, скролл пикера
- M16–M19 — Э6: импакт удаления и деструктив

## Словарь логов

Снимать: `adb logcat -d -t 400 | grep -E "###GROUPS###|###WORDCARD###|FATAL"`.

**Критерий провала (blacklist):** `FATAL EXCEPTION`;
`MembershipFailed` / `GroupWindowFailed` / `SliceLoadFailed` /
`WindowLoadFailed`; `membership add|remove failed`; `window(...) failed`;
расхождение с блоком «Маркеры» кейса. Всё остальное «лишнее» — см.
benign-дубли ниже.

**Benign (НЕ провал):** Room инвалидирует по ТАБЛИЦАМ — любой
insert/delete в `word_groups` переэмичивает `slice` и окна ВСЕХ
раскрытых групп (`window(group=N)` соседних групп при работе с одной —
норма); `no-op | reason=…` — осознанные guard'ы; повторные `slice:` с
теми же counts (distinctUntilChanged гасит большинство, но не все).

### reduce — сообщения и шаги reducer'ов

* `###GROUPS### Reduce ---message---: <Msg>` — вход reducer'а вкладки;
  тяжёлые (`SliceLoaded`/`WindowLoaded`/`GroupWindowLoaded`) — именем.
* `###GROUPS### Reduce ---step---: <атом> | k=v …` — атомарный шаг
  (полный набор атомов — StateAtoms.kt). Ключевые Э5:
  * `openGroupWindow | id=N limit=10` — окно группы открыто;
  * `closeGroupWindow | id=N` — закрыто (сворачивание);
  * `applyGroupCounts | expanded=N effects=M` — окна отреагировали на
    счётчики (автооткрытие/закрытие/компенсация внутри);
  * `applyGroupWindowWords | id=N words=K` — контент окна;
  * `recalcGroupHasMore | id=N hasMore=b` — футер «Ещё»;
  * `purgeDeadExpanded | dead=N` — мёртвые раскрытые вычищены.
* `###GROUPS### Reduce ---step---: no-op | reason=<...>` — guard.
* `###WORDCARD### Reduce ---step---: <атом>` — шаги блока групп карточки:
  * `openGroupPicker` / `closeGroupPicker`;
  * `applyDictGroups | ids=[…]` — список пикера (id-набор!);
  * `applyWordGroups | ids=[…]` — членства слова (id-набор!);
    чипы = пересечение двух наборов — рассинхрон виден по логу;
  * `markMembershipInFlight | groupId=N` / `clearMembershipInFlight …`.

### effects — эффекты вкладки

* `###GROUPS### effect: SetGroupWindow(groupId=N, limit=L)` — подписка
  окна группы; `limit=null` — погашена.
* `###GROUPS### effect: ClearGroupWindows` — все окна разом (смена
  словаря).
* `###GROUPS### effect: CreateGroup/RenameGroup/DeleteGroup(...)` — Э3.

### подписки — эмиссии данных

* `###GROUPS### slice: dict=D words=W groups=G` — структура словаря.
  **W — число СТРОК среза (пар слово-группа), НЕ distinct-слов:** слово
  в двух группах даёт две строки; удаление группы уменьшает W на её
  membership-строки без удаления слов (выяснено прогоном M17). Число
  слов словаря сверять счётчиком «Все» глазами.
* `###GROUPS### window: dict=D limit=L loaded=K` — окно «Все».
* `###GROUPS### window(group=N): limit=L loaded=K` — окно группы N.
* `###WORDCARD### wordGroups: word=W ids=[…]` — членства слова.
* `###WORDCARD### dictGroups: count=N ids=[…]` — группы словаря.

### Э6: удаление с импактом (финал: единый диалог + счётчик)

* `###GROUPS### Reduce ---step---: toggleDeleteWords | deleteWords=b` —
  галка (значение, не факт инверсии).
* `###GROUPS### effect: StartDeleteCountdown(seconds=5)` /
  `CancelDeleteCountdown` — запуск/гашение паузы осмысления.
* `###GROUPS### Reduce ---message---: DeleteCountdownTick` +
  `Reduce ---step---: tickDeleteCountdown | left=N` — секундные тики
  (кнопка «Удалить всё (N)»); хвостовой тик после отмены —
  `no-op | reason=tickDeleteCountdown: …`.
* `###GROUPS### Reduce ---step---: closeConfirmForDeadGroup | groupId=N`
  — конфирм закрыт: группа умерла под ним.
* `###GROUPS### effect: DeleteGroupWithWords(groupId=N)` — ДЕСТРУКТИВ.
* `###GROUPS### delete-with-words outcome: Success(deletedWords=N)` /
  `outcome: NotFound` — оба исхода логируются.
* **Анти-инварианты:** `DeleteGroupWithWords` без предшествующих
  `toggleDeleteWords | deleteWords=true` и 5×`tickDeleteCountdown` =
  провал (деструктив мимо галки/паузы невозможен);
  `no-op | reason=confirmDelete: countdown running` — легальный тап до
  конца счётчика.
* Blacklist +: `delete-with-words failed`.

### мутации membership

* `###WORDCARD### membership add: word=W group=G outcome=<O>` —
  `Added` (успех) / `AlreadyIn` (дубль-идемпотент) / `GroupNotFound` /
  `WordNotFound` (гонки — тихие, правит подписка).
* `###WORDCARD### membership remove: word=W group=G outcome=<O>` —
  `Removed` / `NotFound` (идемпотент).
* `###WORDCARD### Reduce ---message---: MembershipDone(groupId=N)` —
  плоский итог в reducer.

## M1. Открыть пикер групп с иконки карточки

**Что доказывает.**

Иконка групп в шапке карточки открывает пикер-шторку; пикер показывает
ВСЕ группы словаря (живая подписка dictGroups), галочки отражают факт
членства (пустые для слова вне групп).

**Вход.**

* Сборка Э5, словарь с 3+ группами (создать на вкладке «Группы»:
  `dom`, `byt`, `apteka`), 5+ слов.
* Данные приложения чищены после Э4 (смена схемы 13).

**Шаги.**

1. Открыть карточку любого слова.
2. Тап по иконке групп в шапке (слева от ⋮).

**Ожидание глазами.**

Шторка «Группы слова»: список `apteka`, `byt`, `dom` (алфавит), у каждой
пустой чекбокс. Чипов в шапке карточки нет.

**Маркеры в логах.**

```
###WORDCARD### dictGroups: count=3 ids=[…]
###WORDCARD### wordGroups: word=W ids=[]
###WORDCARD### Reduce ---message---: OpenGroupPicker
###WORDCARD### Reduce ---step---: openGroupPicker
```

**Анти-проверки.**

* Нет «Все» в списке пикера (виртуальная).
* Blacklist пуст.

**Прогон 2026-08-28:** ❌❌✅ тёмный фон шторки → containerColor=onPrimary; серые имена → color=secondary; после фиксов — логи по словарю


## M11. Back при летящей записи — flush-on-back

**Что доказывает.**

Контракт А11: выход из карточки ждёт membership-запись (лоадер), запись
не теряется. Запись быстрая — кейс ловится по ЛОГУ (порядок строк), не
глазами.

**Вход.**

* Карточка открыта, пикер открыт.

**Шаги.**

1. Тап по галочке и СРАЗУ (без паузы) свайп-закрытие шторки + Back.

**Ожидание глазами.**

Карточка закрылась (возможно мгновенный лоадер); при повторном входе
галочка/чип соответствуют тапу — запись не потерялась.

**Маркеры в логах.**

```
###WORDCARD### membership add|remove: … outcome=…   ← запись ДОЛЕТЕЛА
###WORDCARD### Reduce ---message---: MembershipDone(…)
(NavigationEffect.Back — после Done, если Back успел раньше)
```

**Анти-проверки.**

* НЕТ потерянной записи (повторный вход показывает изменённое членство).

**Прогон 2026-08-28:** ✅ запись не потеряна (глазами); in-flight-окно руками не поймать — сценарный юнит `back while membership in flight` покрывает (вывод юзера: такое — только сценарными тестами reducer'а)
