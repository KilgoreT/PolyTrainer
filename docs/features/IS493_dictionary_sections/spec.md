## 1. Концепция

**Группа** — структурная единица словаря (подсловарь): выделяет часть слов
словаря. Это НЕ тег: группа — способ структурировать словарь, а не метка.
Группы образуют **дерево** внутри словаря; слово может состоять в нескольких
группах и всегда остаётся в главном словаре (группа ссылается на слово, не
владеет им).

**Закон трёх пластов.** Каждая колонка БД принадлежит ровно одному пласту:
структура (группы, membership) / контент (слова, лексемы, значения, схема
компонентов) / пользовательское состояние (прогресс, статистика, audit-даты).
Публикуются пласты 1–2; пласт 3 — никогда. Группы — пласт 1.

**Группы ≠ компоненты.** Компоненты (IS486) живут на **лексеме**, группы — на
**слове**. Модели не пересекаются.

**Тренировка по группе** (вне v1, модель поддерживает): группа тренируется со
всем своим поддеревом; contract — `resolveSubtreeWordIds`.

## 2. Термины

- **Группа** (`Group`) — узел дерева; «раздел» — синоним в обсуждениях, в
  коде и UI — только «группа».
- **Дерево** (`GroupTree`) — агрегат: все живые группы одного словаря.
- **Membership** — факт «слово привязано к узлу» (`word_groups`); привязка —
  к конкретному узлу любого уровня; членство в предках — производное.
- **Поддерево** — группа + все её потомки; единица удаления и тренировки.
- **«Все»** (`AllWords`) — единственная виртуальная группа (НЕ строка БД):
  первая на корне вкладки, содержит ВСЕ слова словаря (включая разложенные по
  группам). Имя — ресурс UI, локализуемо; kebab/действий нет. Концепт-правки
  2026-08-06: заменила «Не разобрано»; внутренних маркеров НЕТ (см. инвариант
  «папка или лист»).
- **Папка** — группа с подгруппами; слова в неё добавлять НЕЛЬЗЯ.
- **Лист** — группа со словами; подгруппы в ней создавать НЕЛЬЗЯ.
- **Пустая группа** — ни слов, ни подгрупп: обе дороги открыты, «тип»
  определяется первым действием и проверяется по текущему ЖИВОМУ содержимому.
- **Живая группа** — `removed_at IS NULL`.
- **DisplayTree** — дерево отображения: «Все» + группы + счётчики.

## 3. Модель данных

```
dictionary_groups
  id                PK autoincrement
  dictionary_id     FK → dictionaries.id  CASCADE, NOT NULL, INDEX
  parent_group_id   FK → dictionary_groups.id  CASCADE, NULL (null = корень), INDEX
  name              TEXT NOT NULL        -- хранится как введено (после trim)
  created_at / updated_at  NOT NULL      -- updated_at трогает только rename
  removed_at        NULL                 -- soft-delete (audit, не undo)

word_groups
  word_id           FK → words.id             CASCADE, NOT NULL
  group_id          FK → dictionary_groups.id CASCADE, NOT NULL, INDEX
  created_at        NOT NULL
  PRIMARY KEY (word_id, group_id)
```

- Поля `position` НЕТ: порядок сиблингов — алфавитный (В7), locale-aware
  компаратор в Kotlin (не SQLite NOCASE — кириллица). Rename может передвинуть
  узел в списке — принятая цена.
- `words` не меняется; слово остаётся в словаре через `words.dictionary_id`.
- Образец стиля entity — `ComponentTypeDb` (M13). Версия БД 12 → 13, только
  DDL (§11).

## 4. Инварианты

1. **Единство словаря:** родитель и ребёнок — из одного словаря; слово и
   группа в membership — из одного словаря.
2. **Ацикличность:** guard `createsCycle` (паттерн IS486) — задел под
   будущий reparent; в v1 недостижима ни одной операцией (у нового узла нет
   потомков, reparent вне скоупа) — обязательного вызова нет.
3. **Имя:** normalize = trim + NFC + locale-aware case-insensitive сравнение;
   хранится как введено. Непустое; уникально среди **живых** сиблингов
   (включая корневой уровень); резерв «Все» — по **всем локализациям**
   ресурса (набор строк инжектится в валидатор параметром — domain zero-deps).
   UNIQUE-индекса в БД нет (NULL parent + soft-delete): валидация — UseCase,
   паттерн M13. Та же normalize-функция — для будущего импорта.
4. **Liveness membership:** вставка в `word_groups` — только на живую группу
   (проверка в транзакции); все read'ы по `word_groups` JOIN'ят живые группы.
5. **«Папка или лист» (2026-08-06):** запрещено добавлять слово в группу с
   живыми подгруппами (`MembershipOutcome.GroupHasSubgroups`) и создавать
   подгруппу в группе с живыми словами (`CreateGroupOutcome.ParentHasWords`).
   Обе проверки — в транзакции мутации. UI дублирует запрет заранее (пикер:
   папки не выбираемы; kebab: «создать подгруппу» скрыт у листа). Будущий
   механизм конвертации листа в папку — отдельная фича, вне v1.
5. **Транзакционная граница:** каждая мутация = чтение актуального состояния →
   валидация → запись, целиком внутри `CoreDbApiImpl` одной
   `useWriterConnection { immediateTransaction }` (deferred не защищает —
   read-фаза без write-lock). `core-db-impl` зависит от `domain/group`; use
   case — тонкая делегация без валидаций. Конкурентность тестами не гоняется —
   покрывается последовательный путь (осознанное ограничение).

## 5. Операции

| Операция | Outcome | Примечания |
|---|---|---|
| `createGroup(dictId, parentId?, name)` | Success \| EmptyName \| DuplicateSibling \| ReservedName \| ParentNotFound \| ParentHasWords | ParentNotFound = отсутствует ∪ soft-deleted ∪ чужой словарь; ParentHasWords — инвариант §4.5 |
| `renameGroup(id, name)` | ошибки имени + NotFound | NotFound: группа удалена, пока диалог открыт |
| `deleteGroup(id)` | Success \| NotFound | поддерево пересчитывается по БД в транзакции |
| `setMembership(wordId, groupId, member)` | Success \| GroupNotFound \| WordNotFound \| GroupHasSubgroups | liveness-check + инвариант §4.5 в транзакции |

Чтение (Flow):

- `groupTree(dictId)` — живые группы.
- `membershipSlice(dictId)` — id-срез: пары (wordId, groupId) + id слов вне
  групп. Наблюдает **три** таблицы: `words`, `dictionary_groups`,
  `word_groups` (новое слово обязано переэмитить «Все» и счётчики).
- `wordsContent(ids)` — контент слов раскрытого узла (ленивая догрузка).
- `wordGroups(wordId)` — живые группы слова.
- `deleteImpact(id)` — N подгрупп + M слов (см. §10).
- `resolveSubtreeWordIds(groupId)` — задел тренировок (вне v1).

## 6. Дерево отображения

### 6.1 DisplayNode (ADT)

```
sealed DisplayNode
  Group(id, name, children: List<Group>, directWords: List<WordId>,
        subtreeWordCount: Int)                  // инвариант: children XOR directWords
  AllWords(words: List<WordId>, count: Int)     // «Все»; имя — ресурс UI
```

Правила сборки (`GroupTree + membershipSlice → DisplayTree`, чистая функция,
компаратор и reserved-набор — параметры):

- Корень вкладки → AllWords(все слова словаря) **первым**, затем корневые
  группы (О2). «Все» видна всегда (и в пустом словаре — с счётчиком 0).
- Папка → только подгруппы; лист → только слова напрямую (В2).
- Смешанных узлов не существует (инвариант §4.5); fail-soft: аномальный
  смешанный узел из БД рендерится как папка, его прямые слова скрыты.

### 6.2 Счётчики

- Группа: `subtreeWordCount` = distinct слов всего поддерева (В3) — семантика
  «сколько тренируется».
- «Все»: число слов словаря (Р6).
- Издержек нет: всё считается из membershipSlice, который вкладка и так грузит.

### 6.3 Сортировка и загрузка

- Сиблинги — алфавит, locale-aware (В7).
- Слова внутри группы и «Все» — в том же порядке, что на вкладке «Слова»
  (О1: единообразие виджета).
- Контент слов — **лениво**: DisplayTree несёт только WordId + счётчики;
  тексты/лексемы догружаются при раскрытии узла (`wordsContent`). Весь словарь
  в память не тянется (вкладка «Слова» не зря пагинируется).
- Отступ вложенности растёт до 4-го уровня, глубже не увеличивается (О7 —
  дерево любой глубины остаётся читаемым).
- Fail-soft: узел с битым parent-ref пропускается с поддеревом (прецедент —
  skip-row маппер).

## 7. Вкладки таба словаря

Нижний таб словаря = **3 модуля** (Р2): host `vocabulary` + `wordstab` +
`groupstab` (расщепление dictionaryTab; нейминг чинится: Vocabulary* = host).

- Host владеет: Scaffold, TabRow «Слова | Группы» (в верхе content, НЕ в
  topBar-слоте), явный `selectedTab`, snackbar, FAB, текущий словарь — host
  резолвит `dictionaryId` один раз и раздаёт вкладкам параметром слота.
- Контракт вкладки (через CompositionRoot в app): content-слот + FAB-действие.
- **FAB контекстный** (В4): «Слова» → добавить слово; «Группы» → создать
  корневую группу.
- **ActionMode — только у words** (Р2): на «Группах» отсутствует; переключение
  вкладки сбрасывает активный action mode (`Msg.ExitSelectionMode`).
- **Back** (В5): вкладки НЕ перехватывают «назад».
- «Слова» — существующий контент без изменений (переносится как есть, режется
  только Scaffold-обвязка).

## 8. Вкладка «Группы»

- **Аккордеон**: раскрытие на месте, корневые остаются видимы (Д2);
  expand-state — UI-state `Set<GroupId>`, устойчив к rename (ключ — id);
  живёт в сессии экрана, не персистится (дефолт).
- Строка группы: имя (ellipsis при переполнении, О5) + счётчик; действия —
  создать подгруппу (В4), rename, delete (Д4) — через **kebab-меню (⋮)** на
  строке; тап по строке — только раскрытие (О3). У «Все» ни действий, ни
  kebab НЕТ (виртуальная). «Создать подгруппу» скрыт у листа (инвариант §4.5).
- Строки слов — тем же виджетом item'а, что на «Словах» (В2), **read-only**:
  тап → карточка слова; снятие с группы здесь не делается (В6).
- Создание: FAB → корневая группа; действие на строке → подгруппа этой группы.
  Диалог — только имя; ошибки валидации (пустое/дубликат/резерв) показываются
  в диалоге, диалог остаётся открыт (дефолт). Выбора родителя из дерева на
  вкладке нет (В4).
- Empty-state'ы (Р12): нет групп вообще → empty-state + CTA создать; раскрытая
  группа без содержимого → строка-заглушка.
- Смена словаря: `selectedTab` сохраняется, дерево перегружается, expand-state
  сбрасывается (дефолт).
- Ошибки записи вне диалогов (упавший delete и т.п.) — snackbar с общим
  текстом; состояние откатывается само через Flow (О6).

## 9. Карточка слова

- **Шапка** (Д7): группы слова — **чипами, по алфавиту, с wrap** на новые
  строки (О4), в том же виджете, где слово, дата и флаг словаря; там же
  иконка → пикер. Источник — подписка на `wordGroups(wordId)` (новое поле
  state + Flow-handler по образцу `AvailableComponentTypesFlowHandler`).
- **Пикер** (Д6): всё дерево групп словаря (без «Все») с чекбоксами; отмечено
  = слово состоит. **Выбираемы только листья и пустые группы**; папки видны,
  но не выбираемы (инвариант §4.5). Тоггл → `setMembership` немедленно,
  без кнопки «сохранить».
- **Дизейбл на время записи** (Р3): per-membership — галочка с летящей записью
  дизейблится до завершения; остальные галочки живут. Состояние пикера — из
  Flow базы (ошибка записи → галочка сама вернётся; обновление дерева под
  открытым пикером — отражается).
- **Commit-контракт:** membership-записи — keyed in-flight в state карточки;
  flush-on-back ждёт их так же, как коммиты значений (`hasInFlightCommits`
  расширяется, `isGuardedByPending` учитывает).
- **Создание из пикера** (Д6): новая группа с выбором родителя из дерева
  (по умолчанию — корень); второй режим пикера.

## 10. Удаление и каскады

- **Удаление группы** (Д4/Д11): `deleteImpact` → конфирм «удалится N подгрупп,
  у M слов снимется группировка» → `deleteGroup`. Слова НЕ удаляются — только
  группировка.
  - M = `COUNT(DISTINCT word_id)` поддерева, исключая слова с членствами вне
    поддерева; внешние членства — только по живым группам (иначе недосчёт).
  - Механика: одна транзакция — поддерево запросом по БД → soft-delete узлов →
    hard-delete их строк `word_groups`.
  - TOCTOU принят: числа конфирма — ориентир; удаление всегда пересчитывает
    поддерево по факту.
  - Bind-лимит SQLite (999) покрыт границей «десятки узлов» — явное допущение.
- **Удаление слова** (Д5): FK CASCADE чистит `word_groups` — без кода.
- **Удаление словаря**: FK CASCADE сносит всё (группы — включая self-FK по
  дереву, прецедент `depends_on_type_id`).
- Soft-deleted строки `dictionary_groups` копятся — принято (низкая
  кардинальность, вакуум не нужен).

## 11. Миграция 12→13

Только DDL. CREATE TABLE буквально = экспорту `13.json`; составной PK —
новая форма DDL для проекта (в референсе только autoincrement) — выверять
руками; `IF NOT EXISTS` (defensive); имена индексов `index_<table>_<col>`.
Idempotency-тест для чистых CREATE — не обязателен.

## 12. Публикация (семантика зафиксирована, фича позже)

- **П1:** импорт — всегда в текущий словарь; каталог — изнутри словаря,
  фильтр по языку.
- **П2:** совпадение текста слова (trim + case-insensitive, Kotlin
  locale-aware) — сигнал для единого preview-ревью (per-word
  включить/исключить); отказ = слова из пакета нет нигде.
- **П3:** импортированное слово — всегда новая строка `words` (дубли легальны
  — подтверждено кодом); импорт — чисто аддитивная вставка; reuse/склейки нет.
- **Пакет:** поддерево (имена, без порядка) + membership + слова + лексемы +
  значения + подмножество схемы компонентов (builtin — по `system_key` типов
  И опций) + пара языков «изучаемый → перевод» (второй координаты в словаре
  сейчас нет — добавит фича публикации). Audit-колонки, «Все», user-state —
  не входят.
- **Требования к будущему импорту:** preview резолвит схему пакета виртуально
  (до вставки); политика disabled-builtin — решить в П6; версионный дрейф
  опций — П6.
- **Чек-лист v1** (полный — architecture §6.4): не вводить уникальность текста
  слова; уникальность имён групп — только UseCase; самодостаточность словаря;
  идентичность builtin — system_key; «Все» не в БД; язык словаря не
  терять; прогресс в пласте 3; UUID/provenance не вводить.

## 13. Вне скоупа v1

Тренировка по группе (Д9); reparent (Д12); фильтр по группе на «Словах»;
доп. поля группы (описание/цвет/иконка); снятие слова с группы на вкладке
«Группы» (В6); перенос слов между словарями; бейджи групп в списке «Слова»
(мотивация усилена дубль-моделью П3 — в бэклог); публикация целиком (П4–П6).
