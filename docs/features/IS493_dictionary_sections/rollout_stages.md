# IS493 — Этапы появления фичи для пользователя

## Принципы

- Фича раскатывается **юзер-видимыми этапами**.
- Каждый этап — законченная дельта поведения, проверяемая на девайсе.
- После каждого этапа: tests → build → lint → ручной чек-лист этапа.
- Следующий этап начинается только после проверки предыдущего.
- Порядок слоёв внутри этапа — по А16: данные → domain → виджет → host → вкладка → карточка.
- Основа: [spec.md](spec.md), [architecture.md](architecture.md) v3.

Концепт-правка (2026-08-04): корневая виртуальная группа называется **«Все»**
и содержит **все слова словаря**. Появляется на Э2, до всяких групп.

Концепт-правка (2026-08-23, решение пользователя): **вложенности в этой фиче
НЕТ**. Группы всегда корневые, одним уровнем, всегда листья (хранят слова).
Позже отдельной фичей появятся «папки» (контейнеры групп; вложенные или
одноуровневые — решения нет). Текущая фича оставляет задел: колонка `kind`
в схеме (Э4) и нетронутый `parent_group_id`. Прежние Э4 (дерево подгрупп)
и инвариант «папка или лист» из прежнего Э6 — удалены в пользу фичи папок.

Итого: **7 этапов** (Э1–Э3 сделаны).

## Э1. Две вкладки в словаре (заглушка «Групп»)

### Юзер видит

1. Над списком слов — вкладки «Слова | Группы».
2. «Слова» — всё как раньше:
   - список слов
   - поиск
   - ActionMode (выделение)
   - FAB «добавить слово»
3. «Группы» — заглушка (empty-state).
4. FAB на «Группах» скрыт.
5. «Назад» ведёт себя как обычно.

### Внутри

- Host-рефактор: 1 модуль → 3 (`vocabulary` host + `wordstab` + `groupstab`-заглушка).
- Контракт вкладки: content-слот + FAB-действие.
- `selectedTab` — явное поле state хоста.
- Сброс ActionMode при переключении вкладки.
- Нейминг: `Vocabulary*` = host.
- БД не трогается.

### Проверка

- [ ] Регрессия «Слов»: список, поиск, добавление, удаление.
- [ ] ActionMode работает только на «Словах».
- [ ] Переключение вкладок туда-сюда.
- [ ] Смена словаря.
- [ ] Back — обычное поведение.
- [ ] Поворот экрана — `selectedTab` переживает.

## Э2. Группа «Все» — аккордеон со всеми словами

### Юзер видит

1. На вкладке «Группы» — единственная группа **«Все»**:
   - виртуальная (создать/переименовать/удалить нельзя, kebab нет)
   - счётчик = число слов словаря
2. Тап по «Все» — раскрытие аккордеоном:
   - внутри все слова словаря
   - тем же виджетом строки, что на «Словах», в том же порядке
   - read-only: тап по слову открывает карточку
3. Повторный тап — сворачивание, слова скрыты.

### Внутри

Актуализировано по stage2-артефактам (решения В1–В5, 2026-08-10):

- Миграция 12→13: **обе таблицы сразу** (`dictionary_groups` + `word_groups`,
  составной PK) — пока пустые. Тест: изолированный + chained 11→13 + cascade
  (В4, без idempotency).
- `membershipSlice` (наблюдение трёх таблиц: `words`, `dictionary_groups`,
  `word_groups`; ORDER BY id DESC — глобальный порядок «Все»).
- `modules/domain/group` создаётся УЖЕ в Э2 **урезанным** (перенос из Э3):
  `DisplayNode` ADT + `buildDisplayTree` (дедуп wordId) + slice-тип границы;
  валидации/outcomes — Э3.
- `modules/widget/wordrow` (В1): вёрстка строки слова + entities выносятся
  из wordstab (переиспользование words + группы).
- Контент раскрытого узла: **живое окно** (v3, 2026-08-11) — предикатный
  live-запрос `LIMIT window`, кнопка «Ещё» расширяет окно на 50; вставки/
  правки/удаления переэмичиваются Room'ом сами (В2; Paging 3 не
  используется; чанк-снапшоты v2 заменены по итогам ручной проверки).
- Виджет `grouptree` (В5): `GroupNodeWidget` — только строка узла, без
  content-слота; аккордеон на LazyListScope groupstab.
- Host владеет dictionaryId (`DictionarySlot`, закрыт долг D1.6-частично)
  + host-VM на Dagger (закрыт долг D1.1); words словарь резолвит сам (В3).
- Expand-state и чанки — явные поля state groupstab.

### Проверка

- [ ] «Все» видна, счётчик совпадает с числом слов.
- [ ] Раскрытие / сворачивание.
- [ ] Слова — тот же виджет и порядок, что на «Словах».
- [ ] Тап по слову → карточка.
- [ ] Новое слово словаря появляется в раскрытой «Все» живьём (счётчик и
      список, без рестарта и пересворачивания — живое окно v3); правки
      лексем из карточки и удаления тоже отражаются сразу.
- [ ] Миграция на существующей базе (девайс с данными).
- [ ] Большой словарь: раскрытие грузит ≤50, дальше по кнопке «Ещё».

## Э3. Создание групп: корневой уровень

### Юзер видит

Актуализировано по stage3-артефактам (решения В1–В3, 2026-08-11):

1. FAB на «Группах» → ШТОРКА создания группы (В1: скрим прозрачный, при
   вводе список позади live-фильтруется — видно похожие/дубли; фильтр
   только при создании).
2. Список: «Все» первой, затем группы по алфавиту (Collator).
3. У новых групп счётчик «0»; раскрытие — заглушка «пусто».
4. Kebab (⋮) на строке группы (у «Все» — нет):
   - переименовать (та же шторка с предзаполнением)
   - удалить — ВСЕГДА с конфирмом (В2; текст импакта для непустых — Э4/Э6)
5. Ошибки — INLINE в шторке (не snackbar — правка A-H):
   - пустое имя
   - дубликат имени (case-insensitive, живые сиблинги)
   - зарезервированные имена виртуальных групп заняты (все локали)

### Внутри

- `domain/group`: валидации (`validateGroupName` → `Valid(normalized)`),
  outcomes с заделами Э4/Э6 (`ParentNotFound`/`ParentHasWords`),
  normalize (trim+NFC); резерв имён — конструкторная инъекция в data-слой
  (app собирает из ресурсов всех локалей).
- Транзакционные мутации в `CoreDbApiImpl` (`immediateTransaction`,
  read→validate→write; rename исключает self); dep
  `core-db-api → domain/group` (api).
- `groupTree` (живой Flow) + группы в DisplayTree
  (`combine(slice, groupTree)` + distinctUntilChanged).
- Handle-паттерн groupstab (FAB-читалки мосту), kebab через iconDropDowned.

### Проверка

- [ ] Создание / переименование / удаление корневой группы.
- [ ] Дубликат имени отклонён (case-insensitive: «Дом» vs «дом»).
- [ ] Резервные имена отклонены на обеих локалях.
- [ ] «Все» всегда первая, группы по алфавиту.
- [ ] Группы переживают перезапуск приложения.
- [ ] У «Все» нет kebab.

## Э4. Задел под папки: `kind` в схеме

Решение 2026-08-23: пока фича не зарелизена, тип узла фиксируется в схеме
ЯВНО — потом пришлось бы угадывать тип пустых узлов по живым данным.

### Юзер видит

Ничего — поведение не меняется.

### Внутри

- Колонка `kind TEXT NOT NULL DEFAULT 'GROUP'` в `dictionary_groups` —
  правкой СУЩЕСТВУЮЩЕЙ Migration_012_to_013 (версия БД остаётся 13:
  релиза не было, версию 13 никто снаружи не видел; концепт-правка
  2026-08-06 «все миграции этапов — в одной 12→13»).
- `GroupDb.kind` (String, default `GROUP`).
- В domain/API `kind` НЕ протягивается — до фичи папок это мёртвый
  параметр (у всех строк одно значение).
- `parent_group_id` остаётся в схеме нетронутым (ляжет под папки).
- Мёртвые заделы подгрупп (`ParentNotFound`/`ParentHasWords`, рекурсия
  `children` в buildDisplayTree) не развиваются и не удаляются — их
  судьбу решает фича папок.
- Дев-девайсы со старой схемой 13: чистка данных приложения /
  переустановка (schema mismatch; для незарелизенной фичи — норм).

### Проверка

- [ ] MigrationFrom12to13: колонка `kind` есть, дефолт `GROUP`.
- [ ] Chained 11→13 зелёный.
- [ ] Регресс androidTest data-слоя (мутации групп) зелёный.

## Э5. Слова попадают в группы (пикер + чипы)

### Юзер видит

1. В шапке карточки слова — иконка групп.
2. Тап по иконке → пикер:
   - плоский список групп словаря с чекбоксами (без «Все»; папок нет)
   - отметил = слово в группе
3. Чипы с именами групп в шапке:
   - по алфавиту
   - wrap на новые строки
4. Галочка на время записи дизейблится.
5. На вкладке «Группы»:
   - счётчики групп ожили (distinct слов группы)
   - раскрытие группы показывает её слова (вместо «пусто»)
   - слово остаётся и в «Все»

### Внутри

- `addWordToGroup`/`removeWordFromGroup` + liveness/JOIN-check (пара
  вместо setMembership — ревью Arch-4, синк architecture §2.5).
- `wordGroups(wordId)`: Flow-handler + поле state карточки.
- Пикер: режим чекбоксов (без создания групп).
- Keyed in-flight + flush-on-back.
- Счётчики и слова групп из `membershipSlice` + `wordsContent`.

### Проверка

- [ ] Добавление / снятие слова из нескольких групп.
- [ ] Чипы обновляются сразу.
- [ ] Спам по галочке — дизейбл работает.
- [ ] Выход из карточки во время записи — запись не теряется (flush-on-back).
- [ ] Удаление слова чистит членства (каскад) и все счётчики.
- [ ] Слово видно и в группе, и в «Все».

## Э6. Импакт удаления + «удалить вместе со словами»

Переформулирован решением юзера 2026-08-28 (вместо математики
«единственная группа» — простое число слов + деструктивная опция).

### Юзер видит

1. Конфирм удаления группы с ≥1 словом: «В группе слов: N. При удалении
   группы они останутся в словаре» + галка «Удалить вместе со словами».
2. Галка отмечена → подпись меняется («С группой будут удалены слова:
   N»), кнопка становится ДЕСТРУКТИВНОЙ «Удалить всё»
   (насыщенно-красная) и на 5 секунд дизейблится со счётчиком В
   НАЗВАНИИ («Удалить всё (5)»… — пауза осмысления; финал 2026-08-28:
   ЕДИНЫЙ диалог, второй переспрос упразднён — его роль у счётчика).
3. Счётчик оттикал → активная «Удалить всё», один тап — деструктив.
4. Пустая группа — прежний конфирм без текста и галки.

### Внутри

- N — живой счётчик группы из state (запросов при открытии нет).
- `deleteGroupWithWords`: одна транзакция — samples-легаси → hard-delete
  слов чанками (FK CASCADE: лексемы/значения/квизы/membership всех
  групп) → удаление группы.
- Двухстадийный `ConfirmDeleteState` (галка no-op при открытом
  переспросе; галка игнорируется при count=0; конфирм мёртвой группы
  закрывается slice'ом).

### Проверка

- [x] Текст при N, смена подписи галкой, чистая галка при переоткрытии.
- [x] Негативный контроль: без галки слова живы (androidTest + M17).
- [x] Отмена переспроса — ничего не удалено.
- [x] Деструктив: слова исчезают из «Все» и других групп (M19).

- Переиспользование `createGroup`.
- Обновление списка под открытым пикером (state из Flow).

### Проверка

- [ ] Создание из карточки.
- [ ] Группа видна на вкладке «Группы».
- [ ] Слово уже состоит в созданной группе.
- [ ] Валидация имён работает и в пикере.

## Вне скоупа v1 (spec §13 + правка 2026-08-23)

- **Папки (контейнеры групп) и любая вложенность** — отдельная будущая
  фича (вложенные или одноуровневые — решений нет).
- Тренировка по группе.
- Reparent (перемещение группы).
- Фильтр по группе на «Словах».
- Снятие слова с группы на вкладке «Группы».
- Бейджи групп в списке «Слова».
- Публикация (П4–П6).
