# IS540 | Анализ: почему не приходит род и как чинить

## Симптом

- Словарь «Mexico», es → ru, с компонентом «Род»: испанские
  существительные приходят с пустым «Родом» — и со снимка, и из
  карточки слова.
- Изредка род стоит: 31 октября у área все три значения пришли с
  «ж.р.». Это нейронка поставила сама, без записи.

## Причина

1. **В выгрузке род есть.** В `ruwiktionary-es.jsonl` (kaikki, дамп
   2026-10-01) род существительного лежит в категориях статьи:
   «Мужской род/es», «Женский род/es», «Общий род/es». В тегах значений
   и в тегах статьи его нет.
2. **Импорт его не читает.** `grammarOf` в
   `internal/clients/converters/kaikki_rules.go` берёт род только из
   тегов значения: `genderOf(tagSet(sense.Tags))`. Категории статьи
   читает только `irregularOf` — ради «неправильных глаголов».
3. **В базе рода нет.** У лексем русского Викисловаря грамматика
   пустая, в ответе `grammar: {}`.
4. **Нейронке нечего ставить.** В промпт значение уходит с метками
   записи без рода. По инструкции v22 «Выбор» заполняется только из
   записи — «Род» пуст.
5. **Иногда род всё же приходит.** Нейронка изредка нарушает правило и
   ставит род из своих знаний, как у área. Отсюда «то есть, то нет».

## Откуда регресс

- **IS536 Д1, 2026-10-15.** Род из словаря — в компонент «Род». Тогда
  значения шли и из английского Викисловаря, где род лежит в тегах
  значений, и импорт его брал.
- **IS536 Д63, 2026-10-22.** Значения только из Викисловаря языка
  перевода. Для es → ru остался русский — и род пропал.
- **Журнал промпта Ж-28, 2026-10-28.** Записано «в записи Русского
  Викисловаря рода нет» — верно про запись базы, но не про выгрузку.
  Пробы v19…v21 с родом из знаний сняты: модель давала род русского
  перевода, banco «скамья» → ж.р.

## Почему тесты не поймали

Фикстуры `testdata/kaikki/*.jsonl` срезаны скриптом
`scripts/kaikki-fixtures.pl` до полей, которые импорт переносит. Из
категорий оставлены только phrasal verbs и неправильные глаголы, поэтому
категорий рода в фикстурах нет.

## Чего это не касается

- **Кеш.** Запросы со снимка кеш отбора не читают и не пишут (LFL-94.3).
  В ключе кеша карточки слова дерево компонентов есть (LFL-94.2).
- **Приложение.** Экраны и контракт не меняются: род приходит обычным
  сопоставлением в компонент.

## Направления фикса и что выбрано

- **Род из категории статьи при импорте — принято (Д2).** Без других
  источников даёт род 80 значениям из 100.
- **Род из других словарей — принято в виде схемы (Д4, Д5).** Вместо
  одной добавки из английского издания данные всех словарей хранятся по
  источникам и сводятся в сборку слова по правилам. Род — свойство слова,
  поэтому значения разных словарей для этого не сопоставляются.
- **Род из знаний нейронки — отвергнуто (Д3).** Нейронка обрабатывает
  информацию, а не порождает её.
- **Род по окончанию -o и -a — отвергнуто (Д3).** Надёжные суффиксы
  вроде -ción и -dad остаются только проверкой (Д5).

## Механизмы и замеры

Подробно, с точностью каждого механизма, — `sources.md`. Итог по 12835
значениям испанских существительных русского издания без имён
собственных, по правилам Д5 и Д6, без ручной правки:

| Итог | Значений |
|---|---|
| с родом | 12464, это 97,1 из 100 |
| из них общего рода, ставится «м.р.» | 210 |
| пустых из-за спора | 62 |
| пустых, рода нет ни в одном источнике | 309 |

- **Свой род статьи проверяется.** Если он расходится с согласием
  других словарей, с суффиксом или с мостом через переводы, «Род»
  пустой. Так ошибка русского издания у «мед. кома» даёт пустой род, а не
  неверный женский.
- **Омонимы.** Если хоть один словарь даёт у написания разный род, род по
  написанию ставится только при голосе не меньше двух словарей.

## Что придётся сделать

- **Данные источников.** Данные каждого словаря хранятся отдельно,
  значение узнаётся по идентификатору kaikki, а не по позиции. Новая
  выгрузка сравнивается со старой по идентификаторам и отпечатку текста.
  У испанского Викисловаря и FreeLing идентификаторов значений нет, их
  данные сравниваются по написанию.
- **Сборка слова.** Пересобирается целиком, когда меняются данные хоть
  одного источника слова. У каждого параметра записаны источник и правило
  (Д8).
- **Новые конвертеры.** Испанский Викисловарь — род в заголовке части
  речи «Sustantivo masculino». FreeLing — род в теге формы. Русский
  Викисловарь — род из категорий статьи (Д2).
- **Пересборка.** Сборщик сверяет только дату выгрузки, а `importer`,
  записанный у источника, не сверяет. Версия импорта должна запускать
  пересборку данных источника.
- **Защита от битой выгрузки.** Если пропало больше 5% слов, выгрузка не
  применяется. Порог — допущение.
- **Ключ слова.** Регистр сохраняется, ударения не снимаются, варианты
  написания вроде sólo и solo пока не сводятся.
- **Выдача.** Лемму по тапу выбирает текст (Д11). Слово без статьи в
  русском издании берёт английский текст в «Перевод» с пометкой «англ.»
  и в «Толкование», если оно есть (Д9, Д10). Опцию «Выбора» нейронка
  ставит только по данным значения, сервер это не проверяет: что
  компонент пользователя — это род, он не знает (Д14).
- **Рекомендации компонентов снимаются.** Из инструкции нейронки уходит
  правило рекомендаций, тезис LFL-89 отменён, вместо него LFL-126 (Д13).
- **Данные FreeLing — отдельным файлом** (Д12).
- **Ключ лексемы в ответе прежний.** Он позиционный, вида
  `ruwiktionary/1.noun.1`, и считается при выдаче. Идентификатор
  источника живёт только в базе (Д8).
- **Фикстуры и тесты.** `kaikki-fixtures.pl` оставляет категории рода.
  Тесты на каждое правило рода, на дифф данных источников и на защиту от
  битой выгрузки.
- **Спека базы слов WDB** — новая, отдельно от спеки значений по лемме
  (Д15), тезисы WDB-01…WDB-28: выгрузки, разбор и род из каждого
  источника, изменения по идентификаторам, сборка, правила рода,
  выдача, битая выгрузка, версия импорта, отключение источника.
- **Спеки.** Спека значений по лемме получает версию v3:
  - флоу и «Стороны» под решения, род в Ш4 — ссылкой на WDB;
  - новые тезисы: английские значения LFL-124 и LFL-125, без
    рекомендаций LFL-126;
  - правки LFL-71, 73, 75, 81, 85, 87, 91, 97, 102, 108;
  - LFL-69 и LFL-89 отменены;
  - ключи лексем в примерах прежние (Д8).
- **Контракт.** Ветки 2.4, 2.5, 2.6, 5.3, 6.2 и 6.4: английские значения
  и у es → ru, `recommendations` всегда пуст, опция «Выбора» только по
  данным значения.
- **Глоссарий.** «Источник» и «База слов». Спека журнала RUN и экранные
  спеки приложения не меняются.
- **Проверка до деплоя.** Копия базы прода пересобирается, `lexeme probe
  llm` гоняет perro, montaña, área, abadía, coma, dentista и teporingo; у
  «мед. кома» «Род» должен прийти пустым.

## Допущения

Решения без вопроса юзеру, меняются одним словом:

- **Карточка без текста.** Пустая русская статья считается отсутствующей.
  Леммы только с английскими значениями выпадают, если у слова есть
  русские.
- **Порядок по тапу.** Если у леммы из текста нет русских значений, сначала
  поиск по связям «форма → лемма» за русскими, потом английский текст.
- **Термин.** «Данные источника», а не «снимок»: «Снимок» в глоссарии —
  фото.
- **Атрибуция.** Не меняется до решения по лицензии перед выходом в
  продукт.
- **Порог битой выгрузки** — 5%.
- **Варианты написания** вроде sólo и solo в фикс не входят.

## HLD

HLD не делаем (Д16). Устройство базы слов описывает спека WDB,
`backend/docs/handbook/specs/word-base/spec.md` (Д15). База целиком
пересобирается из выгрузок, поэтому ошибка в устройстве стоит
пересборки, а не данных. Контракт и приложение не трогаются.

## План этапов

Код бэкенда, `~/dev/lexeme`. Независимые этапы — первыми. Каждый этап:
тесты по адресам строк спек (TDD), линт, `go test`, затем следующий.
Тег и выкатка — после Э7, пачкой.

Как ложится на нынешнюю базу:

- **Данные источников** уже лежат в записи слова: у каждого элемента
  метка источника, импорт заменяет элементы своего источника целиком.
  Отдельное хранилище не нужно.
- **Сборка** — выведенные параметры на лексемах той же записи: род с
  источником, правилом и причиной спора. Собственный род источника
  остаётся в его данных, выведенный лежит рядом.
- **«Грязные» слова** — отдельная корзина в bbolt: слова, у которых
  изменились данные хоть одного источника. Сборка их разбирает и
  вычищает, после перезапуска продолжает с того же места (WDB-13.4).

### Э1. Род статьи Русского Викисловаря и версия импорта
- Конвертер читает категории «Мужской / Женский / Общий род/es» статьи,
  род ложится на лексемы-существительные статьи, две категории — общий.
- Версия импорта хранится у выгрузки и сверяется вместе с датой: новая
  версия — разбор уже скачанной выгрузки заново.
- `scripts/kaikki-fixtures.pl` оставляет категории рода.
- Тезисы: WDB-04, WDB-27.

### Э2. Форма и инструкция нейронки
- Английская строка значения ложится, как любая, в первое включённое
  ядро и в «Толкование», если оно есть (Д17).
- «Выбор» — только по данным значения.
- Рекомендаций в форме и инструкции нет, проверка их отбрасывает,
  `recommendations: []`.
- Инструкция — файлом на сервере, до тега `lexeme probe llm` на копии
  базы прода: perro, montaña, área, abadía, coma, dentista, teporingo.
- Тезисы: LFL-85, LFL-87, LFL-91, LFL-97, LFL-125, LFL-126, LFL-129.

### Э3. Новые источники
- Испанский Викисловарь: выгрузка, конвертер, род из заголовка части
  речи, значения — лексемы с источником `eswiktionary`.
- FreeLing: файл у сервера отдельно от кода, формы единственного числа
  и неизменяемые с родом по третьей букве тега.
- Настройка источников: не назван — включён, отключён — данные удалены.
- Тезисы: WDB-02, WDB-05, WDB-07, WDB-28.

### Э4. Изменения и битая выгрузка
- Отпечаток значения — текст, теги, переводы, примеры и род статьи.
  Сравнение по идентификатору или, без него, по слову целиком. Слово с
  изменениями — в «грязные».
- Подсчёт слов выгрузки до применения: пропало больше 5% — выгрузка не
  применяется, в логе числа, заново не качается.
- Неразобранная строка слово не удаляет. Загрузка дольше суток
  обрывается.
- Тезисы: WDB-01, WDB-08…WDB-12, WDB-26, WDB-29, WDB-30.

### Э5. Сборка и правила рода
- Сборка «грязных» слов целиком: род лексемы из её источника, голос
  других источников, общий — мужской, проверка суффиксом и мостом, род
  только у существительных, источник, правило и причина спора.
- Голос и мост — как в `research/gender_mechanisms.pl` (Д18). Указатель
  «английское слово → испанские слова моста» для пересборки по мосту.
- Сверка: сборка на копии базы прода против замера, около 97 из 100
  значений с родом.
- Тезисы: WDB-13…WDB-23, WDB-31.

### Э6. Выдача LFL
- Грамматика лексемы-кандидата — из сборки, ключ прежний позиционный.
- Слово без лексем на языке перевода берёт английские значения: по тапу
  — сама лемма, из карточки — его леммы. Свой Викисловарь — только
  Русский у ru и английский у en.
- Ключ кеша отбора несёт версию сборки слова: после пересборки старый
  отбор не читается.
- Тезисы: LFL-73, LFL-81, LFL-94, LFL-102, LFL-108, LFL-124, WDB-24,
  WDB-25.

### Э7. Контракт и выкатка
- Описания в `api/openapi.yaml`, кейсы `control_set.md`, CHANGELOG,
  статусы тезисов по покрытию.
- Сервер: файл FreeLing, место на диске — база около 8 ГБ, новая версия
  импорта пересобирает базу. Тег — патч.
- Ручники на телефоне в словаре «Mexico»: montaña — «ж.р.», dentista —
  «м.р.», teporingo — «Перевод» с «англ.».

Технические допущения, меняются одним словом:

- Сборка лежит на лексемах записи, а не в отдельной корзине.
- Испанский Викисловарь — из сырой выгрузки kaikki испанского издания,
  только статьи `lang_code: es`.
- Версия сборки в ключе кеша — отпечаток сборки слова.
