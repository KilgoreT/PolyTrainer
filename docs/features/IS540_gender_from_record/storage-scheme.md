# IS540 | Схема хранения словарных данных: данные источников и сборка

Как собрать в одну базу данные всех словарей, обновлять и удалять их по
источникам и брать параметры вроде рода из любого источника так, чтобы
при обновлениях ничего не терялось и не уезжало на чужое значение.

> [!NOTE]
> Устройство базы — спека WDB, `backend/docs/handbook/specs/word-base/spec.md`.
> Здесь — разбор с примерами и замерами.

## Зачем

- **Один ответ из многих словарей.** Русский, английский и испанский
  Викисловари, FreeLing, позже другие — значения и параметры из всех, у
  каждого параметра свой источник.
- **Обновления без потерь.** Новая выгрузка меняет только то, что в ней
  изменилось. Параметр из другого словаря не стирается и не переезжает на
  чужое значение.
- **Удаления видны.** Пропавшее из источника уходит из базы.
- **Новый язык без новой схемы.** Добавляются данные нового словаря и
  правила для его параметров.

## Термины

- **Источник** — один словарь: `ruwiktionary`, `enwiktionary`,
  `eswiktionary`, `freeling`.
- **Данные источника** — данные одного источника по одному слову в том
  виде, в каком источник их отдал.
- **Идентификатор значения** — ключ значения внутри источника, не
  зависящий от его места в статье: `ru-planta-es-noun-tUMGFdUV`.
- **Сборка** — то, что видит выдача: слово и все его лексемы из всех
  источников с параметрами.
- **Ключ слова** — язык и написание: `es:planta`.

## Две части коротко

1. **Данные источников** — сырые данные, по источнику отдельно. Меняются
   только импортом выгрузки.
2. **Сборка** — выводится из данных источников. Руками не правится, по
   кускам не сливается: слово пересобирается целиком.

## Данные источников

У каждого источника свои данные на слово. Внутри — статьи (омонимы) с
частью речи, в статьях — значения. Параметр лежит на том уровне, где его
дал источник, и помнит, откуда взят:

- **Статья** — род из категории «Женский род/es» русского Викисловаря,
  из заголовка «coma f» английского или из заголовка «Sustantivo
  masculino» испанского.
- **Значение** — род из тега значения английского Викисловаря.
- **Написание** — род из FreeLing: у него нет ни статей, ни значений,
  только формы с тегами.

Значение узнаётся по идентификатору источника, а не по номеру позиции,
если у источника идентификаторы есть.

> [!NOTE]
> У русского и английского Викисловарей идентификаторы значений даёт
> выгрузка kaikki: `ru-perro-es-noun-pTPNsb3b`. Правило, по которому
> считается хвост, wiktextract не документирует. Проверено на деле: все
> 99 идентификаторов из тестовых строк, снятых с выгрузки начала октября
> 2026, нашлись в выгрузке от 30 октября. У испанского Викисловаря
> идентификаторов значений нет: его данные сравниваются по написанию и
> заголовку статьи, «planta» и «Sustantivo femenino». У FreeLing
> идентификаторов тоже нет: он даёт только формы и род, поэтому его
> данные сравниваются по написанию.

### Пример: FreeLing, abadía и coma

```json
{ "source": "freeling", "language": "es", "word": "abadía",
  "forms": [ { "form": "abadía", "tag": "NCFS000", "gender": "feminine" } ] }

{ "source": "freeling", "language": "es", "word": "coma",
  "forms": [ { "form": "coma", "tag": "NCCS000", "gender": "both" } ] }
```

Тег NCCS у FreeLing значит «мужской или женский» и склеивает настоящий
общий род, как у turista, с омонимами, как у coma. Поэтому both из
FreeLing в правилах не считается. Данные из FreeLing лежат отдельным
файлом: они идут под AGPL, и при нужде их можно опубликовать отдельно от
кода сервера.

## Сборка

Сборка на ключ слова — все лексемы всех источников. У каждого параметра
лексемы записаны значение, источник и правило, по которому он взят.
Сборка выводится только из данных источников. Если у слова изменились
данные хоть одного источника, слово пересобирается целиком, поэтому чужой
параметр каждый раз выводится заново из свежих данных: стереться или
уехать ему не из чего.

### Правила рода, по порядку

1. **Род значения** в источнике лексемы — тег значения.
2. **Род статьи** в источнике лексемы — категория или заголовок.
3. **Согласие других источников** — все источники, которые знают
   написание существительным, дают ему один род на все статьи. both из
   FreeLing не считается.
4. **Конкретный сильнее общего** — одни источники дают общий род, все
   остальные один и тот же конкретный, как у adversario.
5. **Большинство** — два источника против одного.
6. **Иначе пусто.**

Ограничения и проверки:

- **Омонимы.** Если хоть один источник даёт у написания разный род, род по
  написанию ставится только при голосе не меньше двух источников.
- **Общий род** — «м.р.» по умолчанию, как у dentista и mar.
- **Проверки.** Суффиксы -ción, -sión, -xión, -dad, -tad, -tud, -umbre
  дают женский, -ismo, -aje, -miento — мужской. Мост через переводы
  связывает значение русского издания со статьёй английского через
  русские переводы английского слова в русском Викисловаре. Если
  итоговый род, в том числе род статьи, расходится с голосом других
  источников, с суффиксом или с мостом, «Род» пустой.

### Пример: coma — проверка ловит ошибку источника

Обе русские лексемы получают женский род статьи. Голос других источников
молчит: английское издание даёт у coma и мужской, и женский. Проверка
мостом идёт через английское слово coma. В русском Викисловаре у него
есть переводы «мед. кома» и «астрон. кома», а в английском издании
испанское coma с таким переводом есть только у статьи «coma (deep
sleep)» мужского рода. Мост даёт мужской род обеим лексемам, это
расходится с родом статьи, поэтому у обеих «Род» пустой:

```json
{
  "key": "es:coma",
  "lexemes": [
    { "id": "ru-coma-es-noun-4CUKDFHz", "source": "ruwiktionary", "lang": "ru", "pos": "noun",
      "text": "мед. кома",
      "gender": null,
      "genderDispute": "род статьи женский, мост через переводы — мужской" },
    { "id": "ru-coma-es-noun-peCtcfOm", "source": "ruwiktionary", "lang": "ru", "pos": "noun",
      "text": "астрон. кома (газовое и пылевое облако, окружающее ядро кометы)",
      "gender": null,
      "genderDispute": "род статьи женский, мост через переводы — мужской" }
  ]
}
```

Для «мед. кома» проверка спасает от неверного женского рода. У «астрон.
кома» теряется верный женский: мост грубый, он связывает слова, а не
значения. Пустой род здесь лучше неверного.

Причину спора сборка хранит рядом с пустым родом, чтобы было видно, почему
род не поставлен.

## Обновление источника

1. **Скачать** выгрузку, если на сайте вышла новее.
2. **Собрать новые данные** этого источника.
3. **Сравнить** новые данные со старыми по идентификаторам значений: что
   добавлено, что пропало, что изменилось.
4. **Применить** изменения к данным источника.
5. **Пересобрать** только слова с изменениями.

### Пример: в статье добавили значение

Сейчас у perro в русском издании три значения:
`ru-perro-es-noun-pTPNsb3b` «собака; пёс», `ru-perro-es-noun-s~kDL5Z2`
«надувательство, обман», `ru-perro-es-adj-L6WvOBOP` «дурной, скверный».
Пусть редактор вставит между первыми двумя «собака-поводырь»:

```text
perro, ruwiktionary:
  + ru-perro-es-noun-Qk2mZr7p  «собака-поводырь»   (новое)
    ru-perro-es-noun-pTPNsb3b  «собака; пёс»       (без изменений)
    ru-perro-es-noun-s~kDL5Z2  «надувательство…»  (без изменений)
    ru-perro-es-adj-L6WvOBOP   «дурной, скверный» (без изменений)
```

При позиционном ключе вида `ruwiktionary/1.noun.2` «надувательство»
стало бы `1.noun.3`, и всё, что на нём висело, уехало бы на
«собаку-поводыря». По идентификаторам сдвига нет. Идентификатор
`Qk2mZr7p` выдуман для примера.

### Изменился текст значения

Неизвестно, меняет ли kaikki идентификатор при правке текста. Поэтому у
значения в данных источника хранится ещё и отпечаток текста:

- **Тот же идентификатор, другой отпечаток** — значение изменено, данные
  обновляются.
- **Старого идентификатора нет, есть новый** — значение удалено и
  добавлено новое.

В обоих случаях слово пересобирается, и параметры выводятся заново.

### Защита от битой выгрузки

Если в новой выгрузке пропало больше 5% слов, она не применяется:

```text
ruwiktionary-es: было 16276 испанских слов, в новой выгрузке 8100,
пропало 50%, порог 5% — выгрузка не применена, нужна проверка.
```

Порог 5% — допущение, меняется одним словом.

### Смена правил импорта

Правила импорта меняются, когда мы начинаем читать что-то новое, как род
из категорий. У данных источника записана версия импорта:

```text
ruwiktionary-es: данные собраны импортом 1, текущий импорт 2 — данные
пересобираются из той же выгрузки, дифф показывает изменённый род у 7779
существительных, пересобираются только эти слова.
```

## Удаление

- **Значение пропало из источника** — уходит из данных источника, лексема
  уходит из сборки.
- **Слово пропало из источника** — уходят данные этого источника по
  слову. Нет данных ни одного источника — слова нет в сборке.
- **Источник отключён** — уходят все его данные, слова пересобираются без
  него.
- **Словарь юзера на телефоне не трогается.** Приложение хранит свою
  копию лексем, удаление в источнике её не меняет.

## Ключ слова

Ключ — язык и написание с регистром, как сейчас: Málaga — город, málaga —
вино, это разные слова.

> [!WARNING]
> Ударения не снимаются. té — «чай», te — «тебя», sí — «да», si — «если»,
> más — «больше», mas — «но»: это разные слова.

Варианты написания одного слова пока не сводятся. На фото «habitan sólo
en esta región» лемма sólo, а в словарях — solo, поэтому сервер отвечает
«Не найдено».

## Выдача

1. **Ключ слова** из запроса — сборка этого слова. По тапу лемму выбирает
   текст снимка: fuera в «si yo fuera» — это ser.
2. **Лексемы пары языков** — для испано-русского словаря значения с
   русским текстом. Если у леммы русских значений нет, сначала поиск по
   связям «форма → лемма», потом значения английского издания.
3. **Отбор** — нейронка выбирает по тексту или самые употребительные и
   раскладывает по компонентам, ничего не добавляя от себя: «Род» ставит
   только по роду в данных. Английский текст ложится в «Перевод» с
   пометкой «англ.» и в «Толкование», если оно есть в словаре.
4. **Ответ** — в том же виде, что сейчас. Источник параметра остаётся в
   сборке.

### Пример: planta

Словарь es → ru, лемма planta, текст «…especies de animales y plantas…».
Сборка `es:planta` даёт три русских значения с женским родом из статьи.
Нейронка ставит первым «растение» — оно в тексте:

```json
{ "translations": ["растение"], "inContext": true,
  "grammar": { "gender": "feminine" } }
```

### Пример: teporingo — слова нет в русском издании

В русском Викисловаре teporingo нет, в английском есть
`en-teporingo-es-noun-3FulwvMu` «volcano rabbit» с заголовком
«teporingo m». В словаре «Mexico» на телефоне значение придёт так:
«Перевод: volcano rabbit» с пометкой «англ.», «Род: м.р.».

### Пример: рода нет в данных

У «мед. кома» (coma) рода в сборке нет: мост через переводы спорит с
категорией статьи. Нейронка «Род» не ставит, и на телефоне он пустой.
Если она всё же поставит «м.р.», сервер это пропустит: «Род» — компонент
пользователя без ключа, и сервер не знает, что это род. Такое ловит
только контрольный набор.

Выдача «все значения» позже покажет все лексемы сборки. Одинаковые смыслы
из разных словарей не склеены: «растение» и «plant» придут двумя
лексемами, каждая со своим источником.

## Что получается

По замерам на 12835 значениях испанских существительных русского
издания без имён собственных:

| Итог | Значений |
|---|---|
| с родом | 12464, это 97,1 из 100 |
| из них общего рода, ставится «м.р.» | 210 |
| пустых из-за спора | 62 |
| пустых, рода нет ни в одном источнике | 309 |

## Что схема не решает

- **Русских значений мало.** Испанских слов в русском издании около 16
  тысяч, испанских лемм в английском — около 113 тысяч. Для остальных
  будет английский текст с пометкой «англ.», а не русский перевод.
- **Значения разных словарей не сопоставляются.** Мост через переводы
  только проверяет род, значения он не склеивает.
- **Ошибки словарей не исправляются.** Если ошибку ловит проверка, род
  становится пустым, а не верным.
- **Слова, которых нет ни в одном источнике,** остаются без рода.

## Цена

| Что | Сейчас | По схеме |
|---|---|---|
| база на сервере | 3,7 ГБ | около 8 ГБ |
| свободно на диске | 36 ГБ | около 32 ГБ |

- **Сложность.** Две части вместо одной записи, дифф по идентификаторам,
  правила сборки и проверки.
- **Ключ лексемы в ответе прежний.** Он позиционный, вида
  `ruwiktionary/1.noun.1`, и считается при выдаче из сборки.
  Идентификатор источника живёт только в базе, ответ сервера не
  меняется (Д8).
- **Новые конвертеры.** Испанский Викисловарь и FreeLing, у каждого свой.

## Как это ложится на нынешнюю базу

- **Запись слова уже собирает все источники.** Сейчас это данные всех
  источников, сложенные в одну запись. Их можно разложить по источникам
  без потери данных.
- **Обновление сейчас грубее.** Импорт удаляет из записи все элементы
  источника и дописывает новые, поэтому чужой параметр внутри лексемы не
  выживает.
- **Версия импорта уже хранится.** Поле `importer` есть у каждого
  источника в записи, но сборщик его пока не сверяет.
- **Часть сборки уже идёт при поиске.** Выбор издания по языку перевода
  делается на лету.
