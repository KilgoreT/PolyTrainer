# IS491 — юзеркейсы (пошаговые, с лог-контрактом)

Сценарии шаблона «Текст с подписью» (`captioned_text`) и builtin «Пример».
Формат каждого UC: Подготовка → Шаги → Проверка. У шага: действие, `UI:` ожидание
на экране, ожидаемые строки logcat — с новой строки, отдельным блоком.
По этим UC собирается ручной девайс-чек-лист (фаза 4 плана).

## Политика данных

UC выполняются последовательно, данные копятся. Но каждый UC, проверяющий
**точный счётчик** подсказок (UC4, UC10–UC12), получает в подготовке
**свежесозданный компонент** — его счётчики абсолютны и не зависят от истории.
UC на «Цитате» (UC2–UC8) — инкрементальны, счётчики выводятся из предыдущих шагов.

## Плейсхолдеры в логах

`<id>` (dictId/typeId/valueId) и `<n>` (text.len, число словарей) — конкретные
значения НЕ предвычисляются: проверяется факт появления строки и согласованность
полей между строками (один и тот же valueId в add → update → remove; typeId
соответствует компоненту, с которым работаешь — сверяется по контексту действия,
а не по имени). `count=<n>` в suggestions — число пунктов списка, оно в UC задано
точно там, где компонент свежий.

## Лог-контракт

Фичевый тег: **`###CAPTIONED_TEXT###`** — капсом, по конвенции `LogTags`
(все теги проекта капсом: `###APP###`, `###WORDCARD###`, `###DICT_COMPONENTS###`…).

Фильтр:

```
adb logcat | grep '###CAPTIONED_TEXT###'
```

Логи — часть реализации фичи (см. план, пункты «лог-контракт»):

| Событие | Строка лога |
|---|---|
| seed нового словаря | `###CAPTIONED_TEXT### seed: example dictId=<id>` |
| загрузка подсказок | `###CAPTIONED_TEXT### suggestions: typeId=<id> count=<n>` (n = число пунктов списка) |
| добавление значения | `###CAPTIONED_TEXT### value add: typeId=<id> valueId=<id> text.len=<n> caption='<c>'` (caption='null' если пуст) |
| обновление значения | `###CAPTIONED_TEXT### value update: valueId=<id> text.len=<n> caption='<c>'` |
| удаление значения | `###CAPTIONED_TEXT### value remove: valueId=<id>` |
| пикер квиза | `###CAPTIONED_TEXT### quizPicker: available=[<display-имена>]` |
| ошибки парсинга envelope | существующий тег `TemplateValuesJson` — non-manual: руками без порчи БД не воспроизводится, в ручной чек-лист не входит |

Базовая подготовка (для всех UC, если не сказано иное): словарь `ES`, 2–3 слова,
у каждого лексема с заполненным переводом (оформлена).

## Кастомный компонент на шаблоне

### UC1. Создание кастомного компонента

Подготовка: базовая.

Шаги:

1. Конструктор словаря `ES` → «создать компонент».
   UI: radio шаблонов: TEXT, IMAGE (задизейблен), CHOICE, **«Текст с подписью»** (активен).
2. Выбрать «Текст с подписью», имя «Цитата», multiple = вкл, зависимость — лексема,
   **галку «Ядро» СНЯТЬ** (при цели-лексеме она по умолчанию включена; «Цитата» —
   не ядро, иначе будет оформлять лексему и предлагаться в черновике).
   UI: чекбокс «несколько значений» доступен (Д1); пикер цели — стандартный.
3. Сохранить.
   UI: «Цитата» в списке компонентов словаря.

Проверка: карточка слова → у оформленной лексемы «Цитата» предлагается к
добавлению; у черновика — НЕ предлагается.

### UC2. Первое заполнение значения

Подготовка: UC1 (компонент «Цитата», значений ещё нет).

Шаги:

1. Карточка слова → лексема → добавить «Цитата».
   UI: многострочное поле text + однострочное поле подписи; кнопка сохранения
   неактивна (text пуст).
2. Фокус в поле подписи.
   UI: выпадающий список НЕ показывается (пусто).

   ```
   ###CAPTIONED_TEXT### suggestions: typeId=<id> count=0
   ```

3. Ввести текст цитаты в 2–3 строки.
   UI: поле растёт по высоте, перенос строк работает; кнопка сохранения активна.
   Примечание: заодно проверить очень длинную цитату (абзац) — рендер значения
   не обрезает текст молча (перенос/расширение).
4. Ввести подпись `IELTS`.
5. Сохранить.

   ```
   ###CAPTIONED_TEXT### value add: typeId=<id> valueId=<id> text.len=<n> caption='IELTS'
   ```

Проверка: значение отображается: текст полностью (многострочно) + подпись `IELTS`;
после переоткрытия карточки — то же.

### UC3. Подпись из подсказок

Подготовка: UC2 (одно значение «Цитаты» с подписью `IELTS`).

Шаги:

1. Добавить второе значение «Цитата», ввести text.
2. Фокус в поле подписи.
   UI: выпадающий список с одним пунктом `IELTS`.

   ```
   ###CAPTIONED_TEXT### suggestions: typeId=<id> count=1
   ```

3. Тап по `IELTS`.
   UI: подпись подставлена в поле, список закрыт.
4. Сохранить.

   ```
   ###CAPTIONED_TEXT### value add: typeId=<id> valueId=<id> text.len=<n> caption='IELTS'
   ```

Проверка: у обоих значений подпись `IELTS`.

### UC4. Подпись: фильтр и новое значение одним полем

Подготовка: **свежий** multiple-компонент «Фраза» (captioned, как UC1);
добавить три значения с подписями `IELTS`, `Grammar`, `Idioms` (по одному разу).

Шаги:

1. Новое значение «Фраза» → text → фокус в подпись.
   UI: список: `Grammar`, `IELTS`, `Idioms` (частоты равны — порядок алфавитный,
   tie-break).
   Примечание: если пунктов станет больше, чем влезает — список скроллится.

   ```
   ###CAPTIONED_TEXT### suggestions: typeId=<id> count=3
   ```

2. Ввести `I`.
   UI: список сужен: `IELTS`, `Idioms`. Фильтрация локальная — нового лога
   `suggestions` НЕТ.
3. Дописать до `Irregular`.
   UI: список скрыт (совпадений нет); введённое остаётся в поле.
4. Сохранить.

   ```
   ###CAPTIONED_TEXT### value add: typeId=<id> valueId=<id> text.len=<n> caption='Irregular'
   ```

Проверка: новая подпись сохранена; при следующем открытии подсказок `count=4`.

2. Сохранить.


### UC6. Пустой text не сохраняется

2. Ввести в text пробелы/перенос строки.
   UI: кнопка по-прежнему неактивна (trim).

Проверка: лога `value add` НЕТ; значение «только подпись» создать невозможно.

### UC7. Редактирование значения

Подготовка: значение «Цитаты» с text `T1` и подписью `IELTS`.

Шаги:

1. Открыть значение в edit → сменить text на `T2` → сохранить.

   ```
   ###CAPTIONED_TEXT### value update: valueId=<id> text.len=<n> caption='IELTS'
   ```

2. Edit → сменить подпись (подсказки или ввод) на `Grammar` → сохранить.

   ```
   ###CAPTIONED_TEXT### value update: valueId=<id> text.len=<n> caption='Grammar'
   ```

3. Edit → очистить подпись → сохранить.
   UI: значение живёт без подписи.

   ```
   ###CAPTIONED_TEXT### value update: valueId=<id> text.len=<n> caption='null'
   ```

4. Edit → очистить text полностью → закоммитить (выход из поля/сохранение).
   UI: значение удалено из списка.

   ```
   ###CAPTIONED_TEXT### value remove: valueId=<id>
   ```

Проверка шага 4 (фикс origin lossy): переоткрыть карточку — значение НЕ вернулось
(реально удалено из БД, а не «тихо скрыто в UI»).

### UC8. Удаление значения и подсказки

Подготовка: на «Цитате» создать значение с уникальной подписью `Solo`.

Шаги:

1. Новое значение → фокус в подпись → **записать текущий `count` из лога**
   (baseline `X`); `Solo` в списке есть. Закрыть без сохранения.

   ```

   ```

2. Удалить значение с подписью `Solo` (стандартный механизм удаления).

   ```
   ###CAPTIONED_TEXT### value remove: valueId=<id>
   ```

3. Новое значение → фокус в подпись.
   UI: `Solo` в списке отсутствует (агрегация по живым значениям).

   ```
   ###CAPTIONED_TEXT### suggestions: typeId=<id> count=<X-1>
   ```

### UC14. Существующий словарь после апдейта (миграция v11 → v12)

Примечание (решение 2026-08-02): seed «Пример» схлопнут в `Migration_011_to_012`
(шаг 6b) — отдельной миграции 12→13 и лога `backfill` нет. Сценарий актуален
ТОЛЬКО для установки поверх сборки на схеме **v11** (прод-релиз 0.1.5); установка
поверх dev-сборки v12 «Пример» в существующие словари не добавит (v12 уже
финальна) — такие dev-сборки удаляются, это не поддерживаемый путь.

Подготовка: собрать сборку на схеме v11 (тег/коммит до IS486, `git worktree`
или отдельный чекаут) → `adb install -r` → создать словари с данными. Затем
собрать ветку IS491 → `adb install -r` ПОВЕРХ (без удаления приложения).

Шаги:

1. Первый запуск новой сборки → Room прогоняет `Migration_011_to_012`.
2. Конструктор каждого старого словаря.
   UI: «Пример» присутствует, enabled (плюс Перевод и Часть речи).

Проверка: старые данные (слова/лексемы/значения) не тронуты; «Пример» есть во
всех словарях. (Автоматически покрыто androidTest
`MigrationFrom11to12.is491_exampleSeededToAllDictionaries_finalShape` — при
ручной проверке достаточно взглянуть на конструктор.)

## Системные / edge

### UC21. Иерархия и деградация captioned-кастома

Шаги:

1. Кастом «Цитата2» (captioned, не ядро) с целью «Часть речи → существительное»
   (опция).
2. У лексемы с выбранным «существительное» добавить «Цитату2».
3. Удалить часть речи крестиком у чипа (чип глухой, смена = удалить + добавить).
   **Удаление ТИХОЕ, без confirm** (удаление значения в карточке — всегда без
   диалога; каскад по опции молчаливый): значение «Цитаты2» сброшено, компонент
   недоступен до нового выбора «существительное».

   ```
   ###CAPTIONED_TEXT### value remove: valueId=<id Цитаты2>
   ```

Проверка: captioned ведёт себя как любой зависимый компонент — ничего нового
от шаблона.
