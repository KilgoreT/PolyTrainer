# IS491 — Шаблон «текст с подписью» (captioned_text) и builtin-компонент «Пример»

Issue: [#491](https://github.com/KilgoreT/PolyTrainer/issues/491)

## Суть

Два этапа:

1. **Новый шаблон компонента** `captioned_text` — «Текст с подписью»
   (Captioned text), два текстовых поля:
   - **`text`** — многострочный ввод, обязательное; смысловая роль: цитата /
     пример / правило языка — основное содержимое значения;
   - **`caption`** — однострочный ввод, **опциональное**; смысловая роль:
     подпись — источник / категория / уровень сложности.
2. **Builtin-компонент «Пример»** (англ. **Example**) на основе этого шаблона,
   с той же зависимостью, что у части речи (`dependsOn = Lexeme`, не ядро).

Шаблон — generic: юзер может создать на его основе несколько кастомных
компонентов («Цитата + источник», «Правило языка + уровень сложности» и т.д.).

## Как ложится в текущую систему

Термины и механика — по canonical-спеке
`docs/handbook/specs/component-constructor/spec.md`.

- Новый элемент enum `ComponentTemplate` с `template_key = "captioned_text"` и
  `fields` из **двух** TEXT-полей `text` + `caption` (первый шаблон с более чем
  одним полем — JSON-envelope `TemplateValues` изначально проектировался под это).
- Новый `TemplateValues`-подтип: пара (text, caption?), caption nullable/пустой.
- Значения — та же таблица `component_values`. DDL-миграция не нужна (новый
  `template_key` + новый формат envelope колонок не меняют). Seed «Пример» в
  существующие словари **схлопнут в `Migration_011_to_012`** (шаг 6b): v12 нигде
  не релизилась (прод-релиз 0.1.5 = v11, dev-сборка v12 удаляется), прецедент —
  схлопывание IS486. Отдельной миграции 12→13 и bump'а версии НЕТ (решение
  2026-08-02, заменило исходный вариант «bump 12→13 + backfill» из аналитики П1).
- Template immutability, participation, иерархия, каскады — работают как для
  TEXT: шаблон не вводит новых узлов зависимостей (в отличие от CHOICE).
- Multiple разрешён (Д1): это не CHOICE, структурного запрета нет.

## Caption-поле: агрегация значений (ключевой UX)

- При вводе значения компонента под caption-полем — **выпадающий список**
  уже использованных значений этого поля.
- **Одно поле ввода — две роли одновременно**: ввод нового значения И фильтр
  выпадающего списка (combobox с автодополнением). Юзер либо пишет новое,
  либо выбирает из предложенного.
- Caption **не обязателен**: значение компонента сохраняется и без него.
- **Скоуп агрегации — per-компонент** (per `ComponentType`): у каждого
  компонента, созданного на основе шаблона, свой список подсказок.
  «Источник» (у «Цитата + источник») и «Уровень сложности»
  (у «Правило + уровень») не смешиваются. Так как компоненты пословарные,
  скоуп автоматически = компонент внутри словаря.
- Механика списка (Д4, уточнено 2026-08-02): distinct по живым значениям caption
  этого компонента, без отдельной таблицы; **регистр значим** — `ielts` и `IELTS`
  это два отдельных пункта, юзер сам выбирает нужный вариант; сортировка по
  частоте использования, при равных частотах — по алфавиту; без жёсткого
  лимита — длину списка решает фильтрация вводом.

Пример сценария: юзер пишет цитату, в caption вводит «IELTS». Следующая
цитата — в caption выпадает «IELTS», можно выбрать или ввести новое.

## Builtin «Пример» (Example)

- `system_key` — новый (например `example`), display локализуется ресурсом
  (рус. «Пример», англ. "Example").
- **Зависимость (Д2)**: `dependsOn = Lexeme`, `core = false` — ровно как у
  части речи: доступен у оформленной лексемы, черновик не закрывает.
- **Кардинальность (Д1)**: multiple — несколько примеров на лексему.
- Стандартные builtin-правила (§4 спеки): rename/delete/смена шаблона —
  `BuiltInProtected`; disable — можно, пословарно; seed при создании словаря;
  участвует как цель зависимостей.

## Решения

- **Д1. Кардинальность** — multiple везде: builtin «Пример» — multiple;
  кастомные компоненты шаблона выбирают single/multiple при создании, как TEXT.
- **Д2. Зависимость builtin «Пример»** — `dependsOn = Lexeme`, `core = false`
  (буквально «как у части речи»). Вариант `Component(translation)` отклонён:
  ломался бы в словарях с выключенным переводом.
- **Д3. Имена** — `template_key = "captioned_text"`, display «Текст с подписью»
  (Captioned text), поля envelope `text` + `caption`. `label` отклонён
  (занят опциями CHOICE), `tag` отклонён (зарезервирован под будущий
  отдельный компонент тегов).
- **Д4. Механика подсказок** — distinct-запрос по живым значениям caption
  этого компонента, без новой таблицы; **регистр значим, дедупа нет** (`ielts`
  и `IELTS` — отдельные пункты, юзер выбирает сам; решение 2026-08-02, заменило
  исходное «case-insensitive с сохранением первого написания»); сортировка по
  частоте, tie-break по алфавиту; без лимита.
- **Д5. Legacy samples** — в этой фиче `samples`/`hints` не трогаем; миграция
  samples → значения «Пример» — отдельной задачей (пункт в `docs/Backlog.md`).
- **Д6. Тренировки** — в квизах шаблон не участвует: фильтр пикера переводится
  на **белый список** (`template == TEXT`; уточнено 2026-08-02 — прежняя аналогия
  «как IMAGE» не работала: чёрный список ловил только CHOICE). Видение на
  будущее: роль в тренировках — не тренируемый компонент, а обогащение —
  при показе правильного ответа выводить примеры/цитаты лексемы.
- **Д7. Валидация** — `text` обязателен: пустой/пробельный не сохраняется
  (кнопка сохранения неактивна); «только caption без текста» невозможно.
  `caption` опционален.
