# IS511 | Бриф: выбор нескольких корневых компонентов для вопроса квиз-чата

Issue: https://github.com/KilgoreT/PolyTrainer/issues/511. Ветка
`IS511_quiz_multi_component` от master 6fcb27e5 (после 0.1.10).

## Что просит юзер (2026-09-30)

В бургер-меню квиз-чата есть выбор корневого компонента, по которому
задаётся вопрос. Большинство словарей будут использовать только перевод;
у юзера — перевод и определение.

1. Один корневой компонент — пункт меню не показывать.
2. Больше одного — показывать, выбор галками (несколько), не «один из».
   - 2а. Снять последнюю галку нельзя: единственная включённая задизейблена;
     чтобы оставить единственным другой, сначала включить его, потом
     выключить текущий. Обсуждаемо.
   - 2б. При нескольких включённых квиз задаёт вопросы по любому из них:
     одно слово на раунд без дублирования (перевод или определение, не
     оба), компонент для слова — случайно. Правила обсуждаются.

## Что есть сейчас (факты из кода)

- Пикер IS481 (AGG-12): `ItemsState.QuizComponent(availableTypes,
  selectedRef)`, radio-список `ComponentChoiceItem` в подменю
  `QuizComponentMenuItem`; при одном типе подменю показывается, но
  задизейблено (`isPickerEnabled = size > 1`); при пустом — скрыто.
- «Корневые компоненты» = типы с шаблоном TEXT текущего словаря
  (`getAvailableTypes`, белый список IS491): перевод (built-in) и
  пользовательские текстовые (например «Definition»).
- Хранение: prefs, ключ `quiz_picker_dict_<id>`, одна строка
  `builtin:translation` / `user:<name>`; саб `ChatSub.QuizPicker`
  переиздаёт состояние при записи.
- Применение: `QuizGameImpl.fetchData` — выбранный ref сужает
  `quizConfig.componentRefs` до одного элемента; `toQuizItem(refs)` берёт
  **первый по порядку** компонент, который есть у слова (без
  случайности); слово без единого подходящего компонента отбрасывается
  уже ПОСЛЕ отбора порции (порция становится короче лимита).
- Квиз-конфиг словаря по умолчанию — только перевод.
- Заголовок вопроса: built-in → «перевод», любой пользовательский тип →
  «определение» (legacy, header per component — в Backlog).
- Галка в меню — `MenuItem.withCheckbox(isChecked, title,
  onCheckedChange)` из `iconDropDowned`; параметра `enabled` нет.

## Решения (заполняются по ходу обсуждения)

- **Д1. Модель «что может быть вопросом» (решено 2026-09-30).**
  Спрашиваемое — лексема; лицо вопроса — одно из её **ядер** (`core`):
  ядро по определению несёт смысл слова и его идентифицирует, отдельное
  свойство «может быть вопросом» дублировало бы ядро. Корневые не-ядра
  (часть речи, пример, ярлык) — атрибуты лексемы, вопросом быть не могут;
  корневой ≠ ядро (топология против смысла), оба понятия остаются.
  Кандидаты пикера = ядра словаря, включённые, не удалённые, с шаблоном,
  который квиз умеет показать как вопрос (сегодня — TEXT; список растёт
  с рендерами, это свойство квиза, не домена). Один кандидат — меню нет,
  спрашиваем по нему. В раунде лексема встречается один раз, а каким
  ядром показать — случайно из включённых, которые у неё заполнены (2б).
  Белый список TEXT в `getAvailableTypes` → фильтр по `core`, `enabled`,
  `removedAt == null` и поддерживаемому шаблону. `QuizConfig.componentRefs`
  (никем не редактируется) при такой модели лишний — Backlog на удаление.
  Модель зафиксирована в спеке
  [word-model/spec.md](../../handbook/specs/word-model/spec.md) (§2.3, §2.6).
- **Д1а (решено).** Без сохранённого выбора включены **все** пригодные
  ядра: второе ядро добавляет тот, кто готов настраивать квиз; у нового
  словаря ядро одно — меню не появляется.
- **Д2 (решено).** Единственная включённая галка задизейблена (правило
  видно до действия, без снекбаров); под заголовком подменю статичная
  подпись «минимум одно». Radio → галки; у галки меню (`withCheckbox`)
  появляется `enabled`. Отвергнуто: снятие последней = включить все
  (результат противоположен намерению), тап-без-эффекта (тихий отказ),
  radio по сочетаниям (не масштабируется).
- **Д3 (решено).** Лексема без значения хотя бы в одном **включённом**
  ядре в отбор порции не попадает вовсе: фильтр на уровне выборки (грейды
  и добавки «давние»/«ошибки»), раунд добирается до лимита из подходящих.
  Не «выбросить после отбора». Выбор ядра для показа — случайно из
  включённых, заполненных у лексемы (модель, word-model §2.6).
- **Д4 (решено).** Вопрос в чате — «Имя ядра:» / **значение**: для
  встроенного перевода локализованное имя («Перевод»), для
  пользовательских — как назвал пользователь; имена совпадают с
  подписями галок в меню. Два legacy-заголовка («Переведи следующее
  слово», «Какое слово связано с этим определением») уходят. Правило игры
  — один раз за сессию: после «Начать» бот шлёт «Я даю подсказку — ты
  пишешь слово.», затем первый вопрос; после «Продолжить квиз» не
  повторяется. Отвергнута универсальная подводка в каждом вопросе (шум).
  Остальной поток (оценка с правильным ответом при ошибке, «Показать
  ответ», «Пропустить», финал, отчёт) — без изменений.
- **Д5.** → слилось с Д3.
- **Д6 (решено, 2026-09-30).** В пузыре вопроса перед значением — чип
  части речи: «Перевод:» / `[сущ.]` **собака**. Причина: из перевода или
  определения часто не ясно, какая часть речи спрашивается; чип читается
  до текста. Мелкий чип (11–12sp, фон `secondaryContainer`, скруглённый),
  в потоке строки значения (прижим к краю в пузыре ненадёжен). Показывается,
  только если у лексемы заполнена часть речи. Сокращения встроенных опций:
  словарные пометки сущ., гл., прил., нареч., предл., фраз. / n., v.,
  adj., adv., prep., phr. (ресурсы ru/en; уточнено на ручнике 2026-10-01). Рассмотрены 19
  раскладок; отвергнуты прижатые к краю (2, 7, 10), метка в заголовке
  (11, 14, 15 — часть речи свойство слова, а не ядра), «значение первым»
  (18 — часть речи узнаётся после текста). Настраиваемый набор атрибутов
  в вопросе (другие CHOICE-атрибуты, несколько чипов) — Backlog; раскладка
  12 на 2–3 чипа масштабируется.

## Не в скоупе (предварительно)

- Редактирование квиз-конфига словаря (набор компонентов в БД) — пикер
  остаётся оверрайдом поверх конфига.
- Другие режимы квиза.

## Критерий

При одном TEXT-типе пункта меню нет; при двух и более — галки, минимум
одна всегда включена; сессия с двумя галками задаёт вопросы по обоим
компонентам случайно, одно слово в раунде один раз; выбор переживает
перезапуск; юниты на редьюсер/кодек/выбор компонента; ручник на девайсе.
