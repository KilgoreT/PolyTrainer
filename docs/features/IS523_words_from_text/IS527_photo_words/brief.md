# IS527 | Бриф: захват фото и список слов

Подфича фичи IS523 (#523): подфича 3 «Захват фото» и первая половина
подфичи 4 «Распознавание» из `../phases.md`. Issue #527 (sub-issue #523),
ветка `IS527_photo_words` от master `3f39b368`.

Юзер (2026-10-07): «сделаем кнопку добавления через фото (или из галереи),
и пока что на самом аппарате через ML-библиотеку попробуем достать оттуда
слова. Юзер кликает кнопку, появляется окошко выбора фото либо из галереи,
при получении изображения идёт какое-то действие, пока ML работает. При
этом в диалоговом окне крутится лоадер, и позже на месте диалогового окна
появляются слова. Список слов. Пока только список. Пока можно на них
только посмотреть и нажать кансел. И пока только во всплывающем меню. Если
слов много — то скролл.»

## Цель

На вкладке «Слова» появляется вход в фичу «слова из текста»: кнопка-камера
над основным FAB «+». Нажатие → выбор «Камера» / «Галерея» → фото →
распознавание текста на устройстве (ML Kit) → диалог со списком найденных
слов. Со списком ничего делать нельзя: посмотреть и закрыть. Это проверка
качества ML Kit на реальных фото (Д2: «попробуем, позже проверим») и
готовый вход для следующих подфич.

## Что есть сейчас (факты из кода, см. analysis.md)

- Вкладка слов — модуль `:modules:screen:wordstab` (mate MVI). FAB «+»
  рисует хост `:modules:screen:vocabulary` в `Scaffold` по контракту
  `TabSpec.fab: FabSpec?` — ровно один FAB на вкладку
  (`TabContract.kt:29,64`). Второго FAB и колонки кнопок в проекте нет.
- Своего маленького FAB нет: `LexemeFab` — 56 dp, `RoundedCornerShape(16)`
  (`modules/core/ui/.../btn/base/LexemeFab.kt:31`).
- Иконки камеры / галереи в `core/core-resources` нет.
- Манифест: разрешений нет, `FileProvider` нет, `<queries>` нет
  (`app/src/main/AndroidManifest.xml`). Единственная Activity —
  `MainActivity : ComponentActivity`.
- ML Kit, CameraX, Coil/Glide, загрузка Bitmap из Uri — нигде не
  используются. `rememberLauncherForActivityResult` есть только в
  `settingstab` (импорт/экспорт файлов), там же прецедент «Uri в state →
  `LaunchedEffect` запускает контракт».
- Диалоги: базовый `LexemeDialog` (`modules/core/ui/.../dialog/base/`),
  пример явных цветов — `LanguagePickerDialog` (`formBackground`,
  `formTextTertiary`, `LexemeColor.primary`).
- CI (эмулятор API 34, `google_apis`) гоняет `connectedDebugAndroidTest`
  трёх модулей; новый модуль надо добавить в список
  (`.github/workflows/on_pull_request.yml:69`).
- ML Kit Text Recognition v2 (документация, 2026-10-07): bundled-артефакт
  `com.google.mlkit:text-recognition:16.0.1`, +≈4 МБ на письменность на
  архитектуру, модель доступна сразу; unbundled
  `com.google.android.gms:play-services-mlkit-text-recognition:19.0.1`,
  +≈260 КБ, модель скачивается Play-сервисами перед первым
  использованием. Минимум API 23 (у нас minSdk 24). Латинская модель —
  по умолчанию; китайская, деванагари, японская, корейская — отдельные
  артефакты. Вход: `InputImage.fromFilePath(context, uri)` (учитывает
  EXIF-поворот) или `fromBitmap(bitmap, rotation)`. Результат: `Text` →
  `TextBlock` → `Line` → `Element` (≈ слово) → `Symbol`, у каждого
  `boundingBox`.

## Допущения (мои — отменяются одним словом)

- **Д1. Камера — системное приложение камеры** через
  `ActivityResultContracts.TakePicture` (нужен `FileProvider` и файл в
  `cacheDir`; разрешение `CAMERA` не требуется, пока оно не объявлено в
  манифесте). Встроенный видоискатель на CameraX (разрешение, превью,
  съёмка) — не в первой версии. **Подтверждено юзером 2026-10-07**
  («1, но там будет возможность выбора из галереи?» — да, Д2).
- **Д2. Галерея — системный фотопикер** `ActivityResultContracts.PickVisualMedia`
  (без разрешений; на устройствах без фотопикера контракт сам откатывается
  на `ACTION_GET_CONTENT`).
- **Д3. ML Kit — bundled, только латиница.** Модель в APK, работает сразу
  и без Play-сервисов (в т. ч. на эмуляторе CI). Цена — ≈4 МБ на
  архитектуру в сплите AAB. Кнопка показывается для любого словаря; для
  нелатинского изучаемого языка результат будет мусорным — ограничение
  первой версии, гейт по письменности — позже (Д2/Д3 брифа IS523).
- **Д4. Что считать словом.** Берём `Element`-ы ML Kit; с краёв снимаем
  знаки препинания и кавычки, внутренние дефис и апостроф оставляем
  (`well-known`, `don't`); выбрасываем токены без букв (числа, тире,
  маркеры) и одиночные буквы, кроме `a`/`I`-подобных — проще: длина ≥ 2;
  приводим к нижнему регистру; дубли схлопываем; порядок — первое
  появление в тексте. Имена собственные от начала предложения не
  отличаем — это задача нейронки в подфиче 4.
- **Д5. Диалог один, три состояния:** выбор источника («Камера» /
  «Галерея» / «Отмена») → распознавание (лоадер, «Отмена») → список
  (заголовок с числом слов, `LazyColumn`, «Закрыть»). Закрывается кнопкой,
  тапом вне и кнопкой «назад». Пустой результат — текст «Слов не найдено»
  вместо списка. Ошибка ML Kit или недоступная камера — текст ошибки в
  диалоге, без крэша.
- **Д6. Размер фото.** Перед ML Kit картинка уменьшается до бюджета
  12 Мп (`BitmapFactory.inSampleSize`): скриншоты и фото до 12 Мп идут
  как есть, 48-мегапиксельное фото сжимается вчетверо. (Уточнено ревью
  2026-10-07: прежняя формулировка «2048 px по длинной стороне» пережимала
  обычный скриншот 1080×2400 вдвое и убивала мелкий шрифт.) Поворот — из
  EXIF. Временный файл камеры удаляется после распознавания.
- **Д7. Где живёт ML Kit** — новый библиотечный модуль
  `:modules:library:textrecognition` с интерфейсом
  `TextRecognizer.recognize(uri): RecognizedText` и реализацией на ML Kit;
  экран зависит от интерфейса, извлечение слов — чистая Kotlin-функция
  в `wordstab` с unit-тестами. androidTest библиотеки рисует текст на
  `Bitmap` через `Canvas.drawText` и проверяет, что ML Kit его читает (без
  бинарных ассетов), модуль добавляется в CI.

- **Д8. Кнопка-камера только в dev-сборке** (юзер, 2026-10-07, «1»): гейт
  `BuildConfig.DEBUG` в сборке спеков вкладок. В магазинной сборке входа
  в фичу нет, пока не готов сквозной путь до добавления слов (Д12 брифа
  IS523); гейт снимается в подфиче 6.

## Вне скоупа

- Нейронка, бэкенд, токены (подфича 2), значения из источников (5),
  добавление слов и компоненты (6), «уже есть в словаре» (Д10),
  лемматизация, отбор значимых слов, контекст-предложение.
- Файлы, вставка текста, PDF (Д3).
- Письменности вне латиницы, мультимодальный фоллбэк.
- Правка распознанного текста (Д2) — перед нейронкой, не здесь.
- Отметка слов в списке, выбор, любые действия кроме «закрыть».

## Ручная проверка (на девайсе, dev-сборка)

Кейсы — в чате по правилам: фото страницы книги с камеры; скриншот из
галереи; фото без текста; отмена на каждом шаге; поворот фото (альбомный
кадр); длинный текст (прокрутка списка); повторный запуск подряд.
