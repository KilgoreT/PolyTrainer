# IS529 | Ручники: шлюз в приложении и список слов из ответа сервера

Форма — `backend/spec/CHECKS.md`, раздел 3: заголовок кейса несёт адреса
строк спеки `backend/spec/words-from-text.md`. В чат кейсы выдаются по
одному: счётчик, название, шаги-атомы, последний шаг «Напиши “ок”».
Состояние и лог после «ок» проверяет агент.

Вход для всех кейсов: Pixel 7 Pro, dev-сборка `co.lexeme.app.dev` с
ключом в `local.properties`, текущий словарь с изучаемым языком `es` или
`en`, сервер `api.lexeme.pro` жив. Снимать: `adb logcat -d | grep
"###VOCAB###\|###NETWORK###\|Reduce"`.

## Словарь логов

### VOCAB — вкладка «Слова» (`###VOCAB###`)

- `OCR line N: …` — строка распознанного текста, по ней сверяется ML Kit.
- `lookup run=N tokens=K` — запрос на сервер ушёл: номер запуска, число
  токенов после Ш5.
- `lookup run=N outcome=…` — исход: `words=M`, `denied=<причина>`,
  `unavailable`.

### NETWORK — слой сети (`###NETWORK###`)

- `POST /v1/words/lookup -> <код> in <мс>ms` — одна строка на обмен;
  заголовков в логе нет, ключ не печатается (WFT-05).

### Reduce — редьюсер вкладки (`###VOCAB###`)

- `Reduce ---message---: PhotoPicked(uri=…)`, `PhotoPickCancelled`,
  `TokensReady`, `WordsLookedUp`, `ClosePhotoWords` — порядок событий; у
  тяжёлых data-Msg только имя класса, их содержимое пишет handler
  строками `lookup …`.
- `Reduce ---step---: <атом> | k=v` — один шаг состояния:
  `showPhotoSourceChooser | requestId=N`, `returnToPhotoSourceChooser |
  requestId=N`, `startRecognizing | requestId=N`, `startLooking |
  requestId=N`, `showNoPhotoWords`, `showPhotoError | errorRes=…`,
  `hidePhotoWords | requestId=N`; по `requestId` видно, чей запуск
  (WFT-62).
- `Reduce ---step---: no-op | reason=…` — событие пришло и намеренно
  проигнорировано: `tokensReady: foreign run N`, `wordsLookedUp: foreign
  run N` — ответ закрытого или чужого запуска; `photoPickCancelled:
  dialog closed`.
- `RunEffect: <эффект>` под `###MATE###` — эффект ушёл в handler.

### Сервер (`ssh … docker logs lexeme-server`)

- `lookup words run_id=N subject=kilg tokens=K words=M took=…` — та же
  пара номер запуска / число слов, что и на устройстве.

## Кейсы

## WFT-16.1, WFT-16.2, WFT-56.1, WFT-56.7, WFT-57.1 Снимок страницы → список слов с леммами

Вход:
- страница книги или экран с испанским (или английским) текстом, 20–60 слов

Шаги:
1. Вкладка «Слова» → кнопка-камера → «Камера» → снять текст.
2. Смотреть на подпись индикатора, пока идёт запуск.
3. Дождаться списка.

Ожидания:
- экран: сначала «Распознаю текст…», затем «Ищу слова в словаре…», затем
  список: в заголовке «Слов: N», у каждого найденного слова второй
  строкой «лемма, часть речи», под списком «Данные: Wiktionary, CC BY-SA
  4.0»
- лог: `lookup run=N tokens=K`, затем `POST /v1/words/lookup -> 200`,
  затем `lookup run=N outcome=words=M`; `M` равно числу в заголовке
- лог сервера: `run_id=N` тот же, `words=M` тот же

Анти-проверки:
- экран: индикатор не виден одновременно со списком
- лог: ключа доступа ни в одной строке

Прогон: ✅ 2026-10-11 (запуск 2: 20 токенов → 10 слов за 1 с, run_id и число слов совпали на устройстве и сервере; «amigo, noun → friend → друг, приятель»; найден хвост шаблона у «camino», исправлен в сервере)

## WFT-56.3, WFT-60.3 Мусор распознавания → пометка «не найдено»; кириллица → «слов не найдено»

Вход:
- снимок с опечатками или рукописным текстом; страница с кириллицей

Шаги:
1. Кнопка-камера → «Галерея» → картинка с опечатками.
2. Дождаться списка, найти слова с пометкой.
3. Закрыть. Кнопка-камера → «Галерея» → страница с кириллицей.
4. Дождаться результата.

Ожидания:
- экран: у несуществующих слов второй строкой «не найдено», леммы нет
- экран: после кириллицы — «Слов не найдено»
- лог: для кириллицы `lookup` не печатается, `POST` не печатается

Анти-проверки:
- экран: у «не найдено» нет части речи

Прогон: ✅❌ 2026-10-11 (запуск 2: кириллица дала 210 латинских токенов, 194 слова; первый раз «сервер не ответил» — таймаут чтения OkHttp 10 с, исправлено; второй раз список за 80 с, но 186 слов «не загрузилось» из-за квоты источника на некешированные запросы (Д26, принято как есть); «не найдено» у мусора есть; WFT-60.3 переписать — ноль токенов кириллица не даёт)

## WFT-62.2 Отмена во время ожидания ответа

Шаги:
1. Кнопка-камера → «Камера» → снять страницу с большим числом слов.
2. Как только подпись сменилась на «Ищу слова в словаре…», нажать «Отменить».
3. Подождать 10 секунд.

Ожидания:
- экран: диалог закрыт, список не появляется
- лог: `Reduce ---message---: ClosePhotoWords` и `hidePhotoWords |
  requestId=N` раньше, чем `WordsLookedUp`; за `WordsLookedUp` — `no-op |
  reason=wordsLookedUp: foreign run N`, без `startFormLoading`

Анти-проверки:
- экран: диалог не открывается сам

Прогон: ✅ 2026-10-11 (запуск 2: 48 токенов → 38 слов за 48 с; один запрос на запуск, после поворотов повторного lookup нет, индикатор и список на месте)
