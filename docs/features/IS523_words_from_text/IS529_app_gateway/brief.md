# IS529 | Бриф: шлюз в приложении и список слов из ответа сервера

Подфича фичи IS523 (#523): подфича 2б «Шлюз в приложении» из
`backend/docs/features/IS523_words_from_text/phases.md` плюс список из ответа сервера. Issue #529 (sub-issue #523).
Код в ветке родителя `IS523_words_from_text`, как IS527.

Источник истины по поведению — спека `lexeme/spec/words-from-text.md`
(в этом репозитории видна как `backend/spec/words-from-text.md`): шаги Ш5,
Ш6, Ш11 и ветки В2, В3, В4, В5, В7. Контракт — `backend/api/openapi.yaml`.
Сервер в проде: `https://api.lexeme.pro`, lexeme v0.1.2.

Юзер (2026-10-10): «надо её делать»; ключ доступа «надо будет вводить
самому. отдельно создам на сервере и введу»; «этот слой должен быть таким
же, как и датастор».

## Цель

После распознавания (IS527) приложение отправляет токены на свой сервер
одним запросом, ждёт с индикатором, подпись которого говорит о фазе, и на
месте индикатора показывает список слов из ответа: по элементу на слово,
с пометками «не найдено» и «не загрузилось», числом слов и подписью
источника с лицензией. Это первое испытание всей цепочки «снимок →
сервер → словарь» на девайсе. Со списком по-прежнему ничего делать
нельзя.

## Что есть сейчас (факты из кода)

- Диалог «слова с фото» в `:modules:screen:wordstab`:
  `PhotoWordsState(isOpen, isChoosingSource, isRecognizing, words,
  errorRes, requestId)`, сообщения `OpenPhotoSourceChooser`, `PhotoPicked`,
  `PhotoPickCancelled`, `WordsRecognized(words, requestId)`,
  `RecognitionFailed`, `ClosePhotoWords`; эффект `RecognizeWords` в
  `DatasourceEffectHandler` зовёт `useCase.recognizeText(uri)` и прогоняет
  слова через `extractWords` (нормализация на устройстве). `requestId`
  растёт на каждое открытие и снимок, чужой результат отбрасывается:
  это уже WFT-01…03 и половина WFT-62.
- Распознавание отдаёт `RecognizedText(lines, words: List<RecognizedWord
  (text, confidence, language?)>)` — это ровно `TokenQuery` контракта,
  маппинг тривиален.
- Экран знает только свой `WordsTabUseCase` (интерфейс в модуле экрана),
  реализация `WordsTabUseCaseImpl` в `app/.../di/module/wordstab/`
  собирает её из `CoreDbApi.*`, prefs и `TextRecognizer`. Так устроены все
  экраны.
- Слой базы — три модуля: `core/core-db-api` (интерфейс `CoreDbApi`,
  провайдер `CoreDbProvider`, сущности), `core/core-db-impl` (Room, DI
  `RoomComponent`), `core/core-db` (фасад `CoreDbComponent` с ленивым
  `init`, `api(core-db-api)` + `implementation(core-db-impl)`). `App`
  поднимает `CoreDbComponent.init(...)` и отдаёт `CoreDbProvider` в
  `AppComponent` через `dependencies`. На `:core:core-db` зависит только
  `app`.
- Сети и JSON в проекте нет: ни OkHttp, ни Retrofit, ни сериализации,
  только coroutines. Каталоги версий в `deps/*.toml`.
- Языки словаря — `DictionaryApiEntity.learningLanguage` и
  `translationLanguage` (IS525), текущий словарь — через
  `CurrentDictionaryProvider`.
- `BuildConfig` у `app` включён, в `debug` уже кладутся `LOG_LEVEL` и
  `REMOTE_LOG_LEVEL` из `project.findProperty`. `local.properties` в
  `.gitignore`. Dev-сборка — build type `debug` с `applicationIdSuffix
  ".dev"`.

## Решения юзера

- **Д1 (2026-10-10). Сетевая библиотека — Retrofit поверх OkHttp,
  конвертер kotlinx.serialization.** Я рекомендовал голый OkHttp ради
  одного запроса, юзер взял Retrofit сразу: следующие адреса (значения,
  вход через Google) ляжут в тот же интерфейс.
- **Д2 (2026-10-10). Ключ доступа — `local.properties` → `BuildConfig`,
  без экрана настроек.** Ключ выписывает юзер сам на сервере
  (`lexeme key issue`), кладёт в `local.properties`, сборка несёт его в
  `BuildConfig`. Пустой ключ → WFT-19 «нет доступа к серверу».
  Настройки появятся вместе с входом через Google.
- **Д3 (2026-10-10). Сетевой слой устроен как слой базы.** Три модуля по
  образцу `core-db`: api с интерфейсом и сущностями, impl с Retrofit и
  DTO, фасад с Dagger-компонентом. Экран о сети не знает, `UseCase` в
  `app` соединяет распознавание, словарь и сеть.
- **Д4 (2026-10-10). В элементе списка у найденного слова лемма и часть
  речи первого кандидата** («corrían», под ним «correr, verb»). Юзер
  выбрал вариант 1: на девайсе видна работа сервера, иначе первое
  испытание показало бы тот же список, что и до бэкенда. WFT-56 и Ш11
  спеки правлены, новые адреса WFT-56.7 и WFT-56.8.
- **Д5 (2026-10-11, после первого прогона на девайсе). Третьей строкой —
  первое толкование первого кандидата на языке источника** («llegar,
  verb» → «to arrive»). Юзер: «а перевод-то?» — список из одних лемм не
  читается. Это толкование английского Викисловаря, не перевод: русского
  в источнике нет (WFT-53, research_surface §2). Русский — отдельное
  решение, см. «Открытые вопросы». WFT-56.9.
- **Факт прогона (2026-10-11).** Первый снимок дал плохой результат из-за
  языка словаря: у текущего словаря изучаемый язык был `en`, сервер искал
  испанские слова в английской секции. С `es` те же 23 токена дали 10 из
  10 испанских слов с леммами («llamo → llamar», «llego → llegar»). Три
  слова пришли «не загрузилось» разово; сервер причину сбоя источника не
  писал — добавлена строка `source failed` с номером запуска (lexeme, ждёт
  выката, тег пока не ставим по слову юзера).

## Допущения (мои — отменяются одним словом)

- **Имена модулей:** `core/core-network-api`, `core/core-network-impl`,
  `core/core-network`. Пакеты `me.apomazkin.core_network_api` и далее по
  образцу базы.
- **Интерфейс api-модуля:** `CoreNetworkApi.WordsApi.lookup(request):
  LookupResult`, где результат — sealed: `Success(words, attribution)`,
  `Denied(reason)` для 401/429/413/400 с кодом, `Unavailable` для сети,
  таймаута, 5xx и битого тела. Исключения наружу не выходят, экран
  получает один из трёх исходов. Сущности api-модуля — свои
  (`LookupRequest`, `TokenQuery`, `WordResult`, `Candidate`, `Sense`),
  без аннотаций сериализации: DTO с `@Serializable` живут в impl и
  маппятся в сущности.
- **Константы клиента:** базовый адрес `https://api.lexeme.pro`, общий
  таймаут вызова 180 с (`callTimeout`), заголовки `Authorization: Bearer`
  и `X-Run-Id` ставит перехватчик OkHttp; ключ в логи не пишется (WFT-05
  на устройстве: перехватчик логирования не печатает заголовки).
- **HTTPS:** OkHttp по умолчанию доверяет системным центрам, адрес `http`
  не собирается (WFT-21 проверяется unit-тестом на фабрику клиента).
- **Ключ:** `local.properties` → `LEXEME_ACCESS_KEY`, в `BuildConfig`
  обоих build type (в release по умолчанию пустая строка), читается в
  `App` и передаётся в фасад сети как `@BindsInstance`.
- **Ш5 на устройстве:** `extractWords` с нормализацией уходит; остаётся
  `prepareTokens`: убрать пустые, схлопнуть дубли текста с выбором
  наибольшей уверенности на месте первого, потолок 2000 (WFT-17, 18).
  Тесты `ExtractWordsTest` переписываются под адреса `WFT-17.k`, `WFT-18.k`.
- **Стейт диалога:** вместо `isRecognizing` явная фаза
  `phase: Idle | Recognizing | Looking` плюс `words: List<PhotoWord(text,
  status)>`, `wordsCount`, `errorRes`. Подписи «Распознаю текст» и «Ищу
  слова в словаре» по фазе (WFT-16). Отмена закрывает диалог, поздний
  ответ с чужим `requestId` отбрасывается (WFT-62).
- **Сообщения:** `WordsRecognized` заменяется на `TokensReady(tokens,
  requestId)` → эффект `LookupWords(tokens, requestId)` → `WordsLookedUp
  (result, requestId)`. Пустые токены → сразу «слов не найдено» без
  запроса (WFT-60.1).
- **Тексты:** «нет доступа к серверу» (401 и пустой ключ), «лимит на
  сегодня исчерпан» (429), «слишком много слов» (413), «язык словаря не
  поддерживается» (400 `unsupported_language`), «сервер не ответил»
  (сеть, таймаут, иной код, битое тело), «слов не найдено». Подпись под
  списком «Данные: Wiktionary, CC BY-SA 4.0», нажатие открывает
  `https://creativecommons.org/licenses/by-sa/4.0/` (WFT-57).
- **Элемент списка:** слово ответа первой строкой, у `found` второй
  строкой «лемма, часть речи» первого кандидата (Д4), у `not_found` и
  `error` вместо второй строки пометка. Остальные кандидаты и значения
  в стейт не кладутся, пока их некому показывать.
- **Логи:** `X-Run-Id` = `requestId` диалога, в логе устройства строка
  запроса и ответа с числом слов и временем; ключ не печатается.
- **Тесты:** unit на подготовку токенов, редьюсер (фазы, отмена, чужой
  id, ветки ошибок по коду), маппинг DTO → сущности на записанных ответах
  сервера (фикстуры из `backend/testdata`), фабрику клиента (https).
  Имена тестов несут адреса `WFT-NN.k`. Ручники по CHECKS на Pixel 7 Pro.

- **Д6 (2026-10-11). Значения на русском — из Русского Викисловаря по
  лемме, в этой подфиче, не в пятой.** Юзер выбрал вариант 1 из трёх
  («давай сделаем это, потом дальше прогоны»). Сервер после леммы ходит в
  `ru.wiktionary.org/w/index.php?title=<лемма>&action=raw`, берёт раздел
  «Значение» секции изучаемого языка, снимает разметку и отдаёт списком
  `meanings` у кандидата (WFT-66, контракт `Candidate.meanings`). Телефон
  запросов не добавляет; третьей строкой показывает первое русское
  значение, без него — английское толкование (WFT-56.10). Одна лемма —
  один запрос, статья без секции или сбой — пусто, статус слова не
  меняется. Факты, на которых решение: все 12 лемм первого прогона есть в
  Русском Викисловаре с русскими значениями, форм там нет.

- **Д7 (юзер, 2026-10-11). Только портрет, поворот не проверяем.**
  `MainActivity` зафиксирована `android:screenOrientation="portrait"`;
  состояние диалога поворот переживает по устройству mate, но кейсы с
  поворотом из ручников убраны, строки WFT-16.3 и WFT-56.5 остаются
  открытыми с пометкой «не проверяется». Автоповорот на девайсе был
  выключен, я его не трогал.

## Открытые вопросы (к юзеру, по одному)

Нет. Русский закрыт Д6. Факты, на которых решался вопрос:
  - Русский Викисловарь: у всех 12 лемм есть испанская секция с разделом
    «Значение» на русском («llegar → прибывать; приезжать, приходить»,
    «correr» — 15 значений). Форм нет («llego», «llamo» → 404): лемму
    по-прежнему даёт английский Викисловарь, русский берётся по лемме.
    REST-значений нет, разбор викитекста (`action=raw`, шаблоны
    `{{помета}}`, `{{пример}}`), лицензия та же CC BY-SA. Полнота на
    редких словах не проверена.
  - Нейронка через OpenRouter: перевод толкования или леммы с контекстом,
    цена ничтожна (`research_surface` §1), текст уходит третьей стороне,
    качество не проверено.
  - Машинный перевод (DeepL, Google): перевод голой леммы теряет
    значение, перевод толкования — рабочий, но это ещё один ключ и ещё
    одна третья сторона.
