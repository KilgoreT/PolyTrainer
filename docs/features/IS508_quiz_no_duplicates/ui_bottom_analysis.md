# IS508 / чат-фикс 3 | Анализ: лента от низа (`reverseLayout = true`)

Бриф: [ui_bottom_brief.md](ui_bottom_brief.md). Код — по состоянию
ветки на 2026-09-28 (после коммита 674f5b4b, чат-фикс 2).
Compose foundation 1.8.2 (`deps/compose.versions.toml`), ссылки на
исходники — из `foundation-android-1.8.2-sources.jar`.

## 1. Как устроено сейчас

`ChatMessageWidget.kt` — `LazyColumn(reverseLayout = false,
contentPadding = 16.dp, verticalArrangement = spacedBy(4.dp))`:

- `itemsIndexed(state.list, key = order.toString())` — сообщения в
  порядке добавления; внутри элемента логика по индексу оригинального
  списка: `needSpaceBeforePrevious = !isPreviousHasSameType(index)`
  (Spacer 8dp над пузырём при смене стороны), `notShowAvatar =
  index < lastIndex && list[index + 1].isSystemMessage` (аватар только
  у последнего в цепочке системных), `isInChain = index > 0 &&
  list[index - 1].isSystemMessage` (скругление), `isLastMessage =
  index == lastIndex` (кнопки финала).
- Последним — `item(key = "user_actions") { UserActionsWidget }` при
  `showUserActions` (чат-фикс 2), `padding(top = 8.dp)`.
- Автопрокрутка: `LaunchedEffect(state, showUserActions) { if
  (lastIndex >= 0) animateScrollToItem(lastIndex) }`, `lastIndex =
  list.size` при показанных чипах.

Экран: `Scaffold` → `Box.padding(paddings).consumeWindowInsets(paddings)
.imePadding()` (`ChatScreen.kt:61-67`); манифест `adjustResize`;
`enableEdgeToEdge` (`MainActivity.kt:38`). При клавиатуре `Box`
сжимается, лента (`weight(1F)`) — вместе с ним.

## 2. Почему обе проблемы — одна

Якорь ленты — верх: первый элемент прижат к верху вьюпорта, смещение
прокрутки считается от верха. Отсюда:

- короткий контент — под аппбаром, низ вьюпорта пустой (проблема 1);
- при сжатии вьюпорта снизу (клавиатура) верх остаётся на месте,
  срезается низ (проблема 2).

`reverseLayout = true` переворачивает якорь: индекс 0 — нижний
элемент, «прокручено в начало» = «прокручено в конец ленты».

## 3. Что делает `reverseLayout` — по исходнику

- **Короткий контент — к низу только через `Alignment.Bottom`**
  (поправлено по ревью, Б1). Реверс НЕ меняет семантику arrangement:
  KDoc `LazyDsl.kt:372` — «with Arrangement.Top (top) 123### (bottom)
  becomes (top) 321###». Умолчание `LazyColumn` при реверсе —
  `Arrangement.Bottom` (`:393-394`), но явный `spacedBy(4.dp)` его
  затирает и пакует группу к верху (`Arrangement.kt:296-299`).
  Смещения флипаются дважды — в `calculateItemsOffsets`
  (`LazyListMeasure.kt:645-651`) и в `place()`
  (`LazyListMeasuredItem.kt:227-231`) — итог визуальный. Нужно
  `spacedBy(4.dp, Alignment.Bottom)`; зазор 4dp сохраняется.
- **Несколько placeable внутри элемента переворачиваются** (Б2).
  KDoc `LazyListMeasuredItem.kt:121-124`: «inner placeables would be
  placed in the inverted order». Сейчас элемент — `Spacer` + пузырь как
  два корня: в реверсе Spacer ляжет под пузырь, зазоры съедут на одну
  границу. Элемент должен иметь один корень: отступ при смене стороны
  — `Modifier.padding(top)` у виджета сообщения (оба принимают
  `modifier` на внешний `Box`).
- **`contentPadding` визуальный.** `LazyList.kt:231-238`:
  `beforeContentPadding = bottomPadding` при реверсе — нижний отступ
  остаётся снизу, верхний сверху. `PaddingValues(all = 16.dp)` не
  трогается.
- **Клавиатура.** Позиция ленты — `firstVisibleItemIndex` +
  `firstVisibleItemScrollOffset`; в реверсе первый видимый — нижний.
  Если лента в конце (индекс 0, смещение 0), сжатие вьюпорта оставляет
  нижний элемент у нижнего края — конец виден (требование 2). Если
  юзер в истории — его первый видимый (нижний) элемент остаётся,
  прыжка нет.
- **Вставка нового элемента с индексом 0.** `LazyListState` держит
  позицию по ключу первого видимого (`lastKnownFirstItemKey`): новое
  сообщение встаёт «ниже» вьюпорта, лента сама к нему не едет — как и
  сейчас, нужна автопрокрутка (`animateScrollToItem(0)`). Поведение
  Д2 сохраняется.
- **Пустая лента.** `animateScrollToItem(0)` на пустом списке
  безопасен: `lastVisibleItemIndex` для пустого списка = 0
  (`LazyListScrollScope.kt:42-43`) → элемент 0 «виден», дистанция 0,
  снап в (0, 0) без исключений — до цикла прокрутки не доходит. Guard
  `lastIndex >= 0` из чат-фикса 2 не нужен.

## 4. Что меняется в `ChatMessageWidget`

1. `reverseLayout = true` + `verticalArrangement = spacedBy(4.dp,
   Alignment.Bottom)` (Б1).
2. Порядок подачи: `itemsIndexed(state.list.asReversed(), key =
   order.toString())`; внутри — `val index = state.list.lastIndex - i`
   (оригинальный индекс), вся логика цепочек/аватаров/кнопок финала —
   по нему без изменений. Ключи те же — композиция элементов не
   пересоздаётся при переходе.
3. Элемент чипов — **первым** в `LazyListScope` (в реверсе первый =
   нижний): `if (showUserActions) item(key = USER_ACTIONS_KEY) {…}`
   перед `itemsIndexed`. `padding(top = 8.dp)` внутри одного `Row`
   остаётся зазором до вопроса над ним — модификаторы внутри одного
   placeable реверс не трогает.
4. Отступ при смене стороны — `Modifier.padding(top = 8.dp)` у виджета
   сообщения вместо сиблинг-`Spacer` (Б2): один корень на элемент.
5. Автопрокрутка: `LaunchedEffect(state, showUserActions) {
   animateScrollToItem(0) }` — без арифметики `lastIndex` и guard.
6. Отступы как сейчас: между сторонами 4 + 8 = 12dp, внутри цепочки
   4dp, вопрос→чипы 4 + 8 = 12dp.

`ChatWidget`, `ChatScreen`, редьюсер, состояние — без изменений.

## 5. Варианты

### А. `reverseLayout = true` в `ChatMessageWidget` (Д1, принят)

Плюсы: одна раскладка закрывает обе проблемы, стандарт мессенджеров,
клавиатура без слушателей IME; код становится проще (нет `lastIndex`).
Минусы: индексная арифметика `asReversed` + `lastIndex - i` и два
неочевидных свойства реверса (Б1 arrangement, Б2 порядок placeable в
элементе) — проверяются превью с фиксированной высотой и ручником M7.
Объём: ~25 строк в одном файле.

### Б. Только `Arrangement.spacedBy(4.dp, Alignment.Bottom)` — отклонён как самостоятельный

В forward-ленте закрывает только короткий чат; клавиатура остаётся
(якорь верхний). В итоговой конфигурации `Alignment.Bottom` — не
альтернатива, а обязательная часть А: реверс даёт якорь скролла и
клавиатуру, `Alignment.Bottom` — прижатие короткого контента (Б1).

### В. Слушатель IME + `animateScrollToItem(last)` — отклонён

`WindowInsets.ime.getBottom` (прецедент `InputDockedPanelWidget.kt:83`)
→ докрутка при появлении клавиатуры. Не решает короткий чат; при
анимации клавиатуры вьюпорт меняется несколько кадров — докрутка может
не дотянуть; лишний механизм поверх раскладки, которая умеет это сама.

## 6. Влияние на соседние пункты Backlog

- **«Поле ввода прячется при прокрутке к ранним сообщениям»** — в
  реверсе «юзер ушёл от конца» = `firstVisibleItemIndex > 0` (или
  смещение > порога), без вычислений через `layoutInfo` и размер
  списка; реализация упрощается. Записать в пункт.
- **«Анимация как в Telegram»** — `animateItem()` на keyed-элементах
  работает и в реверсе; появление нового сообщения снизу с
  автопрокруткой к 0 — естественная точка для анимации.
- **«Клавиатура закрывает сообщения»** — закрывается этим фиксом;
  пункт удалить.

## 7. Риски

- Ошибка в индексе (`lastIndex - i`): аватар/скругление у не того
  пузыря, кнопки финала у не того сообщения. Ловится превью
  `ChatMessageWidget` (3 сообщения, чипы) и M7 шаг «цепочка из двух
  системных: аватар только у нижнего».
- Автопрокрутка к 0 при каждом изменении `state`: как сейчас (к
  последнему) — регресса нет; «дёргает» при чтении истории — как
  сейчас, Д2.
- `Scaffold` + `imePadding` + `adjustResize` + edge-to-edge —
  комбинация уже работает (вьюпорт сжимается, что и есть исходная
  жалоба); реверс её не трогает.

## 8. Проверка руками (M7)

1. Новый чат: приветствие + «Начать» — сообщения у поля ввода, не под
   аппбаром. «Начать» → вопрос и чипы прямо над полем ввода.
2. Лента длиннее экрана: конец у поля ввода, скролл вверх — история,
   скролл вниз — упирается в чипы.
3. Клавиатура при ленте в конце: последний вопрос и чипы над
   клавиатурой без докрутки. Закрыть — на месте.
4. Клавиатура при прокрученной в историю ленте: позиция не прыгнула.
5. Цепочка из двух системных подряд (оценка + вопрос): аватар только у
   нижнего, скругление верхнего — «в цепочке»; отступ между сторонами
   больше, чем внутри стороны.
6. Финал: кнопки в последнем пузыре, чипов нет; «Сводка», «Продолжить»
   — как в M6.
7. Поворот — лента в конце, один набор чипов; logcat без `FATAL`.
