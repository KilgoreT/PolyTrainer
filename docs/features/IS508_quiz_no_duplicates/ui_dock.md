# IS508 / чат-фикс 8 | Въезд из-под поля со стыковкой (бриф + анализ)

Ветка `IS508_chat_send_animation`, после чат-фикса 7 (ui_send_*).
Ручник: M13.

## Проблема (юзер, 2026-09-29, рабочая скорость после 0.1.9)

1. Новое сообщение квиза появляется резко: его верхняя часть видна над
   полем ввода в первом кадре; особенно на втором подряд сообщении.
2. Иконка квиза иногда так же выскакивает (заметно на однострочных
   баблах с иконкой).
3. После первой правки: «первое стоит, второе прилетает к нему до
   зазора, потом оба вверх» — а не «оба едут, зазор сокращается».
4. На рабочей скорости двухфазный вариант читался как пинок: нужно
   «вкатывание» одним движением.

## Причина

Новый элемент стартует на сдвиг соседей ниже места — его верх на 4dp
ниже низа предыдущего. Лента режет содержимое по своей границе, а между
низом последнего элемента и границей лежит нижний `contentPadding`
16dp: полоса 12dp верха нового элемента (и аватар у низа ряда) видна
сразу.

## Решения

- **Д1.** Обрезка остаётся у поля ввода. Перенос нижнего отступа наружу
  ленты (`Modifier.padding(bottom)`) забракован прогоном: граница
  обрезки повисла на 16dp выше поля, нижняя половина бабла срезалась
  «на фоне».
- **Д2.** Старт глубже: к дистанции въезда добавляется нижний отступ
  ленты (`InsertShiftTracker.slideExtra`, только при реальном въезде,
  сдвиг > 0). Элемент стартует целиком под полем.
- **Д3.** Стыковка: соседи стоят, пока новый проходит добавку и встаёт
  к ним в зазор, потом едут с ним одним куском. Первый вариант — две
  фазы (30 % окна догон, placement соседей с задержкой) — на рабочей
  скорости давал стоп-старт («пинок»). Итог: одна кривая
  `ChatMotion.EASING` у нового элемента на всю дистанцию «добавка +
  сдвиг», а placement соседей — свой `FiniteAnimationSpec<IntOffset>`
  (`DockedPlacementSpec`): остаток пути соседа = min(D, остаток пути
  нового). D известен только анимации (initial → target), поэтому
  кривая считается в спеке, а не задаётся tween-ом.
- **Д4.** Аватар при продолжении цепочки стоит на месте: спуск
  компенсирует ту же дистанцию (добавка + высота ряда + зазор) той же
  кривой (`avatarDescentExtraPx` — лямбда, читается в фазе рисования по
  дистанции элемента).

## Файлы

`widget/DockedPlacementSpec.kt` (новый), `ChatMessageWidget.kt`
(`slideExtra`, линейный прогресс + кривая в слое, placement spec),
`message/SystemMessageWidget.kt` (спуск с добавкой), `ChatMotion.kt`
(геометрия). Логика не тронута.

## Риски

- `DockedPlacementSpec` применяется ко всем placement-сдвигам ленты, не
  только к вставкам: сосед, едущий вниз (редкое оседание), тоже начнёт
  с задержкой на добавку. Вставок в окно анимации нет (пауза бота
  длиннее), сцепка прерванных анимаций не нужна — скорость спека нулевая.
- Мульти-вставка (вопрос + чипы одним апдейтом): оба получают одну
  дистанцию и добавку, стыкуются как блок.
