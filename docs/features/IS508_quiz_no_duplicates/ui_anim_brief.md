# IS508 / чат-фикс 6 | Анимация ленты чата: появление сообщений и чипов без рывков

Issue: https://github.com/KilgoreT/PolyTrainer/issues/508 (ветка
`IS508_quiz_no_duplicates`, все фиксы квиз-чата).
Источник: Backlog «Срочное» → «Анимация сообщений чата как в
Telegram» + уточнение юзера 2026-09-28.
Анализ: [ui_anim_analysis.md](ui_anim_analysis.md).

## Контекст

Лента — `LazyColumn(reverseLayout = true)` с ключами по `order`, чипы
действий — keyed-элемент `"user_actions"` (чат-фиксы 2–3); автопрокрутка
к концу `animateScrollToItem(0)` на каждое изменение списка/флага.
Анимаций в модуле нет: пузыри и чипы появляются и исчезают мгновенно.
Перед ответом бота эффект-хендлер ждёт случайные 100–400 мс
(`DatasourceEffectHandler.kt:113,131`) — «бот думает», без индикации.

## Проблема

Лента «выглядит ненатурально»: новое сообщение возникает скачком,
существующие пузыри прыгают на его высоту (на коротком чате — все
сразу), чипы «Показать ответ» / «Пропустить» пропадают и появляются
рывком (56dp), особенно на «Пропустить»: чипы исчезли → лента осела →
пузырь «Пропустить» → лента подскочила.

## Критерий (юзер, 2026-09-28)

Точного образа нет — «как в Telegram». Критерий: анимация лаконичная,
без рывков, **юзер её не замечает** — она не становится неудобством.
Не шоу, а отсутствие скачков.

## Требования

1. Появление сообщения (бота и юзера) и чипов — плавно, без скачка
   соседей: соседние элементы едут, а не прыгают.
2. Исчезновение чипов — плавно, лента не «оседает» рывком.
3. Автопрокрутка к новому сообщению — как есть (уже анимирована).
4. Длительности короткие (порядка 150–300 мс), без overshoot;
   ничего не «выпрыгивает» и не «пружинит» заметно.
5. Поведение редьюсера, порядок сообщений, задержки — без изменений
   (если не решено иначе в Р1 ниже).

## Не входит

- Анимация текста «улетающего» из поля ввода в пузырь (Telegram) —
  чужой виджет (`PrimaryTextFieldWidget` в core/ui), отдельная фича.
- Анимация клавиатуры — уже системная (чат-фикс 4).
- Хвост Д4 порции — отдельный пункт.

## Решения

- **Д1. Инструмент — `Modifier.animateItem()`** на каждом keyed-элементе
  ленты (сообщения и чипы): fade-in появления, placement-анимация
  сдвига соседей, fade-out исчезновения. Штатный API foundation,
  ключи уже есть. Анализ §3.
- **Р1 (открыт). Индикатор «бот печатает» на время паузы 100–400 мс**
  — это то, что делает задержку осмысленной в Telegram, но меняет
  состояние/редьюсер (плейсхолдер-сообщение или флаг). В скоуп или
  отдельно — решение юзера.
- **Р2 (открыт). Характер появления** — только fade (незаметно) или
  fade + лёгкий подъём/рост пузыря «из низа» (заметнее, ближе к
  Telegram, свой модификатор поверх `animateItem`).
- **Р3 (открыт). Скорости** — дефолт `animateItem` (spring
  MediumLow, ~350 мс, без overshoot по alpha) или укороченные tween
  150–200 мс для fade при дефолтном placement.
