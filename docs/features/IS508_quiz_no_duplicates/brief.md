# IS508 | Квиз-чат: повторы вопросов в порции квиза

Issue: https://github.com/KilgoreT/PolyTrainer/issues/508
Ветка: `IS508_quiz_no_duplicates`
Источник: Backlog, «Срочное» → «Квиз-чат: замечания юзера (2026-09-28)».
Анализ и план: [analysis.md](analysis.md).

## Контекст

Порцию сессии chat-квиза собирает
`QuizChatUseCaseImpl.getRandomWriteQuizList(limit, maxGrade, dictionaryId)`
(`app/.../di/module/quizchat/`):

1. **Грейд-корзины** — по каждому грейду `0..maxGrade` случайные
   квиз-записи (`type = GRADES`), раздача по корзинам с половинением
   остатка, добор `leftovers` до `limit`.
2. **Добавки по опциям меню чата** — при включённых prefs
   «Самые давние» (`getEarliestWriteQuizList`, `type = EARLIEST`,
   `take(2)`) и «Частые ошибки» (`getFrequentMistakesWriteQuizList`,
   `type = ERRORS`, `take(2)`) — сверх `limit`.
3. Результат — `mutableSetOf<WriteQuiz>()`, в конце `shuffled()`.

Квиз-запись (`write_quiz`) привязана к **лексеме**; слово с двумя
лексемами имеет две квиз-записи — два разных вопроса с одним ответом.

## Проблема

В одной сессии юзер видит одинаковые слова (замечено при включённых
опциях «Самые давние» / «Частые ошибки»).

## Причина (подтверждена по коду и ревью)

`WriteQuiz` — data class с полем `type: QuizType?`. Одна и та же
квиз-запись (одна лексема), взятая и из грейд-корзины (`GRADES`), и из
добавки (`EARLIEST`/`ERRORS`), отличается только `type` — для `Set` это
два разных элемента. Вопрос попадает в порцию дважды (при обеих опциях —
до трёх раз). Второй эффект: при сохранении сессии по дублированной
записи идут два апсерта от одного снапшота — один из ответов по слову
теряется.

## Требования (ядро)

1. В порции нет повторов одного и того же **вопроса**: единица
   уникальности — лексема (`lexeme.lexemeId`); уникальность — свойство
   контейнера порции, не отдельных фильтров.
2. Разные лексемы одного слова в порции допустимы, но **не
   предпочтительны**: при сборке предпочитаются лексемы разных слов,
   вторая лексема того же слова добирается только когда других
   кандидатов нет.
3. Размер порции и распределение по грейдам (сколько записей даёт
   каждая корзина, добор до `limit`, до 2 на добавку) не меняются;
   меняется только выбор, какие именно записи брать.
4. «Частые ошибки» дают только слова с ошибками (`error_count > 0`).
5. Инвариант «одна лексема — одна квиз-строка» закрепляется схемой:
   unique-индекс `write_quiz.lexeme_id` (миграция 13→14).

## Не входит

- Размер `limit`, число добавок, окно кандидатов добавок (`limit`
  строк по критерию — Д3).
- Остальные замечания по квиз-чату из Backlog (клавиатура/скролл,
  анимации, поле ввода) — отдельные задачи.
- Спека QuizChat целиком (пробел README остаётся); инвариант порции —
  аддитивно в `quiz-group-filter` §7.

## Решения (2026-09-28)

- **Д1. Единица уникальности — лексема**, не слово.
- **Д2. Добавка фильтрует уже взятые лексемы ДО `take(2)`** — берёт
  следующих кандидатов; «ошибки» фильтруются и от «давних».
- **Д3. Окно кандидатов добавки остаётся `limit`** (10 самых давних /
  ошибочных по критерию). Если все они уже в порции — добавка даёт 0,
  это норма: в маленьком словаре порция и так покрывает почти всё.
- **Д4. Мягкое предпочтение разных слов** (по ревью): на каждом шаге
  сборки сначала кандидаты с новым словом, второй проход — остальные.
  Границу «Не входит» сдвинули: выбор внутри корзин меняется, счётчики —
  нет.
- **Д5. Unique-индекс `write_quiz.lexeme_id`** — в IS508, миграция
  13→14 с предварительным схлопыванием дублей.
- **Д6. `error_count > 0`** в запросе «частых ошибок» — в IS508.
- **Д7. Контейнер порции по лексеме** (`Map<LexemeId, WriteQuiz>`
  вместо `Set<WriteQuiz>`) — в IS508; предусловие — сначала тесты
  распределения по грейдам на текущем коде.
