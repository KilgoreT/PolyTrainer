# IS508 / чат-фикс 10 | Бриф: рефакторинг анимаций ленты

Ветка `IS508_chat_send_animation`, база — коммиты c526f652 (стыковка) и
5d415d00 (финал по одному). Делается ДО мержа (решение юзера 2026-09-29:
«мне важна хорошая кодовая база»).

## Проблема

За чат-фиксы 6–9 анимации накопились одним большим блоком внутри ленты:
выбор «как элемент входит» размазан по условиям (`isNew`, `flying`,
`slideIn`, `fromShowAnswer`, `avatarDescends`), геометрия чипа и пузыря
задана руками в трёх местах, призрак ряда чипов — ручная копия ряда,
ширина «Пропустить» меряется с живого чипа через ленту, инвариант
«пауза бота длиннее анимации» — две несвязанные константы в двух слоях,
логика трекера сдвига («когда стартует въезд, кому раздаётся дистанция»)
без единого теста, движение вообще ничем автоматически не проверяется.

Цель: анимации вынесены в composable-функции со своей зоной
ответственности; выбор входа — одна чистая функция; точки согласования
сведены к константам; инварианты и правила покрыты юнитами; поведение
— device-тестами. Поведение на экране не меняется.

## Решения

- **Д1.** Движение — по максимуму средствами LazyList: `animateItem` +
  `DockedPlacementSpec` для соседей остаются, `Animatable` на элемент
  остаётся внутри своей функции. Свой движок для соседей и единые
  «часы» перехода — отвергнуты (ревью: гонка первого кадра, доводка
  при прерывании, потеря уезжающих элементов; всё это LazyList уже
  умеет).
- **Д2.** Device-тесты движения в модуле чата (androidTest,
  `createComposeRule` + `mainClock`), против текущего поведения.
  Robolectric не заводим (нет в проекте) — в Backlog для CI.
- **Д3.** Глубина чистки рендера — полная: ветки морфа и полёта —
  отдельные composable, один ряд чипов (живой и призрак), геометрия
  чипа из констант пузыря, ширина «Пропустить» с самого призрака, вход
  для чипов и «Начать» — через ту же функцию.
- **Д4.** «Новый» элемент — по растущему `order` (`order >
  maxLaidOutOrder`), а не по множеству виденных ключей: закрывает
  скрытый баг (после поворота старые пузыри морфятся заново при
  скролле в историю). Единственное намеренное изменение поведения, и
  оно чинит дефект.
- **Д5.** Паузы бота выводятся из длительности анимации с запасом на
  кадры старта (`ChatTiming`); тесты хендлера проверяют «пауза не
  короче анимации».

## Не в скоупе

- Логика квиза, редьюсер, эффекты — кроме переноса констант пауз.
- Клавиатура, скролл-якорение (`requestScrollToItem`) — как есть.
- Перевод перекраски чипов в draw-фазу (морф перекомпонует по кадрам)
  — Backlog.
- Пузырь «Продолжить» (`QuizReLoaded`) въезжает как набранный, хотя
  рождён кнопкой финала — Backlog.

## Критерий

Ручники M10–M14 ✅ на девайсе на рабочей скорости; юниты выбора входа,
трекера, формулы стыковки и таймингов зелёные; device-тесты движения
зелёные; в `ChatMessageWidget` нет inline-веток морфа/полёта; геометрия
пузыря/чипа — в одном месте.
