# IS508 / чат-фикс 9 | Пачки сообщений бота — по одному (бриф + анализ)

Ветка `IS508_chat_send_animation`, после чат-фикса 8 (ui_dock.md).
Ручник: M14.

## Проблема (юзер, 2026-09-29)

В финале сессии итог, сводка и сообщение с кнопками появляются разом,
и въезд по одному (чат-фикс 6) на них не работает. Нужно: любые
несколько сообщений бота приходят отдельно, с паузой, каждое со своей
анимацией. От юзера пачек не бывает (набор текста занимает время).

## Причина

`Msg.SessionOver` и `Msg.Summary` кладут по два системных сообщения
одним апдейтом состояния (`ChatReducer`: итог + сообщение с кнопками;
сводка + кнопки). Паузы бота (`botPauseMs`) стоят только перед
самим `Msg` в хендлере — внутри пачки паузы нет.

## Решение

Капельная выдача, содержимое остаётся в редьюсере, темп — в хендлере:

- Эффект `DatasourceEffect.DeliverSystemMessages(messages)` — хендлер
  выдерживает `botPauseMs()` и возвращает `Msg.SystemMessageDelivered(
  first, rest)`; пустая очередь → `Msg.Empty` без паузы.
- Редьюсер: `SessionOver` кладёт итог и ставит в очередь сообщение с
  кнопками (`sessionOverOptions()`); `Summary` кладёт первый элемент
  списка, в очередь — остальные + `summaryOptions()`, флаги
  (`clearUserInput/hideUserActions/disableUserInput`) — на первом
  шаге; `SystemMessageDelivered` кладёт сообщение и повторяет эффект
  для остатка, пока очередь не пуста.
- `QuizLoaded`/`QuizReLoaded` (пузырь юзера из кнопки + одно сообщение
  бота) не трогаются: одно сообщение бота на апдейт, пузырь юзера —
  морф кнопки.

## Тесты

`ChatReducerTest`: `SessionOver` → +1 сообщение и очередь с одним
сообщением на 3 кнопки; `SystemMessageDelivered` с остатком → эффект с
остатком, без остатка → без эффектов; `Summary` → +1, очередь на 2
кнопки, `showUserActions` снят. `DatasourceEffectHandlerTest`:
`DeliverSystemMessages` на тестовом диспатчере (виртуальное время) —
пауза выдержана, первое с остатком; пустая очередь → `Empty` без паузы.
