# IS508 / чат-фикс 4 | Анализ: жест клавиатуры через `imeNestedScroll`

Бриф: [ui_ime_brief.md](ui_ime_brief.md). Код — по состоянию ветки
после коммита 7c899f6e (чат-фикс 3). Compose foundation-layout 1.8.2;
ссылки — `foundation-layout-android-1.8.2-sources.jar`,
`androidMain/.../WindowInsetsConnection.android.kt`.

## 1. Как устроено сейчас

- `ChatScreen.kt:61-67`: `Box.padding(paddings).consumeWindowInsets(
  paddings).imePadding()` — контейнер сжимается на высоту IME.
- `ChatMessageWidget.kt`: `LazyColumn(reverseLayout = true,
  spacedBy(4.dp, Alignment.Bottom))`, индекс 0 — низ, автопрокрутка к 0.
- `PrimaryTextFieldWidget.kt:43-62`: при появлении — ждёт фокус окна,
  `focusRequester.requestFocus()` + `keyboardController?.show()`; при
  уходе — `hide()`. Поле появляется после «Начать» (`readyToStart`) и
  живёт до выхода; `isInputEnabled` фактически всегда `true`
  (`State.kt:250-254`, `disableUserInput` — TODO).
- Манифест `adjustResize`, `enableEdgeToEdge` — insets доставляются в
  Compose, `imePadding` работает (подтверждено чат-фиксом 3).

## 2. Что делает `Modifier.imeNestedScroll()`

`WindowInsetsConnection.android.kt:63-84`: на API < 30 возвращает
`this` (no-op); иначе — `nestedScroll(rememberWindowInsetsConnection(
ime, WindowInsetsSides.Bottom))`.

`WindowInsetsNestedScrollConnection` (`:140-…`):

- **Показ** (`onPostScroll`, `:216`): непоглощённый списком остаток в
  сторону показа нижнего inset'а (палец вверх) → запрашивает
  `controlWindowInsetsAnimation(ime)` (`:184-195`) и двигает IME на
  величину скролла — клавиатура едет за пальцем.
- **Скрытие** (`onPreScroll`, `:207-209`): при видимой клавиатуре
  движение в сторону скрытия (палец вниз) поглощается ДО списка —
  сначала уезжает клавиатура, потом крутится лента.
- **Отпускание** (`onPreFling`/`onPostFling`, `:271-275`): доанимация
  к `shown`/`hidden` по положению и скорости (`:296-360`).
- **Крайние положения** (`:227-233`): если IME уже полностью показана
  / скрыта в нужную сторону и контроллер не активен — `Offset.Zero`,
  скролл уходит списку как обычно.
- **Контроллер ещё не выдан** (`:235-239`): скролл поглощается, пока
  система думает; если система отказала (нет фокусируемого редактора)
  — жест бездействует, исключений нет.

Дельты nested scroll — экранные (палец вверх = `y < 0`), реверс ленты
на них не влияет: при `reverseLayout` «за конец» = попытка крутить
дальше индекса 0, список ничего не поглощает — остаток и уходит IME.

## 3. Фокус

`controlWindowInsetsAnimation(ime)` показывает клавиатуру только при
сфокусированном редакторе в окне. У нас: поле запрашивает фокус при
появлении (после «Начать») и не отдаёт его — «назад» прячет IME, фокус
остаётся; после отправки ответа фокус остаётся; после поворота поле
пересоздаётся и снова запрашивает фокус (+ показ IME — текущее
поведение). До «Начать» поля нет — жест невозможен, и это правильно:
печатать некуда. Дополнительный `requestFocus` при жесте не нужен
(Д3); отказ системы обрабатывается молча (§2).

## 4. Куда вешать (Д2)

Nested-scroll соединение видит скроллы всех потомков. Кандидаты:

- **Контейнер экрана** (`Box` в `ChatScreen`, как в сэмпле Compose):
  видит и ленту, и внутренний скролл многострочного `OutlinedTextField`
  (`singleLine = false`). Тянуть вниз по тексту в поле при видимой
  клавиатуре — клавиатура спрячется. Нежелательно.
- **Лента** (`ChatMessageWidget`, `LazyColumn(modifier =
  modifier.imeNestedScroll())`) — модификатор снаружи внутреннего
  `scrollable` `LazyColumn`, т.е. родитель в цепочке nested scroll;
  видит только скролл ленты. `imePadding` при этом остаётся на `Box`:
  соединение берёт insets из `WindowInsetsHolder.current()` (`:79`),
  привязки к узлу с `imePadding` нет. **Выбор.**

`@ExperimentalLayoutApi` — в проекте опт-ин по файлам
(`@file:OptIn(ExperimentalLayoutApi::class)` в `MainActivity.kt`,
`LexemeTextFieldWidget.kt`); так же в `ChatMessageWidget.kt`.

## 5. Взаимодействие с чат-фиксом 3

Контроллер двигает `WindowInsets.ime` покадрово → `imePadding` на
`Box` меняется → лента (`weight(1F)`) перемеряется с якорем внизу
(реверс) — конец ленты остаётся у верхнего края клавиатуры на каждом
кадре. Автопрокрутка `LaunchedEffect(state, …)` от жеста не
запускается (state не меняется).

## 6. Риски

- API < 30 — жест не работает; тап в поле и «назад» — как сейчас.
  Принято брифом.
- Экспериментальный API: сигнатура стабильна с 1.2, сэмпл официальный;
  риск удаления низкий, опт-ин уже есть в проекте.
- Жест при ленте в истории: палец вверх — список крутится к концу, IME
  не трогается (остаток нулевой); у конца — начинает выезжать IME. Это
  и есть требование.
- Быстрый флик вверх «за конец» — IME доанимируется в «показана»
  (`:271-275`); флик вниз при показанной — в «скрыта».

## 7. Проверка руками (M8)

1. Клавиатура скрыта, лента в конце: тяни вверх — клавиатура выезжает
   за пальцем; отпусти на середине — доедет вверх или вниз по скорости.
2. Клавиатура показана: тяни вниз — сначала прячется клавиатура (чат
   растёт), затем крутится лента.
3. Лента в истории: тяни вверх — сначала докрутка до конца, потом
   выезжает клавиатура.
4. Клавиатура выехала жестом — набор текста работает (фокус в поле).
5. Тап в поле / «назад» — как раньше.
