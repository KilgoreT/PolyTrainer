# IS508 / чат-фикс 2 | Анализ: кнопки «Показать ответ» и «Пропустить» в ленте

Бриф: [ui_buttons_brief.md](ui_buttons_brief.md). Код — по состоянию
ветки на 2026-09-28 (после коммита d37a7a27).

## 1. Как устроено сейчас

`ChatScreen.kt:51-81` — `Scaffold` → `Box` с
`.padding(paddings).consumeWindowInsets(paddings).imePadding()`. Всё
содержимое экрана сжимается на высоту клавиатуры.

`ChatWidget.kt:36-83` — `Column`:

1. `ChatMessageWidget` (лента) — `weight(1F)`, занимает всё свободное.
2. `if (state.showUserActions) Row { ShowAnswerButtonWidget;
   SkipButtonWidget }` — `padding(bottom = 8.dp, end = 16.dp)`, чипы
   прижаты вправо (`Arrangement.spacedBy(8.dp, Alignment.End)`).
3. `PrimaryTextFieldWidget` — поле ввода.

`ChatMessageWidget.kt:39-73` — `LazyColumn`, `reverseLayout = false`,
`contentPadding 16.dp`, ключ элемента — `item.order`. Автопрокрутка:
`LaunchedEffect(state) { animateScrollToItem(state.list.lastIndex) }`.

Кнопки: `ShowAnswerButtonWidget` / `SkipButtonWidget` → общий
`ChatButtonWidget` (чип 48dp, белый, рамка `chatMessageBtnBorder`,
скруглённый, `Surface(onClick)`), шлют `Msg.GetAnswer` / `Msg.Skip`.

## 2. Почему кнопки «прилипли к клавиатуре»

Кнопки — не в ленте, а в той же `Column`, что и поле ввода, сразу над
ним. `imePadding` на `Box` экрана уменьшает высоту всей колонки, лента
(`weight`) сжимается, полоса кнопок и поле ввода поднимаются на высоту
клавиатуры. Прокрутка ленты на них не влияет по построению.

## 3. Показ и скрытие — флаг состояния

`ChatState.showUserActions` (`State.kt:133`), явный флаг по правилу
проекта. Редьюсер (`ChatReducer.kt`): `NextQuestion` →
`showUserActions()`; `UserAttempt` / `GetAnswer` / `Skip` / `Summary`
→ `hideUserActions()`. Между `GetAnswer` и приходом `ShowAnswer`
(эффект с задержкой) вопрос остаётся последним сообщением, кнопки уже
скрыты флагом — защита от двойного нажатия. Флаг нужен при любом
варианте переноса.

## 4. Уже есть механизм кнопок внутри ленты

`ChatMessage.buttons: List<ChatButton(title, action: UserAction)>`
(`State.kt:158,176`). `SystemMessageWidget.kt:72-80` рисует их под
текстом пузыря полноширинными `MessageButtonWidget` (LexemeButton 44dp,
фон `tertiary`), только у последнего сообщения (`showButtons =
isLastMessage`, `ChatMessageWidget.kt:61-65`). Нажатие →
`Msg.UserAction(action)`; `UserAction` = `CONTINUE | SUMMARY | EXIT`
(финал сессии, сводка). «Показать ответ» / «Пропустить» — отдельные
`Msg.GetAnswer` / `Msg.Skip`, в `UserAction` не входят.

## 5. Варианты

### А. Отдельный элемент ленты «действия» (рекомендую)

`ChatMessageWidget` получает `showUserActions: Boolean` и в конце
`LazyColumn` добавляет `item(key = "actions") { Row(чипы) }`, когда
флаг поднят. `Row` из `ChatWidget` удаляется. Автопрокрутка — к
последнему элементу списка (индекс `list.lastIndex + 1`, когда элемент
действий есть).

- Модель сообщений, редьюсер, `Msg`, тесты — без изменений.
- Внешний вид сохраняется: те же чипы справа, под последним вопросом.
- Объём: ~20 строк в двух виджетах.
- Риск: ключ `"actions"` не пересекается с `order.toString()` (числа).
  При скрытии элемент исчезает, лента укорачивается — без анимации,
  как и сейчас.

### Б. Кнопки внутри сообщения-вопроса

`NextQuestion` кладёт вопрос с `buttons = [ShowAnswer, Skip]`;
`SystemMessageWidget` рисует их под текстом. Нужно расширить
`UserAction` (`SHOW_ANSWER`, `SKIP`) и в редьюсере отобразить их на
переходы `GetAnswer` / `Skip`, либо заменить `ChatButton.action` на
`Msg`. Видимость — `isLastMessage && showUserActions` (флаг остаётся).

- Семантика «кнопки принадлежат вопросу» (inline-клавиатура Telegram).
- Внешний вид меняется: полноширинные кнопки в пузыре (как финал
  сессии) либо отдельная ветка рендера чипов внутри пузыря.
- Объём: ~40 строк + правки редьюсера + тесты редьюсера
  (`ChatReducerTest`, если есть — проверить).
- Риск: `showButtons = isLastMessage` сейчас единственный критерий для
  финальных кнопок; смешение двух критериев в одном виджете.

### В. Оставить полосу, прятать при клавиатуре — отклонено

Противоречит требованию: кнопки должны прокручиваться с лентой.

## 6. Связь с клавиатурой (пункт Backlog «закрывает сообщения»)

Лента привязана к верху (`reverseLayout = false`): при появлении
клавиатуры высота ленты уменьшается, а смещение прокрутки от верха
сохраняется — низ ленты (последние сообщения, а после переноса и
кнопки) уходит под клавиатуру. Это и есть пункт Backlog №2. Два пути:

- `reverseLayout = true` — лента привязана к низу, как в мессенджерах:
  при сжатии остаётся виден конец; требует развернуть список, поменять
  цель автопрокрутки на 0 и пересчитать «цепочки» сообщений
  (`isPreviousHasSameType`, аватар у последнего в цепочке).
- Прокрутка к концу по факту появления IME (`WindowInsets.isImeVisible`
  → `animateScrollToItem(last)`), список не трогается.

Варианты А/Б от этого не зависят, но полный эффект «кнопки всегда
видны при наборе» даёт только связка с фиксом №2. Решается отдельным
брифом, следующим шагом.

## 7. Проверка руками

1. Вопрос показан → кнопки под ним в ленте; скролл вверх — кнопки
   уезжают вместе с сообщениями.
2. Ответ / «Показать ответ» / «Пропустить» → кнопки исчезают, лента
   без «дыры».
3. Следующий вопрос → кнопки снова под ним, автопрокрутка к ним.
4. Финал сессии и сводка — чипов нет, кнопки финала на месте.
5. Клавиатура открыта → поведение как у остальных сообщений (до фикса
   №2 — могут уйти под клавиатуру, докрутить вручную).
