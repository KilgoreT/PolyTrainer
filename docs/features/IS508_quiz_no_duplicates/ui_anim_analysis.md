# IS508 / чат-фикс 6 | Анализ: анимация ленты через `animateItem`

Бриф: [ui_anim_brief.md](ui_anim_brief.md). Код — после коммита
eeb3ae82 (чат-фикс 5). Compose foundation 1.8.2, ссылки —
`foundation-android-1.8.2-sources.jar`.

## 1. Что есть сейчас

- `ChatMessageWidget.kt`: `LazyColumn(reverseLayout = true,
  spacedBy(4.dp, Alignment.Bottom))`; элемент чипов `item(key =
  "user_actions")` первым, сообщения `itemsIndexed(list.asReversed(),
  key = order)`; корень элемента — `SystemMessageWidget` /
  `UserMessageWidget` с `Modifier.padding(top = topSpace)`;
  `LaunchedEffect(state, showUserActions) { animateScrollToItem(0) }`.
- Анимаций нет (grep по `animate|Animated|tween|spring` в модуле —
  пусто, кроме `animateScrollToItem`).
- Паузы бота: `delay(Random.nextLong(100, 400))` перед `NextQuestion`
  и `Assessment` (`DatasourceEffectHandler.kt:113,131`); `Skipped` и
  `ShowAnswer` — без паузы.

## 2. Откуда рывки

1. **Короткий чат** (контент короче вьюпорта, прижат к низу): новый
   элемент внизу — все пузыри мгновенно уезжают вверх на его высоту.
   Скролла нет (всё влезает), значит и скролл-анимации нет — чистый
   скачок раскладки.
2. **Чипы.** `Skip`: флаг снят → элемент чипов исчез → пузыри осели на
   56dp → сразу `Skipped` → пузырь «Пропустить» → пузыри подскочили.
   Два скачка за один тап. `NextQuestion` → чипы появились скачком.
3. **Появление пузыря** — без перехода: был пусто, стал пузырь.
4. **Длинный чат**: новый элемент встаёт под вьюпорт (позиция по
   ключу), `animateScrollToItem(0)` плавно подвозит — это уже
   анимировано, но пузырь «всплывает» из-под края уже целиком
   непрозрачным.

Telegram (Android) для сравнения: входящий пузырь появляется с
fade + лёгким ростом снизу, лента сдвигается плавно; на время
ожидания — «печатает…»; свой пузырь «вылетает» из поля ввода.

## 3. Инструмент: `Modifier.animateItem()`

`LazyItemScope.animateItem(fadeInSpec, placementSpec, fadeOutSpec)`
(`LazyItemScope.kt:77-101`, стабильный API):

- **fadeIn** — появление элемента (alpha 0→1), дефолт `spring(
  stiffness = MediumLow)`;
- **placement** — любое смещение элемента из-за раскладки
  («reordering, arrangement or alignment changes»), дефолт `spring(
  MediumLow, visibilityThreshold = IntOffset.VisibilityThreshold)`;
- **fadeOut** — исчезновение (элемент дорисовывается, пока гаснет),
  дефолт `spring(MediumLow)`;
- `null` в любом параметре — эта анимация выключена.

Требование: ключ у элемента (KDoc `:81-82`) — у нас есть. Модификатор
должен стоять **первым** в цепочке корня элемента
(`Modifier.animateItem().padding(top = topSpace)`), иначе анимируется
не тот узел.

### Как это закрывает §2

1. Короткий чат: соседи получают новые позиции → placement-анимация
   везёт их вверх вместо скачка; новый пузырь — fade-in.
2. Чипы: fade-out при снятии флага, соседи едут (placement); при
   появлении — fade-in, соседи едут. Скачок «осели → подскочили» на
   `Skip` превращается в один плавный сдвиг: пока чипы гаснут,
   пузырь «Пропустить» уже проявляется на их месте (разница высот 56
   vs ~40dp — placement на 16dp, не на 56).
3. Появление — fade-in.
4. Длинный чат: fade-in + существующая скролл-анимация — пузырь
   проявляется, пока въезжает.

### Взаимодействие с реверсом и автопрокруткой

- Реверс на `animateItem` не влияет: анимируются смещения в
  координатах раскладки, ключи те же.
- Placement-анимация и `animateScrollToItem(0)` одновременно: скролл
  двигает вьюпорт, placement — элемент относительно раскладки;
  разные оси управления, конфликта в API нет. Проверить глазами на
  длинном чате (M10).
- `LaunchedEffect(state, showUserActions)` не трогается.

## 4. Варианты

### А. Только `animateItem` на всех элементах (Д1)

`Modifier.animateItem()` у корня каждого сообщения и у
`UserActionsWidget`. Специи: либо дефолты (spring MediumLow — alpha
без overshoot, ~350 мс), либо fade `tween(150–200)` + placement
дефолт (Р3). Объём: 3 строки в `ChatMessageWidget`. Незаметная
анимация — ровно критерий брифа. **Рекомендую.**

### Б. А + «рост из низа»

Свой модификатор появления: `graphicsLayer { scaleY/translationY }`
от `Animatable` в `LaunchedEffect` на первом появлении элемента
(remember-флаг «уже показан»). Ближе к Telegram, заметнее, +30–40
строк и состояние на элемент; при рекомпозиции/повороте нужно не
проигрывать заново. Против критерия «не замечает». Не рекомендую
сейчас; можно вторым шагом, если А покажется «плоским».

### В. А + индикатор «бот печатает» (Р1)

На время `delay(100–400)` показывать плейсхолдер-пузырь с тремя
точками. Это изменение состояния: либо флаг `isBotTyping` в
`ChatState` (явный флаг по правилу проекта) + элемент ленты с ключом
`"typing"`, поднимаемый хендлером перед задержкой и снимаемый
сообщением; либо плейсхолдер-сообщение. Затрагивает `Msg`, редьюсер,
`DatasourceEffectHandler`, тесты редьюсера/хендлера. Объём: ~60–80
строк + тесты. Даёт «телеграмность» задержке, но пауза 100–400 мс
коротка для индикатора — либо удлинять до ~600–900 мс (замедляет
квиз), либо индикатор будет мелькать. Вопрос юзеру.

## 5. Риски

- Fade-out чипов: пока гаснут, они ещё на экране — тап по гаснущему
  чипу? `Surface(onClick)` остаётся кликабельным до удаления из
  композиции; флаг уже снят, второе `Msg.Skip` → редьюсер снова
  `hideUserActions` + эффект `Skip` → `quizGame.skip()` дважды.
  Проверить: либо `fadeOutSpec = null` для чипов (исчезают сразу,
  соседи всё равно едут плавно), либо короткий fade-out 100 мс.
  Решается в плане после ответа на Р3.
- Placement-анимация при появлении клавиатуры: `imePadding` меняет
  высоту ленты покадрово; элементы, прижатые к низу, меняют позицию
  → placement-spring «догоняет» клавиатуру с запаздыванием — может
  выглядеть как желе. Если так — `placementSpec` жёстче
  (`StiffnessMedium`/`High`) или проверить, что в реверсе с якорем
  внизу позиции элементов относительно раскладки не меняются
  (меняется вьюпорт, не позиции). Проверить на девайсе первым делом
  (M10 шаг про клавиатуру).
- Поворот: ключи стабильны, `animateItem` не проигрывает появление
  для уже существующих элементов при пересоздании — ожидаемо.

## 5а. Ревизия после M10a/M10b (2026-09-28)

Оба варианта (fade / fade + рост) забракованы: на коротком чате новый
пузырь встаёт на место сразу, а соседи едут к новым позициям из
старых — 300 мс нижний сосед лежит поверх нового («раздувается»). Две
вставки разом (вопрос + чипы, оценка + вопрос через 100–400 мс)
накладывают анимации. Решение юзера — «как в Telegram»: пузырь
въезжает снизу вместе с лентой, по одному.

Сделано: чипы — внутри элемента последнего вопроса (`Column`-корень,
вид прежний), любая вставка — один элемент; новый пузырь стартует ниже
на свою высоту + зазор и едет вверх той же пружиной, что placement
соседей (`StiffnessMediumLow`); fade/рост убраны; въезд только пока
лента короче экрана (`!canScrollForward`) и только для сообщений,
добавленных после первой композиции (`initialLastOrder`); пауза бота
400–650 мс (не короче анимации).

**Открыто (M10c, юзер):** «чипы исчезают → на их месте мой пузырь» —
стрёмно: чипы схлопываются мгновенно внутри элемента вопроса (соседи
едут вниз), а пузырь ответа въезжает снизу — два движения врозь.
Кандидаты: (а) чипы не убирать до прихода ответа, а гасить/сжимать
той же пружиной (`animateContentSize` на `Column` вопроса — высота
элемента едет, а не прыгает); (б) пузырь ответа не въезжать, а
появляться на месте чипов (он их «заменяет»); (в) оставить чипы
видимыми, но disabled, до оценки. Решить после M10d.

## 5б. Итог реализации (2026-09-29)

- **Въезд и якорь.** При изменении набора элементов у конца ленты —
  `requestScrollToItem(0)` (без удержания по ключу и без
  `animateScrollToItem` с его пружиной): и на коротком, и на длинном
  чате соседи едут placement-tween, новые въезжают снизу на дистанцию
  сдвига прежнего нижнего сообщения. Дистанция считается в
  `layout`-модификаторе ленты после измерения и раздаётся **по ключу**
  новым элементам (`InsertShiftTracker.distances`); «новый» = ключа не
  было в раскладке (`knownKeys`), кнопки — вне «известных». Пока
  дистанции нет — элемент скрыт (первые кадры), позже — страховка
  «рисовать на месте».
- **Переиспользование композиции LazyList.** Всё per-item состояние
  (`remember`, `LaunchedEffect`) — под ключом элемента: LazyList
  переиспользует композицию ушедшего элемента для нового, и без ключа
  прогресс/защёлки переживали смену элемента (мелькание, «под соседом»).
- **Кнопки.** `ChatButtonWidget` — обычный `Surface` + `clickable`:
  кликабельный M3 `Surface` раздувал раскладку до 48dp при виде в 30 —
  причина «качания вниз» при замене кнопок пузырём. «Начать» —
  системная кнопка в ленте (`StartActionWidget`, 48dp, primary, 60 %
  по центру), поле ввода — `AnimatedVisibility(expandVertically)`.
  Превращение в пузырь — в `UserMessageWidget` по `UserMessageOrigin`
  (`colorMorph` / `geometryMorph`, фазы `ChatMotion.window`), призраки
  соседних чипов — внутри элемента нового пузыря; на время морфа
  placement выключен (`MorphState`).
- **Аватар.** `SystemMessageWidget(avatarDescends)`: при продолжении
  цепочки стартует на месте аватара предыдущего пузыря и опускается.
- **Паузы бота** перед каждым сообщением (`botPauseMs`), **слоу-мо в
  релизе** по решению юзера: `ChatMotion.DURATION_MS = 1500`, пауза
  2000–2100 мс (рабочие 350 / 400–650).

## 6. Проверка руками (M10, набросок)

1. Короткий чат: «Начать» → пузыри и чипы проявляются, соседи едут.
2. «Пропустить» → чипы гаснут, пузырь «Пропустить» и вопрос
   проявляются, лента едет один раз, без оседания.
3. Длинный чат: ответ → пузыри проявляются, въезжая.
4. Клавиатура жестом (M8) и тапом — лента без «желе».
5. Поворот — без повторного проигрывания появления.
