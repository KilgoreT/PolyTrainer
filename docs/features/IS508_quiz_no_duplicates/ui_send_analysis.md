Бриф: [ui_send_brief.md](ui_send_brief.md). Код — master 0d3ef556.

## 2. Почему «буквы летят» нельзя сделать внутри ленты

- `LazyColumn` режет содержимое по оси прокрутки
  (`clipScrollableContainer` внутри LazyList) — элемент не может
  нарисоваться ниже ленты, где стоит поле.
- Поле — другой узел дерева (`Column` под лентой). Общей системы
  координат у элемента ленты и текста поля нет, кроме окна.

Значит — **слой-оверлей** поверх ленты и поля: `ChatWidget` становится
`Box { Column(лента, поле); FlightLayer }`. Слой рисует копию текста и
двигает её между двумя прямоугольниками в координатах корня
(`positionInRoot`): **источник** — где текст стоял в поле, **цель** —
где встал `Surface` нового пузыря.

## 3. Механика полёта

### Состояние

`FlightState` (UI-локальное, `remember` в `ChatWidget`, snapshot-поля):

- `text: String`, `source: Rect` (левый верх текста в поле + его размер),
  `order: Int?` — сообщение, которое летит; `target: Rect?` — левый верх
  `Surface` пузыря; `progress: Animatable(0f)`.
- Живёт от `onSendAction` до конца полёта; пока `order != null`, реальный
  пузырь этого `order` в ленте скрыт (alpha 0 в graphicsLayer), чипы в его
  элементе рисуются призраком и гаснут.

### Последовательность

1. **`onSendAction`** (ChatWidget): берём `state.inputState` и координаты
   поля (`onGloballyPositioned` на `LexemeTextFieldWidget`, хранится в
   обычном поле), считаем `source` = левый верх поля + (16dp, 16dp) —
   отступ содержимого `OutlinedTextField`. Заполняем `FlightState`,
   затем `sendMessage(Msg.UserAttempt)`. Порядок важен: после апдейта
   поле уже пустое.
2. **Апдейт состояния**: в ленте появляется пузырь `order = N` с
   `origin = INPUT`; `ChatMessageWidget` получает `flight` и для нового
   (`isNewKey`) пузыря с `order == flight.order`:
   - `slideIn` выключен (полёт его заменяет);
   - `Surface` пузыря скрыт (`graphicsLayer { alpha = 0 }`, пока
     `flight.order == order` — читается в фазе рисования);
   - `Surface` сообщает свои координаты (`onGloballyPositioned` →
     `flight.target = rect`); колбэк приходит каждый проход раскладки —
     цель обновляется, если раскладка едет (см. риск с клавиатурой);
   - в `Box` элемента — призрак обоих чипов (`ChatButtonWidget(enabled =
     false)` ×2 в ряду, как `UserActionsWidget`) с `alpha = 1 −
     window(p, 0, GHOST_FADE_END)`. Элемент чипов исчез в тот же апдейт,
     призрак стоит на его месте: чип по геометрии равен пузырю, высота
     элемента не меняется, соседи не едут.
3. **Слой**: пока `target == null` — копия рисуется в `source`
   (t = 0: это её законное место, цель нужна только для t > 0), поэтому
   кадра-пропуска между очисткой поля и появлением копии нет. Как только
   цель известна — `progress.animateTo(1f, tween(DURATION_MS,
   LinearEasing))`; по завершении `flight.order = null` → пузырь в ленте
   становится видимым, копия исчезает. Копия на t = 1 геометрически
   равна пузырю (те же отступы, стиль, форма, ширина), подмена не видна.
4. Страховка: если цель не пришла за `DURATION_MS` (пузырь вне экрана —
   юзер отправил из истории и лента подвозит скроллом), полёт
   завершается без анимации: копия исчезает, пузырь показывается.

### Что рисует копия (фаза рисования, без рекомпозиции на кадр)

`Canvas`-подход: `rememberTextMeasurer()`; текст измеряется один раз при
старте полёта стилем пузыря `BodyM` в ширину пузыря (Д4:
`maxWidth = ширина ленты − 32dp`) → `TextLayoutResult` даёт размер
текста `T`. Размер копии = `T + (32dp, 16dp)` — ровно `Surface`
пузыря. В `drawBehind` слоя на каждом кадре (читает `progress`,
`target`):

- `e = EASING(t)` — положение и масштаб; `c = window(t, RECOLOR_START,
  1)` — фон и цвет.
- масштаб `s = lerp(17/15, 1, e)` — в поле буквы стоят 17sp, в пузыре
  15sp; масштаб через `scale()` канвы вокруг левого верха текста, без
  переизмерения текста (переизмерение по кадрам меняло бы переносы).
- левый верх **текста** `P = lerp(source.topLeft, target.topLeft + (16dp,
  8dp), e)`; левый верх копии = `P − (16dp, 8dp)·s`.
- фон: `drawRoundRect(primary.copy(alpha = c), углы 20/20/20/8)` в
  размере копии ×s;
- текст: `drawText(layoutResult, color = lerp(цвет текста поля,
  onPrimary, c), topLeft = P)`.

Всё — обычные поля/`Animatable`, читаемые в `drawBehind`: анимация
перерисовывает слой, не перекомпонует (как `slideInWithColumn`).

### Согласование с чипами (Д2, Д5) — один t

| t | чипы (призрак в элементе) | копия текста |
|---|---|---|
| 0 → 0.45 | гаснут (`GHOST_FADE_END`) | летит, ещё «буквы» (фон прозрачный) |
| 0.3 → 1 | — | проявляется фон, текст перекрашивается (`RECOLOR_START`) |
| 1 | нет | копия = пузырь; подмена |

Одно окно `DURATION_MS`, один `EASING` — те же константы, что у
морфов кнопок; новых констант не нужно.

## 4. Изменения по файлам

- `ChatWidget.kt`: `Column` → `Box { Column; FlightLayer }`;
  `FlightState` (`remember`); `onSendAction` захватывает источник;
  поле получает `onGloballyPositioned`. `FlightLayer` — новый
  composable в `widget/` (свой файл `FlightLayer.kt`, ~80 строк).
- `ChatMessageWidget.kt`: параметр `flight: FlightState`; для пузыря
  `INPUT`: `slideIn` выкл., скрытие, `onGloballyPositioned` на
  `Surface`, призрак двух чипов. `USER_ACTIONS_KEY` без изменений.
- `UserMessageWidget.kt`: два параметра — `surfaceModifier: Modifier`
  (цепляется к `Surface` после существующих `graphicsLayer/layout`) и
  `hidden: () -> Boolean` (или `alpha` в лямбде graphicsLayer).
- `PrimaryTextFieldWidget.kt` / `LexemeTextFieldWidget.kt` (core/ui):
  пробросить `modifier` до `OutlinedTextField` уже есть; нужен только
  `onGloballyPositioned` снаружи — через `modifier`, без правок API.
- `ChatMotion.kt`: без новых констант; KDoc `window` дополнить
  упоминанием полёта.
- Логика/редьюсер/state: не меняются (полёт — UI-состояние).

## 5. Риски

1. **Клавиатура прячется при отправке.** `disableUserInput` делает
   поле `enabled = false` → фокус снимается → IME уезжает, и содержимое
   под `imePadding` растёт вниз ~250 мс. Цель (пузырь у низа ленты)
   едет вниз во время полёта. Копия целится в **текущую** цель каждый
   кадр (колбэк обновляет `target`), источник зафиксирован — буквы
   отрываются там, где стояли, и догоняют пузырь. Проверить на девайсе
   первым делом; если некрасиво — отдельно решать про клавиатуру (не
   выключать поле, а только игнорировать ввод — это уже UX-решение).
2. **Точность старта.** Левый верх текста в поле считается по отступу
   16dp `OutlinedTextField`, не измеряется (M3 не отдаёт `onTextLayout`).
   Погрешность 1–2dp по вертикали возможна (разные `lineHeight` у 17sp и
   15sp); на слоу-мо видно по первому кадру — подстроить константой.
3. **Многострочный ответ (Д4).** В поле переносится по ширине поля
   минус иконка, в копии — по ширине пузыря: на первом кадре строки
   перестроятся. Принято брифом, смотрим на девайсе.
4. **Отправка из истории** (лента не у конца): пузырь вне экрана, цели
   нет → страховка п. 3.4 (полёт без анимации). Редкий случай.
5. **Переиспользование композиции LazyList**: скрытие и призрак
   привязаны к `flight.order == item.order` (значение, не защёлка) —
   после смены ключа состояние не переживает. `remember(key)` там, где
   нужна защёлка (как в фиксе 6).
6. **Дважды «Отправить»** за окно полёта невозможно: поле выключено
   апдейтом; второй полёт стартовать некуда.

## 6. Проверка руками (M12, набросок)

1. Короткий ответ, чат у конца: буквы отрываются с места, летят вниз к
   пузырю, фон проявляется по пути, чипы гаснут; в конце — обычный
   пузырь без мелькания.
2. Многострочный ответ: то же; отметить, как выглядит первый кадр.
3. Ответ из истории (прокрутить вверх, отправить): пузырь просто
   появляется, `FATAL` нет.
4. Клавиатура: как ведёт себя цель во время полёта (риск 1).

## 7. Итог реализации (2026-09-29)

- Как в §3: `FlightState` + `FlightLayer` (`widget/FlightLayer.kt`),
  копия на канве (`TextMeasurer` + `drawText`, масштаб вокруг базовой
  линии первой строки), цель — `Surface` пузыря через `surfaceModifier`
  (`onGloballyPositioned` + скрытие), призрак двух чипов в элементе
  пузыря, `slideIn` для летящего пузыря выключен. Геометрия пузыря
  (углы, отступы) и отступ ленты — в `ChatMotion`, одна точка правды для
  пузыря и копии.
- **Прогресс полёта — snapshot-поле, а не `Animatable`.** Первый вариант
  обнулял прогресс в корутине эффекта (`snapTo(0)`), и на втором полёте
  первый кадр читал 1.0 от прошлого: призрак чипов рисовался с альфой 0
  и «появлялся позже» (мелькание, прогон M12). Теперь `launch()` ставит
  `progress = 0f` синхронно в момент отправки, эффект крутит его по
  `withFrameNanos` линейно; фазы — `ChatMotion.window`.
- **Плейсхолдер поля** (Д6/Д7): `placeholderModifier` прокинут через
  `PrimaryTextFieldWidget` → `LexemeTextFieldWidget` (core/ui) до `Text`
  плейсхолдера; альфа = `window(progress, SWAP_START, SWAP_END)`, чипы —
  `1 − window(...)`; окно — весь полёт.
- **Риск §5.1 (клавиатура прячется)** подтверждён: цель едет вниз во
  время полёта, копия её догоняет — юзер принял («вроде норм»).
- **Слоу-мо** (Д8): `DURATION_MS = 6000`, паузы бота 7000–7200.
- Неизменно: логика/редьюсер/state, порядок `order = list.size`
  (`nextOrder()`), страховка без цели — полёт без анимации по таймауту.
