# Основные понятия

[← Оглавление](README.md)

## Цикл

Mate — реализация The Elm Architecture. Раннер (`Mate`) — это цикл
одной самостоятельной единицы UI со своим состоянием: экрана, вкладки
внутри host'а, отдельного виджета (например, app bar со своей
ViewModel). На одном видимом «экране» может жить несколько раннеров —
у каждого свой цикл:

```
UI ──accept(Msg)──▶ mailbox ──▶ reduce(state, msg) ──▶ (newState, effects)
                                      │                      │
        StateFlow ◀── публикация ◀────┘                      │
        подписки  ◀── дифф subscriptions(newState)           │
        исполнители ◀── роутинг эффектов ────────────────────┘
                │
                └──consumer(Msg)──▶ mailbox (каскад)
```

- **State** — иммутабельный слепок экрана. Меняется только reducer'ом.
- **Msg** — факт («юзер нажал», «база ответила», «поток эмитнул»).
  Единственный вход в цикл.
- **Reducer** — чистая тотальная функция `Msg × State → (State, Effects)`.
  Не делает IO, не бросает исключений, обрабатывает любой Msg в любом
  состоянии (невозможный — явный no-op).
- **Effect** — разовое различимое намерение, описанное данными
  («сходи в базу», «перейди на экран»). Исполняет handler, результат
  возвращается НОВЫМ Msg — колбэков в обход цикла не существует.
- **Subscription** — подписка на поток данных, выведенная из State («слушай
  слова словаря 5»). Живёт, пока состояние её объявляет.

## Гарантии раннера

Библиотека гарантирует в рантайме:

- **Mailbox (FIFO).** Msg встают в очередь и разбираются строго по
  одному единственным внутренним циклом; `accept` потокобезопасен по
  построению. Каскадные Msg (рождённые эффектом) встают в хвост
  очереди.
- **Порядок итерации зафиксирован:** reduce → публикация state →
  дифф подписок → запуск эффектов. Порядок ЗАВЕРШЕНИЯ эффектов одного
  reduce не гарантирован (исполняются конкурентно, как Cmd в Elm).
- **Init-эффекты** исполняются первой итерацией цикла, до любого Msg;
  initial-дифф подписок — ещё раньше, от initState.
- **Цикл не умирает.** Исключения reduce/handler'ов/подписок уходят в
  `MateFailPolicy`; `Strict` (дефолт) превращает ошибку в краш —
  режим отладки, некидающая политика оставляет цикл жить.
- **Роутинг — по реестру семейств.** Каждый эффект доставляется ровно
  одному handler'у по декларации семейства; невалидная конфигурация —
  ошибка при создании раннера или при диспатче
  ([подробнее](04_effects.md)).

## Карта типов

| Тип | Роль |
|---|---|
| `Mate<State, Message, E : Effect>` | раннер цикла |
| `MateReducer<State, Message, Effect>` | чистая функция update |
| `Effect` / `MateEffectHandler<Message, E>` | разовые намерения и их исполнители |
| `Subscription` / `MateSubscriptionHandler<Message, S>` | подписки на потоки данных и их исполнители |
| `MateStore<State, Message>` | то, что видит UI: `state` + `accept` |
| `MateObserver` | наблюдатель полного цикла |
| `MateFailPolicy` / `MateError` | политика ошибок раннера |
| `NavigationEffect` / `NavTable` / `Screen` | навигация как данные |

## Контракт вызывающего

Единственное требование к коду вокруг: не читать `state.value`
синхронно сразу после `accept` — состояние публикуется циклом, все
чтения через подписку на `StateFlow`.
